<migration_contract>
Signature: `log.<level>(scope, msg, ctx?)` — exactly three arguments, the error ALWAYS under `ctx.err`.
Import: `import { log } from "@/lib/log"`.
Level map: `console.error`→`log.error`, `console.warn`→`log.warn`, `console.log`→`log.info`,
`console.info`→`log.info`. **A warn stays a warn** — do not "promote" it to error.

**Scope rule**, identical to plans 10, 14 and 15. A `[bracket]` prefix already in the string always
wins. Otherwise derive from the module path: strip the leading `src/`, strip a leading `app/`, strip a
trailing `/route.ts` or `/page.tsx` or the file extension, and keep every remaining segment verbatim
including dynamic segments. Worked examples: `src/app/api/signup/route.ts` → `api/signup`;
`src/app/api/api-keys/[id]/route.ts` → `api/api-keys/[id]`;
`src/app/api/files/[entityId]/[fieldName]/[filename]/route.ts` → `api/files/[entityId]/[fieldName]/[filename]`;
`src/lib/api/rate-limit.ts` → `lib/api/rate-limit`; `src/lib/api-keys.ts` → `api-keys`.

**Message rule.** The trailing `:` leaves the message. Where the message repeats a path the scope now
carries, drop the path and keep the verb. Interpolated values move into named `ctx` keys.
**Never add a value that was not already in the string.**

**Control flow rule.** Byte-for-byte equivalent. Status codes, response bodies, catch structures and
`.catch` attachments are unchanged.

**Style rule.** Several of these files use single quotes (`upload/route.ts`, `files/.../route.ts`,
`custom-fields/save/route.ts`). Match the surrounding file; the repo is mixed. Do not reformat.
</migration_contract>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated internet → pre-login auth routes | `signup`, `verify-email`, `forgot-password` and `reset-password` receive raw credentials, reset tokens and email addresses from anonymous callers |
| API-key holder → api-keys routes | Key creation and regeneration have a freshly minted secret in scope at their catch sites |
| uploaded file / stored file → upload and files routes | Filenames and entity ids from client input |
| internal cron caller → internal/email/process | Runs with `INTERNAL_SECRET`; its catches have queued email rows in scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-31 | Information disclosure | the four pre-login auth route catches | mitigate | All four currently log a fixed label plus the caught error and nothing else. The migration adds no `email`, `token`, `password` or `body` key — `err` is the only `ctx` key. Enforced by a grep acceptance criterion over those files plus a requirement to quote each migrated line verbatim in the summary. A leaked reset token in a log line would be a credential disclosure, not a hygiene issue. |
| T-42-32 | Information disclosure | `api-keys/route.ts:100` and `api-keys/[id]/route.ts:58` | mitigate | A freshly generated API key is in scope at both catches and must not enter `ctx`. Same grep criterion, same verbatim quoting requirement. |
| T-42-04 | Information disclosure | `deliver.ts:39` and `notes-collection.ts:165` | mitigate | The webhook URL, its payload and the notes `result` object are all in scope and none of them is in the current log string. Only the field the original surfaced is carried. |
| T-42-33 | Denial of service | `src/lib/api-keys.ts:77` | mitigate | The `.catch` must survive as a `.catch`. It guards a fire-and-forget `lastUsedAt` update on the API-key validation path; removing it turns a dropped update into an unhandled rejection on every authenticated v1 request. And `.catch(log.error)` — the form that compiles and is wrong — would emit an unusable line on exactly that path. |
| T-42-05 | Tampering / Repudiation | user-controlled text reaching a log line | mitigate | Inherited from plan 01: `JSON.stringify` escapes newlines, so an uploaded filename or a search query containing a newline cannot forge a second log line. `search/route.ts` and the files route are the two most likely sources of adversarial text in this set. |
| T-42-34 | Repudiation | downgrading the rate-limit warning | mitigate | `rate-limit.ts:27` stays `log.warn`. Promoting it to `error` would drown the error stream under normal abuse traffic; demoting it to `info` would hide it under the default `LOG_LEVEL`. Asserted by a count criterion. |
</threat_model>
