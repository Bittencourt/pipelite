<migration_contract>
Signature: `log.<level>(scope, msg, ctx?)` — exactly three arguments, the error ALWAYS under `ctx.err`.
Import: `import { log } from "@/lib/log"`.
Level map: `console.error`→`log.error`, `console.warn`→`log.warn`, `console.log`→`log.info`,
`console.info`→`log.info`. **A warn stays a warn.**

**Scope rule.** A `[bracket]` prefix in the existing string — whether written inline or interpolated from
a module-level constant — ⇒ use that name verbatim as `scope`. No bracket ⇒ derive from the module path:
strip the leading `src/`, strip the file extension, keep every remaining segment
(`src/lib/views/actions.ts` → `lib/views/actions`).

**Message rule.** The trailing `:` leaves the message. The prefix interpolation disappears entirely.
Every other interpolated value moves out of the string into a named `ctx` key and the message becomes
fixed. **Never add a value that was not already in the string.**

**Constant deletion.** After a file's last site migrates, delete its `LOG_PREFIX` declaration, having
first grepped for other uses.

**Control flow rule.** Byte-for-byte equivalent. Swallow-and-log catches keep swallowing; return shapes,
status codes and redirects are unchanged.
</migration_contract>

| failed workflow run → failure-alert log line | Alert-path catches have run payloads and step outputs in scope |
| trashed CRM records → trash-queries log lines | Seven sites on the trash read paths, each with an entity type and id in scope |
