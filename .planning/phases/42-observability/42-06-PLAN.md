<migration_contract>
Signature: `log.<level>(scope, msg, ctx?)` — exactly three arguments, the error ALWAYS under `ctx.err`.
Import: `import { log } from "@/lib/log"`.
Level map: `console.error`→`log.error`, `console.warn`→`log.warn`, `console.log`→`log.info`,
`console.info`→`log.info`.
Scope rule: a `[bracket]` prefix in the existing string ⇒ use that name verbatim as `scope` (the 22
existing names are referenced by name in file headers and runbooks). No bracket ⇒ derive from the
module path with `src/` and the extension stripped and `/` kept.
Message rule: the trailing `:` moves out of the message. Interpolated values move OUT of the string
into `ctx` keys. **Never add a value that was not already in the string** — logs carry counts only,
never row contents.
Control flow rule: byte-for-byte equivalent. A swallow-and-log catch keeps swallowing, its body keeps
exactly one statement, and a mandatory `.catch(...)` stays attached. Read any header comment above a
catch before touching it.
</migration_contract>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external HTTP / DB rows → processor tick bodies → log line | Tick bodies handle webhook payloads, email queue rows, scheduled-workflow rows and trash records; whatever they log crosses into the container's stdout |
| processor module graph → heartbeat registry | The write side of the `globalThis` bridge that `/api/health` reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-04 | Information disclosure | the 33 migrated call sites | mitigate | The migration contract forbids adding any value that was not already in the string. `trash/prune.ts:184,187` already log an entity type and id and keep exactly those; no row contents, no field values, no record bodies are introduced. Enforced by the `git diff` acceptance criterion and by reviewing each site against its original string. |
| T-42-24 | Denial of service | `recordTick` placement | mitigate | `recordTick` never throws (plan 02 makes an unknown name a no-op) and sits outside the `try`, next to a reschedule call whose out-of-try placement is already asserted by `prune.test.ts:31`. A throw there would break the `setTimeout` chain and silently kill the processor — the exact class of failure this phase exists to detect. |
| T-42-10 | Repudiation | tick recording semantics | mitigate | The tick is recorded on body COMPLETION, not on success, so a processor whose every tick throws reads alive-and-broken rather than dead. Asserted behaviourally in task 1 for both pruners. Conflating the two would let a real outage hide behind an accurate-looking 503, or a broken processor hide behind a 200. |
| T-42-25 | Tampering | control flow of swallow-and-log catches | mitigate | Byte-for-byte equivalent control flow is a hard constraint. `trash/prune.ts:60-70` carries a header explaining why its catch swallows; the migration changes the call and nothing else. The existing suites' "still swallows" assertions must keep passing untouched. |
| T-42-09 | Denial of service (of the background jobs) | these six files' Turbopack chunks | mitigate | All six live in the 21 chunks standalone tracing drops and `Dockerfile:24-41` restores. This plan does not change that, and does not need to: `/api/health` (plan 05) is the runtime detector and plan 03's Dockerfile postcondition is the build-time one. Recorded here so the asymmetry is understood as the design rather than a risk. |
</threat_model>
