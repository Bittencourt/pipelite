<objective>
Build `src/lib/observability/heartbeat.ts` — the in-process worker registry that `/api/health` reads
and that all six processors and all four subscribers write to.

Purpose: OBS-03's foundation, and the location of this phase's two proven traps.

Trap one (amendment A1): if the response is built by iterating the live registry, a completely dead
`register()` serializes as `processors: {}` and `Object.values({}).every(...)` is **`true`** — the
endpoint returns 200 ok on precisely the failure it exists to detect. So `snapshot()` iterates a
hard-coded ten-name roster and reports an unregistered worker as `alive: false`, present in the JSON.

Trap two (amendment A2): `src/lib/events/bus.ts` exists as FOUR independent Turbopack module instances
in this repo's own build (`587400`, `117126`, `930245`, `947362`) — including two inside the same
`register()` call. A module-level `const` registry would be duplicated between two processors started
by the same function. The registry must be a namespaced `globalThis` singleton.

Output: `src/lib/observability/heartbeat.ts` and `src/lib/observability/heartbeat.test.ts`.
</objective>

```typescript
// src/lib/observability/heartbeat.ts
export type WorkerKind = "processor" | "subscriber"

export const EXPECTED_WORKERS = [
  "webhook-processor", "email-processor", "schedule-processor", "execution-processor",
  "audit-prune", "trash-prune",
  "webhook-subscriber", "workflow-trigger-subscriber", "stage-history-subscriber", "audit-subscriber",
] as const

export interface WorkerReport { alive: boolean; lastTickAt: string | null }

export function registerProcessor(name: string, expectedIntervalMs: number, initialDelayMs: number): void
export function registerSubscriber(name: string): void
export function recordTick(name: string): void
export function snapshot(now?: number): Record<string, WorkerReport>
export function _resetForTesting(): void
```

Per-worker constants, read from every processor file — the spread is a factor of 17,280, which is why
one global staleness rule is impossible:

| `email-processor` | `src/lib/email-processor.ts:1-2` (module-private) | 15 s | 300 s |

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| instrumentation module graph → route module graph | Heartbeat writes happen in the graph loaded by `register()`; reads happen in the route graph. `globalThis` is the only reliable bridge, proven by four distinct Turbopack module IDs for `bus.ts` in this repo's own build. |
| in-process registry → unauthenticated HTTP response | `snapshot()`'s output is serialized directly into the public `/api/health` body by plan 05 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-10 | Repudiation | `snapshot()` | mitigate | The system must not be able to deny a failure it is built to detect. `snapshot()` iterates the hard-coded `EXPECTED_WORKERS` roster, so a dead `register()` yields ten `alive:false` entries rather than an empty object that `every()` reads as healthy. Proven by the empty-registry test AND by RED #2 wrong-implementation A. |
| T-42-13 | Tampering | the registry map | mitigate | The `Map` is module-private; only `registerProcessor`, `registerSubscriber`, `recordTick` and `_resetForTesting` can mutate it, and `snapshot()` returns a freshly built plain object rather than a reference into the map. A caller cannot flip a worker to alive. |
| T-42-14 | Information disclosure | `WorkerReport` fields | mitigate | The report carries exactly two fields: `alive` and `lastTickAt`. No interval, no `registeredAt`, no error text, no counts — nothing that would widen the unauthenticated payload plan 05 exposes. |
| T-42-03 | Information disclosure | the ten worker names | accept | An unauthenticated caller learns that ten named background jobs exist and which are dead. CONTEXT requires the endpoint open for load balancers and uptime checks; the reconnaissance gain is limited to job names already visible in the open-source repo. |
| T-42-11 | Denial of service | `recordTick` on an unknown name | mitigate | No-op rather than throw. `recordTick` is called from processor tick tails, several of which sit outside a try/catch on purpose; a throw there would break the reschedule chain and kill the processor. |
</threat_model>
