<objective>
Create the two controlled dialogs the bulk action bar opens: the count- and retention-aware delete
confirmation, and the owner reassignment form.

Purpose: both dialogs are the last thing between a click and a hundred writes, so their copy carries
the phase's safety contract. The delete dialog must name the real retention window read from trash
settings, and must say something DIFFERENT when no window is configured — `readTrashRetentionDays()`
fails closed to `null` (Phase 37 T-37-05: "default in data, fail closed in code"), so a hardcoded
"30 days" would be the UI lying about its own deployment. The reassign dialog must state in writing
that no email is sent, because the single-record path DOES email a new assignee and silence would be
an implied promise.
Both are controlled with no trigger of their own — the non-definer shape `trash-table.tsx` uses —
because a React element crossing the RSC boundary into a Radix `asChild` slot renders nothing at all,
silently (Phase 44 CFUI-01), and a repo-wide gate fails the build on it.
Output: two `'use client'` dialogs and a comment-stripped source gate over both.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server page → dialog props | Only plain serializable values may cross (`retentionDays: number \| null`, `owners: {id,name}[]`); a React element crossing into a Radix `asChild` slot renders nothing at all |
| dialog copy → user decision | The strings are the user's only information before a hundred writes |
| owners prop → ownership transfer | An unapproved or soft-deleted user in that list becomes the owner of up to 100 records, and the write succeeds so no per-record failure reports it |
