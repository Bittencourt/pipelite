<objective>
`GET /api/v1/stages/:id` 403s the stage's legitimate owner. The GET builds its `with` options from the
caller's `?expand=pipeline` (`:59-62`), so the relation its ownership predicate reads at `:74` is never
loaded, and `!stage.pipeline` short-circuits to `Problems.forbidden()`. The file's own
`verifyStageOwnership` helper at `:33-51` loads the relation **unconditionally** and is already used
correctly by PUT (`:93`) and DELETE (`:149`).

The fix is deletion, not addition: **the GET calls the existing helper, unchanged.** Its `:74` predicate
is a byte-for-byte copy of the helper's `:46`; the only difference is who decides what the check can see.
No input may decide what an authorization predicate can see.

Purpose: SEC-02, ROADMAP SC-4.
Output: the GET reduced to the PUT/DELETE prologue plus a projection, a test covering all four SC-4 cells
with the vacuous one labelled, and an assertion guarding the leak the fix itself creates.
</objective>

<constraints>
1. **`verifyStageOwnership` needs NO change.** It already returns the `{ stage, owned }` pair that yields
   exactly the 404-vs-403 discrimination the GET performs, and its `!stage.pipeline` and `deletedAt`
   branches are identical to the GET's. Modifying the helper would change PUT and DELETE behaviour and is
   out of scope.
2. **THE SC-4 VACUITY TRAP — handle it, do not rediscover it.** Of the four cells, only
   `owner + no expand → 200` is red today. `non-owner + no expand → 403` is 403 today for the WRONG
   reason (the relation is never loaded, so the predicate never runs) and passes identically before and
   after the fix. Assert all four cells; label the three green-today cells **regression guards** in the
   test source and in the SUMMARY; present only the first as evidence.
3. **The fix creates its own leak.** After the change `stage.pipeline` is always populated, so the
   `expand.has("pipeline") &&` guard at `:80` stops being belt-and-braces and becomes the only thing
   preventing a bare GET returning the pipeline object. It gets its own assertion (SC-4c).
4. **The db mock must model relational loading.** A mock that returns the fixture with its `pipeline`
   relation regardless of the `with` argument makes SEC-02 unreproducible — the route would return 200
   before the fix and the test could never go red. The mock inspects `with` and strips the relation when
   it was not requested, and that behaviour is asserted in its own test before any route assertion
   depends on it.
5. 403 stays; do not change it to 404. The existence-leak tension is recorded and deliberately deferred.
6. `rtk` hazards: `./node_modules/.bin/vitest`, never `npx`; `node -e` for counts; `git diff --exit-code`
   for cleanliness.
</constraints>
