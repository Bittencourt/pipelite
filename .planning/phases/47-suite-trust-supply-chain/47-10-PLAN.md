<objective>
Make the properties that keep the allowlist honest into assertions that run on every commit, offline.

Purpose: the allowlist is a mechanism for **suppressing security signal**. Everything that makes it
trustworthy — a reason that is actually a reason, an expiry that is actually enforced, a `failOn` that
has not been quietly emptied — is a convention until a test asserts it. This is precisely where a gate
goes quietly green, and 47-VALIDATION requires three of the controls to be **permanent in-file cases**
rather than run-once-by-hand, in the shape `node-engines-floor.test.ts`'s NC-3 already established.

This gate is deliberately OFFLINE. The one assertion that needs network — every allowlisted GHSA is
still reported by a live `npm audit` — lives in `scripts/audit-policy.mjs`, because the base vitest
project must stay offline-clean. That split is stated in both headers.

One cross-gate hazard is handled here explicitly: this file's expiry assertion,
`expect(new Date(entry.expires).getTime()).toBeGreaterThan(Date.now())`, is structurally identical to
`src/app/admin/users/actions.test.ts:59` — a designated FALSE POSITIVE of the SC-1b timing gate 47-05
built. If 47-05's taint rule were not exactly "left operand of a subtraction, or a division of two
tainted values, and NOT an addition producing a future timestamp", this file would become that gate's
first casualty. 47-05 already carries that exact expression as a KNOWN_NEGATIVE fixture; this plan
verifies the pairing from the other side.

Output: an offline policy-shape gate with three permanent negative controls and their complements.
</objective>
