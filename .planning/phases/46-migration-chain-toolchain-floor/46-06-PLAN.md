<!-- Read from the live environment at plan time, 2026-08-25. -->

docker needs NO sudo here (the user is in the `docker` group). NEVER embed a password in a command.
NEVER run `npm run dev` / `next dev`.

  app container name      : pipelite-app-1
  app image name          : pipelite-app
  postgres container name : pipelite-postgres-1   (image postgres:16-alpine)
  compose network name    : pipelite_default
  host port mapping       : 3001 -> container 3000 ; Postgres 5433 -> 5432
  health route            : src/app/api/health/route.ts

Expected shape of a healthy response (measured during research):
  HTTP 200
  {"status":"ok","db":{"ok":true,"latencyMs":3},"processors":{…}}   processors: 10, all alive: true

docker-compose.yml deliberately declares NO healthcheck on `app`, because /api/health legitimately
returns 503 when a worker reads stale and `restart: unless-stopped` would then restart-loop the
container. The trash-prune worker announces after a ~60s initial delay, so allow up to ~120s of polling
before treating a 503 as a failure — and read the body rather than the status alone.

`-e` overrides `--env-file` in `docker run`, so `--env-file .env -e DATABASE_URL=…` yields the override
while every other secret stays off the command line. `.env` holds a live SMTP_PASSWORD and AUTH_SECRET —
never echo it, never pass its values as literal `-e` arguments.

`docker-entrypoint.sh:2` is `set -e` and the entrypoint runs `npx drizzle-kit migrate` at boot. Against
an already-migrated database that is a correct no-op emitting only 42P06/42P07 NOTICEs. On the tree as
it stood BEFORE this phase, a fresh volume made that entrypoint crash-loop — which is why DEPLOY-01
made `docker compose up` on a clean host impossible rather than merely inconvenient.
