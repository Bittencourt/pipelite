<key_facts>
- **`audit-entry.tsx` was read at its current post-45-06 state: 495 lines, all four rules land in one
  40-line region, lines 408-460.**
- **A-2 is not free, and the UI-SPEC did not anticipate this.** Line 409 is
  `const predicate = t(\`entry.${entry.action}.${entry.entityType}\`)` — computed with **no values
  object** — while `audit.entry.merged.*` carries `{name}`. **Planner decision: pass the values
  object unconditionally**, `t(key, { name: entry.mergedLoserName ?? "" })`. next-intl tolerates an
  unused values object, so the three existing predicates are unaffected, and one call site stays one
  call site — which is what A-2's "no new predicate-building code path" is protecting. A conditional
  ternary would create the second path A-2 forbids.
- **`loserName` is not on `AuditTimelineEntry` today** and must be added and hydrated. The hydration
  site is `src/lib/timeline/sources.ts:780`, the only caller of `buildAuditFieldChanges`.
- **`buildAuditFieldChanges` returns `[]` for `deleted`**, which is why `PURGE_MARKER`'s `__purge`
  key has never rendered. `merged` renders its field list (A-5), so the three marker keys plan 39-09
  writes WOULD render as unlabelled rows unless they are skipped. Skipping `__`-prefixed keys is
  new behaviour for `updated` too — assert that a `__purge` key on an `updated` action is skipped, so
  the rule is proven general rather than special-cased.
- **A-5: keep `entry.action === "deleted" ? null : ...` exactly as narrow as it is.** Widening it to
  include `merged` would silently delete the field detail that makes success criterion 5 meaningful.
- **A-6: the empty-changes fallback must branch on the action.** `audit.entry.noVisibleChanges` reads
  as a bug report in prose (that branch's own comment says so). For a merge where the survivor won
  every field, no values changed and that is a correct, expected outcome — render
  `audit.entry.mergedNoFieldChanges`. Leave the `created`/`updated` wording exactly as it is.
- **A-7:** `audit.entry.mergedChildren` renders as ONE Label-typography muted line beneath the
  predicate row and before the field list.
- **A-3: the loser's name is plain text, never a link.** The loser is soft-deleted; `/trash` owns
  that affordance and a 404-ing link from a timeline is worse than a name.
- **A-8: `AUDIT_FIELD_LABELS` and `NATIVE_ORDER` are untouched.** 45-06 recorded that `NATIVE_ORDER`
  is derived from `AUDIT_FIELD_LABELS`' insertion order and adding a key there reorders every record
  timeline in the app.
- **The filter-then-derive-count ordering at lines 428-438 matters.** A change that renders `null`
  must also leave the array, or `hiddenFieldCount` promises "show 1 more" and produces nothing. The
  marker filter therefore belongs in `buildAuditFieldChanges`, upstream of both.
- **The gate must be brace-scoped, not file-wide** (A-10, the 45-06 precedent in
  `deleted-at-wiring.test.ts`): `merged` and `noVisibleChanges` are how other rows work elsewhere in
  the file, so a file-wide negative assertion is answered by unrelated code. Use `callArguments` /
  a quote-aware brace matcher from `src/components/custom-fields/__tests__/source-scan.ts`.
- The comment/grep collision fired fifteen times across phases 37-38, and once IN REVERSE. Use
  `readStrippedSource` for every gate, prefer minimum counts over exact counts when the target string
  is the natural way to explain the mechanism, and keep at most one deliberately RAW read — and only
  where the asserted token exists solely in a comment.
