<objective>
Close the asymmetry plan 39-18 created and recorded as a known residual: the `/duplicates` identity-field
picker offers EVERY organization custom field label, while only a `text`-typed label can ever be
collected at create time or ever decide a certain match. An admin can therefore choose `Tier`, see
`Identity fields saved.`, and get nothing — the same silent-failure class D-39-01 was.

Purpose: `identity-inputs.ts`' own module header names this residual in as many words ("the admin
identity-field form offers every organization field label with no type filter, so an admin can
configure a non-text field and see it saved while no input ever appears for it. Filtering that
control is a separate decision, not this module's to make"). The human verifier has now made that
decision: close it.

The load-bearing requirement is NOT "add a filter". It is that **the picker's rule and the dialog's
rule are the same rule, in one place.** A second, independently written type filter in the form
would reproduce the defect one layer up the moment the two disagreed — and 39-18 has already
established a rule subtler than "type === text": a label whose two active definitions DISAGREE about
type is collectable by neither side, because `customFields` is keyed by NAME and one blob key
addressed by a `text` row and a `multi_select` row cannot be safely filled from a text input.

Output: the predicate extracted and exported from `identity-inputs.ts` and consumed by both sides;
`/duplicates/page.tsx` projecting through it; the form keeping a stranded stored value visible
rather than blanking it; one new `dedup.identity.*` sentence in three locales; and an equivalence
test that fails if the two sides ever diverge.

NOT in this plan: any change to what the create dialog collects (39-18 owns that and is merged), any
Docker rebuild, and any change to `e2e/`.
</objective>

`src/lib/dedup/identity-inputs.ts` as it stands after 39-18 — the rule to extract lives inline in
the loop at lines 90-101:

```ts
export const IDENTITY_INPUT_FIELD_TYPE = "text"

interface FieldTypeByName { name: string; type: string }   // private today

export function selectIdentityInputFields(
  configured: readonly string[] | null,
  definitions: readonly FieldTypeByName[]
): string[] {
  if (configured === null || configured.length === 0) return []
  const selected: string[] = []
  for (const label of configured) {
    if (selected.includes(label)) continue
    const matching = definitions.filter((definition) => definition.name === label)
    if (matching.length === 0) continue                                            // ← predicate
    if (!matching.every((d) => d.type === IDENTITY_INPUT_FIELD_TYPE)) continue      // ← predicate
    selected.push(label)
    if (selected.length === ORG_IDENTITY_FIELDS_MAX) break
  }
  return selected
}

export async function readOrgIdentityInputFields(): Promise<string[]>   // fail-closed, 2 reads, 1 round trip
```

Note `matching.every(...)`: on an EMPTY array `every` returns true, which is exactly why the
`matching.length === 0` test has to come first and must travel with it into the extracted function.
