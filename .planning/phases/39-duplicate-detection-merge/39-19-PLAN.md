The certain rule for organizations, from `src/lib/dedup/scoring.ts`
(`classifyOrganizationMatch`) — the fixture must satisfy BOTH conjuncts:
```
namesMatch  = isComparableOrgName(a.normName) && isComparableOrgName(b.normName) && a.normName === b.normName
identity    = first configured field populated on BOTH sides, with EQUAL values
certain     = namesMatch AND identity
otherwise   = LIKELY_SIMILAR_NAME  ← NOT surfaced at create time
```
So: same name + same identity value → advisory. Same name + DIFFERENT identity value → `likely`,
which `findCertainOrganizationMatches` filters out (`classification.tier !== "certain"` → `continue`).
That asymmetry is this spec's own discriminator and needs no source tampering to exercise.

Catalog anchors, all PLAIN strings (no ICU), read from `src/messages/en-US.json` rather than typed
into the spec (39-VALIDATION V-3):
```
dedup.warning.createAnyway = "Create anyway"
dedup.warning.body         = "Check whether one of these is the record you meant. You can still create a new one."
dedup.warning.openExisting = "Open in a new tab"
dedup.reason.nameIdentity  = "Same name and the same identifying field"
```
`dedup.warning.title` is `{count, plural, …}` and is deliberately NOT used as an anchor — the spec
would have to reimplement ICU selection to read it.

Literals that are NOT in the catalog and must be typed, with a comment saying why:
`"Add Organization"` (the `data-table.tsx` trigger, line 358) and `"Create Organization"` (the
dialog's un-warned submit label). 39-UI-SPEC § "Out of scope, stated so the checker does not flag
it" records that both dialogs carry ~20 hardcoded English literals each and that this phase
declines to migrate them. A locator on them is therefore unavoidable, not sloppiness.

DOM ids from plan 39-18: each identity input is `#org-identity-0`, `#org-identity-1`, in configured
order. The native fields are `#name`, `#website`, `#industry`, `#notes`.

The advisory's DOM, from `src/components/dedup/duplicate-warning.tsx`: an `<Alert variant="default">`
containing an `AlertTitle`, a `<p>` with `dedup.warning.body`, then a `<ul>` of `<li>`s, each
holding an `<a target="_blank" rel="noopener noreferrer" href="/organizations/<id>">` with the
record name plus an `sr-only` span, then two `<p>`s: the distinguishing value and the reason.

Harness facts, from `playwright.config.ts`:
- `fullyParallel: false`; one app instance, one shared database.
- The `chromium` project supplies `viewport: { width: 320, height: 640 }` and
  `storageState: "e2e/.auth/admin.json"`, and depends on the `setup` project.
- `launchOptions: { ignoreDefaultArgs: ["--hide-scrollbars"] }`.
- No `webServer` block: the harness attaches to the already-running Docker container at
  `http://localhost:3001`.
