<key_facts>
- **The insertion point is exact:** the certain-match lookup goes between the `auth()` guard and the
  `runWithActor` call in `createOrganization` (`src/app/organizations/actions.ts:29-47`) and its
  person twin. The `confirmDuplicate` flag skips it. `runWithActor` still opens only after the
  session check (T-36-02).
- **Adding a third member to the return union is a breaking change for both dialogs.** Their
  `if (!result.success) { toast.error(result.error) }` branch stops typechecking, because the new
  member has no `error`. **Expect exactly two typecheck errors at the intermediate commit** — one per
  dialog — and say so; 45-05 established that predicting the intermediate error count is how this is
  done honestly rather than by suppressing it.
- **W-1:** the warning renders inline INSIDE the open create dialog, directly above the form, as
  `Alert variant="default"` with a `TriangleAlert` icon. Not a nested dialog, not a Sheet, not a
  toast. A second modal over a modal at 320px has nowhere to go, and a toast is dismissible by
  timeout — an advisory a user can miss is not an advisory.
- **C-1:** `Alert variant="default"`, never `destructive`. There is no `--warning` token and this
  phase does not add one (`globals.css` stays untouched). A possible duplicate is not an error, and
  the decision that the warning is advisory is contradicted by red. The weight is carried by the words
  and the icon.
- **W-2:** the dialog does not close and the form does not reset. `organization-dialog.tsx` already
  goes to considerable lengths to protect an in-flight draft (the `createdRecordIdRef` guard,
  T-35-31/WR-12); the warning path must not become the one way to lose one. Nothing was created, so
  `createdRecordIdRef` stays null.
- **W-3:** each matched row's name is a link with `target="_blank" rel="noopener noreferrer"`.
  Opening in the same tab would destroy the draft, which is exactly what W-2 exists to prevent. The
  accessible name is `dedup.warning.openExisting` ("Open in a new tab") so the behaviour is announced,
  not implied.
- **W-4:** "create anyway" is the dialog's EXISTING submit button, relabelled
  `dedup.warning.createAnyway` while the warning shows. It stays the single primary-filled control.
  The second submit carries the confirm flag so the server skips the check — the check must not run
  twice and produce the warning again.
- **W-5:** cancel is the dialog's existing `common.cancel` / close. No new control.
- **W-6:** no "merge now", and the reason is worth restating in the code: there is no losing record to
  trash and no field history to reconcile for an unsaved draft. Gated at zero occurrences of
  `dedup.merge.` in both dialogs.
- **W-7:** each matched row shows three things, stacked: the name (the link), its distinguishing value
  at Label typography muted, and its match reason from `dedup.reason.*`. Never a horizontal row, which
  cannot survive 320px inside a dialog. **A matched record is never shown without its reason** — a bare
  name the user cannot audit is what turns a warning into noise people learn to click through.
- **W-8:** capped at five. Six certain matches means the data is broken in a way a create-time
  interruption cannot fix. No "and N more" link.
- **W-9:** while the check is in flight the submit button shows its EXISTING loading state. No separate
  "Checking for duplicates…" step — the check is part of the submit, and naming it invites the user to
  think it is optional.
- **W-10:** the warning clears when the user edits any compared field (name, website, email, phone).
  A stale warning about a name the user has since changed is worse than none.
- **The importer gets a report, not a prompt** — plan 39-16. Nothing in this plan makes the importer
  interactive.
- **Out of scope, deliberately:** both dialogs carry roughly twenty pre-existing hardcoded English
  literals each ("Add Organization", "Organization created!", every field label and placeholder).
  Phase 45's S-8 assigned those to "Phases 39-43" and this phase declines them: migrating two 400-line
  record dialogs inside the same change as the warning would make the warning's own diff
  unreviewable. **The narrow, enforceable rule is: every string this phase ADDS comes from the
  catalog — zero NEW hardcoded literals in any file it edits.**
</key_facts>
