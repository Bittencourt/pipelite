<objective>
Build the two pure functions the whole matching layer rests on: name normalization and
confidence-tier classification. Both are decided here, in TypeScript, with tests, before any
database object exists — because the SQL function written in plan 39-03 must agree with this one
character for character, and the only way to state what "agree" means is to have a checked-in table
of cases.

Purpose: SC-1 (create-time warning) and SC-2 (scan) are both downstream of these two decisions. A
wrong suffix rule silently halves the recall of a 46,054-row scan; a missing email-sentinel guard
turns 212 people whose email is `#` into a 22,366-pair clique (measured, 39-RESEARCH B2).
Output: `src/lib/dedup/` with constants, types, normalization and scoring, fully unit-tested.
</objective>

- The SQL normalization this file mirrors (39-RESEARCH § The Matching Layer, item 2), exercised
  against the live database:
  `btrim(regexp_replace(regexp_replace(regexp_replace(lower(immutable_unaccent(coalesce($1,''))), '[^a-z0-9]+', ' ', 'g'), '\m(ltda|me|epp|eireli|sa|cia|mei)\M', ' ', 'g'), '\s+', ' ', 'g'))`
- Measured outputs to reproduce exactly:
  `COGUMELO INDUSTRIA E COMERCIO LTDA` → `cogumelo industria e comercio`;
  `AUTO POSTO MR DA TAQUARA LTDA ME` → `auto posto mr da taquara`;
  `Condomínio do Edifício Internacional RIo` → `condominio do edificio internacional rio`;
  `Ramada Hotel & Suítes Recife Boa viagem` → `ramada hotel suites recife boa viagem`.
- **Do NOT strip standalone `s` or standalone `a`** — `a` is a Portuguese article. 39-RESEARCH
  explicitly warns that the probe version which stripped them was wrong.
- 16,763 organizations (36.4%) carry a legal suffix, so the suffix step is load-bearing.
- 9 of 46,054 organizations produce no token of length ≥ 3; they must never match each other.
- Person email tiers: unfiltered exact-email grouping yields 28,032 pairs with a largest group of
  212 (`#`); requiring a syntactically valid address yields 5,338 pairs, largest group 23.
  `teste@gmail.com` (23) and `teste@teste.com` (16) are the next two junk values.
- Person names: normalized `nao encotrado` appears 559 times; `marcelo` ×78, `eduardo` ×71.
- Organization *certain* tier (39-CONTEXT § Post-Research Decisions, supersedes the locked
  "name + domain" rule): identical normalized name **AND** identical non-empty value of the first
  configured identity custom field that is non-empty on both records. Unconfigured → **no certain
  tier at all**, never a fall back to name-only (which measured 1,030,436 pairs).
