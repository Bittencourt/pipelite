<key_facts>
All verified against the live Docker Postgres by 39-RESEARCH:

- PostgreSQL 16.13. `pg_trgm` 1.6 and `unaccent` 1.1 are available and trusted but not installed.
  `pipelite` additionally has `rolsuper = t`, so the migration runs unattended.
- `unaccent(text)` is STABLE (`pg_proc.provolatile = 's'`), so
  `CREATE INDEX ... USING gin (unaccent(lower(name)) gin_trgm_ops)` fails with
  `ERROR: functions in index expression must be marked IMMUTABLE`. That failure is LOUD. The silent
  variant - the query's expression drifting from the index's - is what plan 39-05 EXPLAIN-verifies.
- The wrapper, schema-qualified so a restricted `search_path` cannot repoint it:
  `CREATE OR REPLACE FUNCTION public.immutable_unaccent(text) RETURNS text LANGUAGE sql IMMUTABLE PARALLEL SAFE STRICT AS $$ SELECT public.unaccent('public.unaccent'::regdictionary, $1) $$;`
- `upper`, `lower`, `btrim`, `regexp_replace`, `translate` and `similarity` are already IMMUTABLE.
- Migration doctrine (39-PATTERNS section 15). `drizzle/0014_sloppy_slapstick.sql` states Phase 33's
  D-06: no INDEX DDL is ever hand-written, because `drizzle-kit generate` owns the schema and
  silently dropped a hand-written index once (0009 to 0010). This migration contains no table and no
  index - only extensions and functions, which `generate` cannot emit and D-06 does not cover. Plan
  39-05 delivers the columns, indexes and tables through a normal `generate`.
- Last journal entry today: `idx: 15`, `tag: "0015_trash_retention_seed"`.
- `npx` is broken on this host - it resolves to `npm run` and fails with "Missing script". Use
  `./node_modules/.bin/drizzle-kit`.
- `scripts/trash-checks.sql` (667 lines) is the analog to copy structurally: numbered Parts, a Part 0
  before-snapshot, every mutating Part wrapped `BEGIN ... ROLLBACK`, a final Part that re-counts and
  asserts nothing changed, and a header stating it is re-runnable and mutates nothing. No credential
  ever appears in the file or on the command line - `psql` reaches the server over the container's
  local unix socket.
- `docker` needs no `sudo` on this machine. Never embed a password in any command.
