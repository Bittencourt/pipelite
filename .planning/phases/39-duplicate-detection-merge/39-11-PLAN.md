<key_facts>
- `src/middleware.ts` is five lines and checks no role. `src/app/admin/layout.tsx:11-17` is where all
  admin enforcement in this app actually lives. `/duplicates` sits outside `/admin`, so it needs its
  own copy of those two redirects, plus a re-check inside every action.
- `src/app/admin/audit/actions.ts`'s header states the rule authoritatively: a layout redirects a
  non-admin away from every page RENDER; it does not and cannot protect a server action, which is a
  POST endpoint the browser can invoke with no page involved. A disabled button is cosmetic and is
  never the control.
- `src/app/trash/actions.ts` is the shape for the error-code union and for runtime argument
  narrowing. Its `parseRecordId` uses a bare shape test (non-empty, at most 64 characters), not a UUID
  pattern, and its comment explains why: a type annotation is not a runtime control on a value that
  arrived over the wire.
- `src/app/trash/page.tsx` is the RSC analog: search params parsed through a validating parser before
  anything reaches a query, `auth()` then redirect, three independent reads via `Promise.all` none of
  which throws, and `isAdmin` used for VISIBILITY ONLY and never as the authorization.
- `src/app/trash/trash-tabs.tsx` is the tabs analog. `activationMode="manual"` is load-bearing, not
  stylistic: Radix selects on focus by default and each selection is a `router.push`. `counts === null`
  renders NO count rather than a zero. `TabsList` carries `max-w-full overflow-x-auto` (R-7).
  Switching tabs DELETES the `page` param.
- UI-SPEC L-1: state lives in the URL — `?type=organizations|people`, `?page=`, `?dismissed=1`.
  UI-SPEC L-2: two tabs labelled from the existing `nav.organizations` / `nav.people` keys.
- UI-SPEC's three distinct empty states, which is why `listPairs` returning `{ ok: false }` rather
  than an empty success matters: never scanned, scanned with zero pairs, and every pair dismissed.
  Each has its own heading, body and control, all from the catalog delivered by plan 39-04.
- UI-SPEC P-6: a running scan is visible to whoever opens the page, not only to whoever started it.
  A non-starter sees `dedup.scan.startedBy` and NO cancel button. The button's absence is presentation;
  `cancelDuplicateScan` enforces it.
- `cancelPipedriveImport` checks authentication but never ownership — the gap this route must not
  inherit.
- UI-SPEC K-1: zero new hardcoded literals in any file this phase adds or edits. The pre-existing
  English in the record dialogs and data tables is explicitly out of scope, but nothing NEW may be
  hardcoded.
- The identity-field control is a planner addition: 39-CONTEXT locks "the organization identity key
  is ADMIN-CONFIGURABLE" and the UI-SPEC has no surface for it. It lands here because `/duplicates` is
  already admin-only, which avoids both a new route and a twelfth admin nav item (45-09 gated the
  eleven admin items as declared once, counted by href).
</key_facts>
