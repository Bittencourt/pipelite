## Spacing Scale

Every value is a multiple of 4 and already appears in the codebase.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | `gap-1` between a confidence `Badge`'s icon and its label |
| sm | 8px | `gap-2` / `space-y-2` — between the two options of one merge field group; between a pair card's two action buttons; between the progress label row and the track |
| sm-plus | 12px | `px-3 py-2` on a merge option card; `p-3` on a pair-card body. **Declared, not an exception** — 12 is a multiple of 4, and a 16px inset on a one-line value in a list of 10+ field groups wastes a third of the 241px usable width at 320px |
| md | 16px | `space-y-4` between merge sections; `p-4` on the scan panel and each pair card; `gap-4` in the page header cluster |
| lg | 24px | `space-y-6` on the page shell (matches `/organizations`, `/trash`) |
| xl | 32px | `container` `padding-inline: 2rem` — inherited and **unchangeable**; it costs 64 of the 305px client width at 320px |
| 2xl | 48px | not used by this phase |
| 3xl | 64px | `py-8` × 2 — the `container py-8` page shell, inherited from `/organizations` |

**Fixed dimensions declared by this phase:**

| Dimension | Value | Why |
|-----------|-------|-----|
| Progress track height | **10px (`h-2.5`)** | inherited verbatim from `src/components/import/progress-bar.tsx`. Two visually different progress bars in one app is the defect this reuse prevents. The single non-multiple-of-4 in this phase, and it is pre-existing. |
| Merge option card min-height | **40px** | `px-3 py-2` around a `text-sm`/`leading-normal` line yields 20 + 16 = 36px; the radio is `size-4`. **Exceptions:** `h-2.5` (10px), above, is the only one. `max-w-sm` / `max-w-lg` are constraints, not
scale values.

## Typography

Four sizes, two declared weights. Every class already exists in the codebase.

| Role | Size | Weight | Line Height | Class | Where |
|------|------|--------|-------------|-------|-------|
| Label | 12px | 400 | 1.33 (16px) | `text-xs` | the record-name caption above each merge option's value; `current / total` under the progress track; the match-reason line on a pair card |
| Body | 14px | 400 | 1.43 (`leading-normal`, 20px) | `text-sm` | every value in the merge picker; the warning Alert body; pair-card record names; scan status text; the `merged` audit predicate |
| Heading | 18px | 600 | 1.2 (`leading-tight`) | `text-lg font-semibold` | the scan panel title; each merge section legend ("Which record do you want to keep?", "N fields differ") |
| Display | 30px | 700 | 1.2 | `text-3xl font-bold` | the `/duplicates` and `/duplicates/[pairId]` `<h1>` |

**Weight exception (inherited, not introduced here).** `text-3xl font-bold` is 700, and
`buttonVariants` bakes `font-medium` (500) into every `Button`. Neither is a weight *this phase
declares* — the h1 matches `/organizations`, `/people`, `/deals` and `/trash` byte-for-byte, and
using 600 there would make one page in the app look wrong. This is the same posture Phase 45 took
with `font-medium`: the two declared weights (400, 600) are the only weights this phase's **new**
copy introduces.

**Forbidden in this phase:**

- Any font size outside {12, 14, 18, 30}. In particular **no `text-2xl font-bold` stat tiles** — the
  Pipedrive progress step uses them (`progress-step.tsx:151`) and this phase deliberately does not,
  because a scan summary is one sentence, not a dashboard.
- `leading-none` on anything that can wrap. Every legend and every record name in this phase can
  wrap: pt-BR "Qual registro você quer manter?" is 34 characters inside 241px at 320px.
- Truncation (`truncate`, `line-clamp-1`) on **any value inside the merge picker**. A user choosing
  between two values must see both in full; a truncated website or address makes the choice
  unmakeable. Values wrap (`break-words`) instead. Truncation is permitted only on the pair-card
  record names in the *review list*, where the full value is one click away on the merge screen.

**Accent reserved for — the complete list for this phase:**

1. The `:focus-visible` outline on buttons, links and `[role="button"]` (global, already in `globals.css`).
2. **One primary-filled button per surface, and no more:**
   - `/duplicates`: "Scan organizations" / "Scan people" (or "Scan again" when a scan has run).
   - `/duplicates/[pairId]`: "Merge records".
   - the create dialog with a warning showing: the existing submit button, relabelled "Create anyway".
3. The **selected** merge option: the `RadioGroupItem` indicator dot (`fill-primary`, from the block) plus `border-primary` on its card. This is the only per-row accent in the phase.
4. The progress bar fill (`bg-primary`) — inherited from `src/components/import/progress-bar.tsx`.
5. The `Loader2` spinner shown while a scan is being started (`text-primary`), matching `progress-step.tsx:87`.
6. **A link from a listed row to the record it names** (`text-primary hover:underline`) — the pair
   card's two record names, and the create-time warning's matched-record links. This is the
   sanctioned accent use already documented in `audit-entry.tsx:357-361` ("a link from an entry to
   the record it describes"). Nothing else in this phase gets `text-primary` text.

**Explicitly NOT accent:** "Review and merge" on a pair card (`variant="outline"`), "Not a
duplicate" (`variant="ghost"`), "Show dismissed pairs" (`variant="ghost"`), the identical-fields
disclosure (`variant="ghost"` + `text-muted-foreground`, matching `audit-entry.tsx`'s show-more
affordance), "Find duplicates" on the list-page toolbars (`variant="outline"`), "Cancel scan"
(`variant="outline"`), and the "Back to duplicates" link (`variant="ghost"` with `ArrowLeft`).

**Rule C-1 — the create-time warning is `Alert variant="default"`, never `destructive`.**
There is no `--warning` token and this phase does not add one (`globals.css` stays untouched, per
Phase 45). A possible duplicate is not an error: the decision that the warning is *advisory, never
blocking* is contradicted by red. It renders as the default Alert (`bg-background text-foreground`,
`border`) with a `TriangleAlert` lucide icon, which `alertVariants` colours `text-foreground`. The
weight is carried by the words and by the icon, exactly as Phase 45 required of the bulk failure
panel ("colour is never the sole carrier").

**Rule C-2 — the merge confirmation's action button IS `variant="destructive"`.**
The consequence of a merge is that a record leaves the list and lands in Trash — the identical
consequence to the bulk delete, the single delete and the purge, all three of which use a
destructive `AlertDialogAction` in this repo. Using a different colour for the same consequence
teaches the user that red means "gone" except when it doesn't. The words carry it too
(`dedup.merge.confirmAction` = "Merge and move to Trash").

**Rule C-3 — confidence tiers are distinguished by WORDS first.** `certain` → `Badge
variant="default"` reading "Almost certain"; `likely` → `Badge variant="secondary"` reading
"Likely". Never a bare colour-only dot, and never red/amber/green.

### Locale-gate consequences

**L-1 — a new exact-set contract.** Add `REQUIRED_DEDUP_KEYS` to
`src/messages/locale-parity.test.ts`, listing all 69 `dedup.*` dot-paths, and assert it **totally**
against the shipped `dedup` namespace in all three locales — the `REQUIRED_BULK_KEYS` /
`REQUIRED_TRASH_KEYS` pattern, where a 70th string added to the namespace without a contract entry
fails the run. A presence-only check would not catch that.

**L-2 — `REQUIRED_AUDIT_KEYS` grows by exactly 4** (81 → 85). The audit contract is already
exact-set (`locale-parity.test.ts:668-674`), so adding the keys without extending the list fails,
and extending the list without adding the keys also fails. Both directions are already gated; do not
add a new assertion.

**L-3 — ten new ICU plural keys.** `placeholderDrift()` cannot see `{count, plural, …}` (its regex
is `/\{[a-zA-Z0-9_]+\}/g`), so the dedicated `icuPluralReport` assertion is the only defence. Extend
it to cover all ten: `dedup.warning.title`, `dedup.review.pairsFound`,
`dedup.merge.{conflictsLegend,filledLegend,identical,movesDeals,movesNotes,movesPeople}`,
`dedup.import.flagged`, `audit.entry.mergedChildren`. pt-BR and es-ES use `one`/`other` only —
correct for both.

**L-4 — `IDENTICAL_TRANSLATION_ALLOWED` needs no additions, and this must be verified, not
assumed.** `untranslatedInBoth()` flags a key only when **both** pt-BR and es-ES are byte-identical
to en-US. No string in the 69 satisfies that. The two near-misses are `dedup.reason.email`
(pt "Mesmo e-mail" ≠ en) and `dedup.merge.movesNotes` (pt and es are identical *to each other* —
"# nota" — which the function does not test). Run the gate; do not reason about it.

**L-5 — placeholder parity across five multi-placeholder keys.** `dedup.scan.progress`
(`{current}`, `{total}`), `dedup.scan.startedBy` (`{name}`), `dedup.scan.lastRun` /
`dedup.review.emptyNoPairsBody` / `dedup.merge.createdOn` (`{time}`), `dedup.merge.confirmBody`
(`{loser}` ×2, `{survivor}`) and `dedup.merge.success` (`{loser}`). `placeholderDrift()` compares
the *sorted joined set*, so `{loser}` appearing twice in en-US and once in a translation would slip
through if the set is deduplicated — check the helper's behaviour before relying on it for
`confirmBody`, and if it deduplicates, assert `confirmBody`'s occurrence count separately.

## Surface 4 — Merge Screen Contract

**This is the hard surface.** Locked: the picker **pre-selects the survivor's value except where the
survivor's is empty and the loser's is not**; the loser **soft-deletes to Trash**; the audit gets one
explicit `merged` entry naming the loser and the field choices, alongside the per-field diff.

### M-1 — Layout: a stacked field list, never side-by-side columns **[DISCRETION RESOLVED]**

The discretion item names the two candidates. **The stacked per-field option list wins, and
side-by-side columns are rejected outright — not merely de-prioritised at small viewports.**

Three reasons, in order of weight:

1. **320px makes columns unreadable, and this is measured, not asserted.** The usable width at a
   320px viewport in this app is 305 − 64 (`container` `padding-inline: 2rem`) = **241px**. Two
   columns plus a gutter gives each value ~112px. An organization name in this dataset is
   "CONDOMINIO EDIFICIO RESIDENCIAL …"; a website is a full URL. Neither is legible at 112px, and
   § Typography forbids truncating a value the user must choose between.
2. **Column headers scroll away.** With 10+ fields the user picking field 12 has lost the header
   that said which column is which — and picking the wrong survivor's value is a silent, permanent
   data error. In a per-field option list, **every option carries its own record name**, so the
   choice is unambiguous at every scroll position. This defect is viewport-independent: it hurts at
   1920px too.
3. **Radix `RadioGroup` per field is the correct accessible primitive** for "choose the winning
   value per conflicting field" (DEDUP-02), and it maps 1:1 onto the stacked list. A column layout
   needs the same radios anyway, laid out worse.

**The ergonomic advantage of columns — "keep everything from this record" — is recovered by the
survivor selector (M-2), which sets every default in one click.** That is the operation users
actually want columns for.

At `sm` (640px) and up, the two options of a single field group **may** sit in a
`grid gap-2 sm:grid-cols-2`. That is a two-up of one field's two options, not a two-column
comparison of two records: each option still carries its own record-name caption, so nothing depends
on a header. Below `sm` the grid collapses to one column and the options stack.

### M-2 — Section 1: which record survives

`RadioGroup` with two option cards, legend `dedup.merge.survivorLegend` at Heading typography, helper
`dedup.merge.survivorHelp` at Label typography muted. Each card shows the record name (Body),
`dedup.merge.createdOn` with a formatted relative instant (Label, muted), and the counts of what it
carries (`dedup.merge.moves*`). Default: the older record survives.

**Changing the survivor recomputes every field default and discards manual field choices.**
`dedup.merge.survivorHelp` states this *before* the click. No confirmation dialog — a dialog for a
reversible in-form change is friction, and the sentence is the honest mitigation.

### M-3 — Sections 2–4: three field groups, in this order

| # | Group | Legend | Default | Collapsed? |
|---|-------|--------|---------|-----------|
| 2 | **Conflicts** — both sides populated and different | `dedup.merge.conflictsLegend` | the **survivor's** value | never |
| 3 | **Filled only on the other record** — survivor empty, loser populated | `dedup.merge.filledLegend` + `dedup.merge.filledHelp` | the **loser's** value | never |
| 4 | **Identical** — equal, or both empty | `dedup.merge.identical` | n/a, no control | **yes**, behind `dedup.merge.showIdentical` |

Group 3 exists as its own visible section for one reason: its default **adopts a value from the
record being destroyed**. The locked decision calls that "the common real one", which is exactly why
it must not be silent — a default that quietly imports data is the thing a user needs to be able to
audit before pressing Merge. Hiding it inside group 2 or inside the collapsed group 4 would make the
merge's most surprising behaviour its least visible.

The group-4 disclosure is a `variant="ghost"` `text-muted-foreground` button with a chevron, matching
`audit-entry.tsx`'s show-more affordance exactly. It is a plain conditional render — no animation, no
`Collapsible` primitive — following `audit-entry.tsx:328`'s stated precedent.

### M-4 — Field labels come from the audit layer, not a new map

Every field label in the picker is resolved through `AUDIT_FIELD_LABELS` / `describeField` in
`src/lib/audit/present.ts`, which already maps `name`, `email`, `phone`, `website`, `industry`,
`firstName`, `lastName`, `owner`, `organization` to `audit.field.*` leaves and handles the `custom:`
prefix for custom fields. **No new field-label keys, and no second map.** The user sees the same word
for a column in the merge picker as in the timeline entry that records the merge — which is the
whole point, since one is the receipt for the other.

### M-5 — Option-card anatomy

```
<label> (the whole card is the label — the tap target is the card)
  <RadioGroupItem />                       size-4, indicator fill-primary
  <span class="text-xs text-muted-foreground">   record name (the caption)
  <span class="text-sm break-words">             the value
```

- Unselected: `rounded-md border px-3 py-2`. Selected: `border-primary` — plus the radio dot, so the
  state has two carriers and colour is never the only one.
- **An empty side renders `audit.value.empty` in `text-muted-foreground italic`, never a blank.** A
  blank option looks unclickable and is indistinguishable from a render bug; "choose emptiness" is a
  real, legitimate choice and must be presentable.
- Long values wrap (`break-words`). No `truncate`, no `line-clamp` (§ Typography).
- The `RadioGroup` is labelled by the field's label element (`aria-labelledby`), so a screen reader
  announces "Website — Acme Ltda, https://acme.com.br" rather than two bare values.

### M-6 — Section 5: what moves

A plain `<ul>` at Body typography stating exactly what will be reassigned, with counts:
`dedup.merge.movesDeals`, `dedup.merge.movesNotes`, `dedup.merge.movesPeople` (organizations only),
`audit.value.files`, followed by two sentences: `dedup.merge.activitiesFollowDeals` and
`dedup.merge.filesStayInPlace`.

This section is how success criterion 4 ("nothing is orphaned") becomes checkable by a human before
the merge rather than only afterwards. Both trailing sentences are load-bearing statements of locked
decisions: activities have no direct organization or person link and follow their deal transitively,
and file blobs stay at the loser's path.

### M-7 — Confirmation

`AlertDialog`. Title `dedup.merge.confirmTitle`; description `dedup.merge.confirmBody` with `{loser}`
and `{survivor}` interpolated; cancel `common.cancel`; action `dedup.merge.confirmAction`
(`variant="destructive"`, per rule C-2). The body states both that the loser is restorable from Trash
**and** that the merge itself is not undone — the second half is the part a user would otherwise
learn the hard way.

### M-8 — Failure states

| State | Rendering |
|-------|-----------|
| Merge failed | `toast.error(dedup.merge.failed)` — "Nothing was changed — try again." The form keeps every choice the user made. |
| One record already gone | `Alert variant="destructive"` with `dedup.merge.gone`, the form disabled, and `dedup.merge.backToList`. This is reachable: another user can merge or delete the same pair while this screen is open. |

**The merge is a single database transaction, so there is no partial-failure surface and no
per-record failure list.** Phase 38's principle (name the record that failed, never swallow it into
a count) is satisfied here by the transaction: either every child moved or none did. **If the plan
cannot deliver the merge as one transaction, this contract changes** and the screen must render a
`BulkFailureReport`-shaped list naming each child row that did not move — state which of the two is
being built, and do not leave it implicit.

### M-9 — The submit row is NOT sticky

`flex flex-wrap gap-2` at the end of the form: `dedup.merge.submit` (primary, `dedup.merge.submitting`
while in flight) then `common.cancel` (`variant="outline"`, returns to `/duplicates`). A `Card`
wrapper, no `sticky`, no `fixed`.

Phase 45's D-45-02 is an **open** UAT item about a fixed bar occluding "Back to App" at 1280px and a
save button at 320px in es-ES. Adding a second fixed bar to the app while that is unresolved would
compound a known live defect, and a form whose submit lives at the bottom of the form is the
universally understood arrangement anyway.

### M-10 — Route and navigation

`/duplicates/[pairId]`, a full page — not a `Dialog` and not a `Sheet`. The screen is a long form
with 10+ decision points; a modal at 320px would put it inside a scroll container inside the page's
scroll container. A route also gives the user a URL to return to when a merge fails, and a working
back button. `dedup.merge.backToList` (`variant="ghost"`, `ArrowLeft`) sits above the `<h1>`.

## Responsive Contract

Single breakpoints: `sm` = 640px (the merge option two-up), `md` = 768px (inherited shell collapse).
This phase introduces no new breakpoint.

| Rule | Requirement |
|------|-------------|
| R-1 | **`/duplicates` joins the `e2e/viewport-320.spec.ts` matrix**: 6 routes × 3 locales becomes **7 × 3 = 21** assertions. The route renders its empty state with no fixture data, so this costs no seeding. |
| R-2 | **The merge screen gets its own 320px spec, with its own fixtures.** `/duplicates/[pairId]` cannot be measured without a pair. Following 45-08's rule ("e2e specs that mutate data create and hard-delete their own fixture rows rather than borrowing a user's record"), the spec creates two organizations that will match, runs a scan or inserts the pair directly, measures `scrollWidth <= clientWidth` at 320 × 640 in all three locales, and hard-deletes both rows plus the pair afterwards. **This is the single most valuable verification in the phase** — the merge screen is where a side-by-side layout would have failed, and a spec is the only instrument that measures real layout (jsdom computes none). |
| R-3 | **Nothing in this phase may render two records horizontally adjacent at any viewport below `sm`.** Concretely: no `grid-cols-2` without an `sm:` prefix; no `flex` row of two record blocks without `flex-wrap`; no table whose columns are "record A" and "record B". This is the enforceable form of the M-1 decision and a source scan can check it. |
| R-4 | **Every flex row that can grow carries `min-w-0`** — the pair card's action row, the merge option grid's children, the toolbar search cluster. A flex item's default `min-width: auto` is the mechanism behind every overflow Phase 45 measured. |
| R-5 | **The `/organizations` and `/people` toolbars become `flex flex-wrap items-center justify-between gap-2`** when the "Find duplicates" button lands (L-10). They are non-wrapping today. |
| R-6 | The `container` gutter (`padding-inline: 2rem`, 64px of 305) is global and **unchangeable**. Every layout here fits inside the remaining 241px. |
| R-7 | The tab list uses `max-w-full overflow-x-auto` (`trash-tabs.tsx:97`). Two tabs fit at 320px; the class is belt-and-braces and matches the precedent. |
