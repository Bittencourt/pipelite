<objective>
Decide the export, in arithmetic, with no database in the room.

`guardExportInput` (`src/lib/export/view-export-guard.ts:128-139`) treats the PRESENCE of a filter as
authorization. `search=a` is a filter, so it passes, and it matches 44,254 of 46,054 organizations.
This plan builds the rule that refuses it — and nothing else. No call site changes here.

**Why the rule is a separate module and not a change to `guardExportInput`.** That function's own
header (`:18-19`) says: *"NO DATABASE IMPORT, and that is a property worth keeping: everything here is
decidable from the submitted filter map alone, which is what makes the refusal happen BEFORE any query
runs."* A cardinality rule needs I/O. Making the guard async would destroy that property, force an
`await` onto ~40 existing sync assertions in `view-filters.test.ts:575-708`, and lose the property
that a crafted `entityType` is refused with zero queries. So the decision splits in two: the
ARITHMETIC lives here, pure and synchronous; the COUNT lives in `src/lib/export/export-count.ts`
(plan 50-04) and imports `@/db`. Two files, not one, and that split is what makes this plan's cells
possible at all — `pipelite_dedup_test` starts empty and every live table is ≥ 25,195 rows, so the
small-N branch of this rule is unreachable by any database in this project. A pure function with
injected `(matched, total)` is the only instrument that can see it.

**NO ADMIN BRANCH, and this module asserts its own absence.** `view-filters.test.ts:736-747` forbids
an `admin`/`role` token in `export-action.ts`, and its message anticipates exactly the move a reader
would make here. `src/app/admin/export/actions.ts:16` is already a separate role-gated unbounded
export, so admins keep the path they have and the view path is bounded for everyone. Relocating the
branch into this module to keep that gate green would be gate-laundering, so this plan adds the same
two negative assertions to this module. The escape is closed on both sides.

Purpose: SEC-03's decision function, and the only place its floor can be proven.
Output: one pure module, one unit file whose cells fail for six distinct reasons, and a re-measured
live baseline every later plan reads its named integers from.

export const MAX_EXPORT_FRACTION = 0.4
/** A POLICY FLOOR, NOT A MEASUREMENT. See the doc comment. */
