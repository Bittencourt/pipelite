# Phase 34 Plan 13: Close the Two Verification Gaps

## Objective

Close the two gaps `34-VERIFICATION.md` recorded as `partial`: the CSV export's
first-row-only header derivation (SC-2) and the CSV importer's two unrecalculated
auto-create sites (FORMULA-01).

## Context

- @.planning/phases/34-formula-reactivity/34-VERIFICATION.md — the two gaps, stated precisely
- @.planning/phases/34-formula-reactivity/34-CONTEXT.md — D-01..D-19 LOCKED
- @.planning/phases/34-formula-reactivity/34-11-SUMMARY.md — the audit, with the measured numbers
- @.planning/phases/34-formula-reactivity/34-10-SUMMARY.md — `recalculateImportedRows`, and why ONE budget

**Gap A, measured:** a 46,055-row organization export produced **zero** `custom_*`
columns although **30,264** rows carried custom field values, because
`Papa.unparse(data, { header: true })` derives the header from the first object only.

**Gap B, read from source:** `resolveOrganization` (`actions.ts:162`) and the inline
person create in `importDeals` (`actions.ts:447`) insert real rows with native
attributes and are never handed to `recalculateImportedRows`.

## Tasks

### Task 1 — Gap A: union-of-keys CSV header (tdd="true")

<behavior>
Given rows where the FIRST row has no `custom_*` key and a LATER row does, the string
returned by `exportToCSV` contains that custom column in its header, and re-parsing the
string with `Papa.parse({header:true})` yields the later row's value in that column.
Native columns keep their exact current order and position. Custom columns follow, in a
deterministic sorted order. Covered for more than one entity export.
</behavior>

<implementation>
Add `deriveCsvColumns(rows)`: walk every row, collect non-`custom_` keys in first-seen
order, collect `custom_` keys into a set, sort the custom keys with a locale-independent
comparator, append. Pass the result to `Papa.unparse` as `columns`. Apply the same
derivation in `exportToPipedriveCSV`, which has the identical defect on the identical
data.
</implementation>

**Verify:** `npx vitest run src/lib/export/formatters.test.ts` — RED first (new tests
fail against the current `header: true` call), then GREEN.

### Task 2 — Gap B: recalculate the CSV importer's auto-created rows (tdd="true")

<behavior>
`importPeople` and `importDeals`, when they auto-create an organization or a person,
hand that row to `recalculateImportedRows`, spending from the SAME decrementing
allowance the primary batch uses — never a fresh `FORMULA_EVALUATION_BUDGET`.
</behavior>

<implementation>
Introduce `createCsvImportFormulaBudget()` in `actions.ts`, mirroring the Pipedrive
importer's run-level closure: it holds `remaining`, memoises one definitions read per
entity type, and pushes the T-34-25 shortfall sentence into the action's `warnings`.
Have `resolveOrganization` return the inserted row alongside `{ id, autoCreated }`;
collect auto-created org/person rows during the loop and recalculate them through the
same budget. Parents are recalculated BEFORE the primary batch, because a child formula
may reference a parent field (D-08) including a parent formula field (D-10).
</implementation>

**Verify:** `npx vitest run src/app/import/actions.test.ts` — RED first, then GREEN.
Tests are DB-free (`vi.mock("@/db")`); no import is run against the live database.

## Success Criteria

- RED tests prove both gaps before either fix
- Native column order unchanged; custom column order deterministic
- Both auto-create sites recalculate, sharing the existing budget, `cascade: false`
- `npm test`, `npx tsc --noEmit`, `npx eslint .` and `npm run build` all exit 0
- No existing test weakened, skipped or deleted; no database row mutated
