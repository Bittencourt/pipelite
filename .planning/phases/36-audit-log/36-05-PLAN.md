<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API key → `/api/v1` handler | Untrusted bearer token crosses here; `withApiAuth` is where authentication is proven and therefore the only place an `api_key` actor may be created. |
| trigger/schedule → workflow run graph | The run id exists only inside the executor; nothing outside it may assert one. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-36-01 | Spoofing | `withApiAuth` actor construction | mitigate | The actor is built only from `validateApiKey`'s return value. No header, query param or body field reaches `runWithActor`. Grep-asserted: `workflowRunId` appears zero times in `auth.ts`. |
| T-36-10 | Elevation of Privilege | a `/api/v1` route that skips `withApiAuth` | mitigate | The wrap sits after both reject paths, so skipping it loses authentication, rate limiting AND actor attribution simultaneously — the three failures are now coupled, which makes the omission detectable. |
| T-36-13 | Spoofing | forged `workflow_run_id` | mitigate | Written only from the executor's own `runId` inside `engine.ts`; `crm.ts` is grep-asserted to contain no wrap of its own. |
| T-36-SC | Tampering | npm/pip/cargo installs | accept | Zero packages added this phase. |
</threat_model>
