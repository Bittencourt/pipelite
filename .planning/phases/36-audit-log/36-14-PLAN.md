  <action>
    Create `src/app/admin/audit/retention-form.tsx` as `'use client'`. It owns the input state, the
    transition, the toast and the `AlertDialog`. **The `AlertDialog` and its trigger live entirely
    inside this module** — CFUI-01 is a hard boundary and the repo-wide gate fails the build if a
    non-client module renders a children-forwarding `asChild` component.

    Implement the full behaviour table, all seven rows:
    - Empty, non-integer, `<1` or `>3650` → Save DISABLED, with the always-visible helper text
      (`audit.retention.windowHelp`) stating the allowed range. No error colour and no message that
      appears and disappears — a rule the user can read before failing beats one that scolds after.
      `--destructive` is NOT used for the out-of-range state.
    - Value unchanged from saved → Save disabled.
    - Value raised, or set for the first time → saves directly; the button shows
      `Loader2 animate-spin` + `audit.retention.saving`, the `Input` goes `disabled`, and success
      fires `toast.success(audit.retention.saved)`.
    - Value lowered → opens the shorten `AlertDialog` FIRST. Title `audit.retention.shortenDialog.title`,
      description `...description` with the `{days}` value, cancel labelled
      `...cancel` ("Keep current window", not "Cancel"), confirm labelled `...confirm`
      ("Shorten retention window", not "Confirm"). Confirm runs the same save.
    - Dialog cancelled → the typed value stays in the `Input` so the operator can adjust rather than
      retype.
    - Save fails → the `Input` is re-enabled with the typed value RETAINED and
      `toast.error(audit.retention.saveFailed)` fires.
    - After a successful save the two readouts are NOT optimistically updated. The entry count and
      oldest entry only change when the pruner next runs, and pretending otherwise would be a lie
      told by the UI.

    The success toast is deliberate and is not an exception to Phase 35's "no success toast where the
    result is visible" rule — it is the mirror image of it. The number in the input looks identical
    before and after a successful save, so there is no visible result to serve as the confirmation.

    The dialog description says "the next time pruning runs", not "immediately", because the pruner
    is a daily `setTimeout` chain and nothing is deleted at save time. Copy must not describe a
    deletion the system does not perform when the button is pressed.

    Accessibility: the `Input` carries a visible `<Label htmlFor="retention-days">`; the helper text
    is associated with `aria-describedby`; the placeholder is never the label. `Input` is
    `max-w-32` with `type="number" inputMode="numeric" min={1} max={3650} step={1}`. Do not add
    per-component focus styling and do not set `outline: none` anywhere.

    The Save button is `variant="default"` — the only filled button this phase adds, and the page's
    primary visual anchor.
  </action>
