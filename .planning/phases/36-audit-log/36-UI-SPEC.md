# Phase 36 — UI Design Contract

> Visual and interaction contract for the audit timeline entry, the timeline filter toggle that
> governs it, the workflow-run linked-records section, and the retention admin control.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Sources:** `36-CONTEXT.md` (locked decisions), `.planning/REQUIREMENTS.md` (AUDIT-01..04),
`.planning/ROADMAP.md` (Phase 36 SC-1..SC-5), and — above all —
**`35-UI-SPEC.md`, the approved contract for the timeline this phase extends.**

**Inheritance is the governing rule of this document.** Phase 35 already declared the spacing scale,
the typography roles, the colour reserve, the copy rules and the accessibility contract for the
timeline card. This phase does **not** re-derive any of them. Where a section below repeats a Phase 35
value it is to make the executor's job single-file; where it *adds* something, the addition is called
out explicitly and justified. Nothing here contradicts `35-UI-SPEC.md`.

**No new dependencies. No new shadcn component. No new registry fetch.** Every primitive the four
surfaces need is already vendored in `src/components/ui/` — including `switch.tsx`, which the filter
toggle uses — and `components.json` declares `"registries": {}`.

## Spacing Scale

Identical to `35-UI-SPEC.md`. All multiples of 4.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | `gap-1` — icon↔label inside the actor-kind badge; `space-y-1` between field-diff rows; `mt-1` from the entry's line 1 to its field list |
| sm | 8px | `gap-2` — rail → content column (inherited skeleton), line-1 element gaps, field-label → value gap, stat label → value |
| md | 16px | `gap-4` — admin card grid; `mt-4` above the linked-records heading |
| lg | 24px | `px-6` / `py-6` Card padding (from the `Card` primitive); `space-y-6` on the admin page and the run detail page (both pre-existing) |
| xl | 32px | `w-8` rail column and `size-8` actor medallion — **byte-identical to the three Phase 35 renderers** |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used (no textarea on any surface in this phase) |

**Exceptions:** two, both inherited, neither introduced here.

1. **32px controls.** The "Show N more fields" disclosure renders at `size="xs"` (24px tall) — below
   the 44px touch guidance. Accepted for the same reason Phase 35 accepted 32px row actions: desktop-first
   CRM, the control is **always visible** (never a hover-only reveal), it is a progressive-disclosure
   affordance and not a primary flow, and every primary control in this phase (the retention Input, its
   Save button, the AlertDialog buttons) is ≥36px.
2. **The run detail page's `container py-6 space-y-6` shell** is pre-existing and untouched.

No other exception. Every value in the four surfaces is one of the seven declared tokens.

## Typography

Four sizes, two declared weights, two declared weight exceptions.

| Role | Size | Weight | Line Height | Tailwind | Applies to |
|------|------|--------|-------------|----------|-----------|
| Display | 30px | 700 *(exception 2)* | 1.2 | `text-3xl font-bold` | The `/admin/audit` page `<h1>` only |
| Heading | 16px | 600 | 1.25 | `text-base font-semibold leading-tight` | Retention card titles; the "Records changed" heading on the run page (`text-base`, not the page's `text-2xl`) |
| Label | 14px | 600 | 1.25 | `text-sm leading-tight font-semibold` | Audit entry actor name; linked-record title/link; retention stat values |
| Body | 14px | 400 | 1.5 | `text-sm leading-normal` | The entry predicate sentence, every field-diff **value**, retention helper text |
| Meta | 12px | 400 | 1.33 | `text-xs` | Timestamps, actor-kind badge text, field-diff **labels**, stat labels, disclosure button label, field counts |

**Declared weights: 400 (normal) and 600 (semibold).**

**Weight exception 1 (inherited from Phase 35):** `button.tsx` hardcodes `font-medium` (500) in its base
class, so every button label in this phase renders at 500. This phase does not patch a shared primitive
to satisfy its own contract.

**Weight exception 2 — consistency with the existing admin pages, NOT a new choice.** The
`/admin/audit` page `<h1>` uses `text-3xl font-bold` (700). This phase is not deciding anything about
headings; it is joining a decision the admin shell already made. Every existing admin page —
`admin/page.tsx:51`, users, fields, pipelines, webhooks — renders its `<h1>` with exactly that class,
so a sixth admin page whose title alone sat at 600 would read as a rendering bug rather than as
restraint. The exception copies an existing class string rather than inventing a value, and it is
confined to one element on one page.

**Two exceptions is the ceiling, and neither is this phase's invention.** Both — 500 from
`button.tsx`, 700 from the admin page shell — come from shared code this phase declines to patch,
which is the posture `35-UI-SPEC.md` already took toward `button.tsx`. A later phase citing this
document as precedent should read it as "inherit an existing exception, never mint a new one", not as
permission to stack a third.

**Deliberately NOT used: `text-2xl font-bold`.** The admin dashboard renders its counts as
`text-2xl font-bold` stat numbers. The retention page's two readouts (entry count, oldest entry) are
**not** KPIs — they are the cost of a setting, shown next to the setting. They render at the declared
Label role (14/600) with a Meta label (12/400 muted), which keeps this phase inside its declared scale
instead of borrowing a fifth size for two numbers.

**Field-diff type pairing.** The field **label** is 12/400 muted and the field **values** are 14/400
foreground, aligned on a shared baseline (`items-baseline`). Label and value are therefore distinguished
by *both* size and colour, so the row is readable without punctuation — which matters, because a
label/value separator like `:` is locale-dependent and would have to become a translated string.

## Color

| Role | Token | Value (light) | Usage |
|------|-------|---------------|-------|
| Dominant (60%) | `--background` / `--card` | `oklch(1 0 0)` | Page background; the timeline card; the retention cards; the linked-records panel fill |
| Secondary (30%) | `--muted` / `--border` | `oklch(0.97 0 0)` / `oklch(0.922 0 0)` | The `size-8` actor medallion (`bg-muted`), the actor-kind badge (`variant="secondary"`), the linked-records panel border and dividers (`rounded-md border divide-y`), every field label, every `from` value, every timestamp (`text-muted-foreground`) |
| Accent (10%) | `--primary` | `oklch(0.205 0 0)` | See reserved list |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` | See reserved list |

**Accent (`--primary`) reserved for exactly four things in this phase — nothing else:**

1. **Save retention window** — `Button variant="default"`, the only filled button this phase adds.
2. **Links from an entry or row to a related record**, `text-primary hover:underline`: the workflow-run
   actor name → its run detail page, and each linked-record title → its detail page. This is Phase 35's
   sanctioned use #2, unchanged.
3. **The audit filter toggle's track when it is ON.** `switch.tsx` hardcodes
   `data-[state=checked]:bg-primary`, so an enabled toggle is accent-filled. This is a **fourth**
   sanctioned accent inside the timeline card, where Phase 35 declared three, and it is declared here
   rather than allowed to appear undeclared. It is admissible because the filled state is 32×18px —
   roughly a fortieth of the "Add note" button's area — and because it is **absent in the default
   state**, so the card as it first paints carries exactly Phase 35's three accents and no more.
   Phase 35's primary visual anchor (the filled "Add note" button, then the newest entry) is unchanged.
4. The keyboard focus outline, already global (`globals.css:154` `2px solid var(--primary)`).
5. Nothing else.

Explicitly **not** accent: the "Show N more fields" disclosure (`variant="ghost"` + `text-muted-foreground`
— it is not a link and must not read as one), the `from`→`to` arrow, actor-kind badges, action badges,
rail medallions, field labels, the entry count.

**Destructive (`--destructive`) reserved for exactly two things:**

1. The `AlertDialogAction` confirm button in the **shorten-retention** dialog.
2. Sonner `toast.error(...)`, owned by the `sonner.tsx` primitive.

Never used for the number Input's out-of-range state (see § Interaction Contract — the helper text is
always present and neutral, and the disabled Save button is the message), and never for a `deleted`
audit entry or a deleted linked record.

**Zero new hues. No add/remove semantics.**

This is the single most important colour decision in the phase and it is a prohibition: a field diff
**must not** render `from` in red and `to` in green. Two reasons, either sufficient:

- It would introduce hues outside the token set. Phase 35 tolerated two *inherited* pastel maps
  (stage colours, activity types) and explicitly refused to "add new instances of that problem".
- It would lie. A field changing is neither a loss nor a gain. Green/red diff colouring imports
  version-control semantics into a record of business facts, and it turns every routine owner
  reassignment into something that reads like an error.

The `from` value is distinguished from the `to` value by **muted foreground vs. foreground plus an
explicit arrow**, which carries the direction without carrying a judgement.

**Forbidden:** any hardcoded hex, `bg-white`, `text-black`, `text-red-*`, `text-green-*`,
`bg-red-*`, `bg-green-*`, or any colour outside the token set anywhere in the four surfaces.

## Surface 1 — The Audit Timeline Entry

### Data contract (what the renderer receives)

The renderer is dumb by design: every DB-dependent decision (resolving `owner_id` to a person, reading a
custom field's user-authored name, counting files) happens in the audit timeline **source**, and every
locale-dependent decision (date, number and list formatting) happens in the **client component** via
`useFormatter`. That split is what this shape encodes.

```ts
// src/lib/timeline/types.ts — appended to the existing union
export type TimelineEntryKind = 'note' | 'activity' | 'stage_change' | 'audit'

export type AuditActorKind = 'user' | 'workflow_run' | 'api_key' | 'import' | 'system'
export type AuditAction = 'created' | 'updated' | 'deleted'

/** A single displayable value. `empty` is a first-class case, never an empty string. */
export type AuditValue =
  | { type: 'empty' }
  | { type: 'text'; value: string }
  | { type: 'number'; value: number }
  | { type: 'boolean'; value: boolean }
  | { type: 'date'; iso: string; withTime: boolean }
  | { type: 'list'; items: string[] }
  /** A resolved foreign key. `label: null` → the referenced row is gone. */
  | { type: 'reference'; label: string | null }
  | { type: 'files'; count: number }
  /** Already-compacted JSON for anything the cases above do not cover. */
  | { type: 'json'; value: string }

export interface AuditFieldChange {
  /** React key + ordering identity: the column name, or `custom:<definitionId>`. */
  field: string
  /** Already resolved. Native columns are localized by the source; custom fields carry
   *  `customFieldDefinitions.name` VERBATIM — user-authored text is never translated. */
  label: string
  /** `null` on a `created` entry: there is no before. */
  from: AuditValue | null
  to: AuditValue
}

export interface AuditTimelineEntry extends TimelineEntryBase {
  kind: 'audit'
  action: AuditAction
  entityType: EntityType
  actorKind: AuditActorKind
  /** Only when actorKind === 'user'; null when that user row is gone. */
  actor: { id: string; name: string | null; email: string } | null
  /** Only when actorKind === 'workflow_run' and the workflow still exists. */
  workflowRun: { runId: string; workflowId: string; workflowName: string } | null
  /** Only when actorKind === 'api_key'; `apiKeys.name`. */
  apiKeyName: string | null
  /** Empty on `deleted`. May be empty on `updated` — see the defensive state below. */
  changes: AuditFieldChange[]
}
```

**Field ordering inside `changes` is fixed, not incidental:** native columns first in the order of the
`AUDIT_FIELD_LABELS` map below, then custom fields ascending by `customFieldDefinitions.position`, ties
broken by `label.localeCompare`. This matters because only the first three are shown by default — an
unstable order would show a different three on every render.

### Row skeleton — identical to the three Phase 35 renderers

Non-negotiable. The merged feed only reads as ONE list because all four kinds share this grid
(`35-UI-SPEC.md` § Layout & Composition; enforced in prose by the module headers of
`activity-entry.tsx` and `stage-change-entry.tsx`).

```
<div class="flex gap-2">
  <div class="w-8 shrink-0">            ← rail: Avatar size-8, or bg-muted size-8 rounded-full circle
  <div class="min-w-0 flex-1">          ← content
    line 1: flex flex-wrap items-center gap-2
    line 2: mt-1  → the field list (a <dl>)
    line 3: mt-1  → the disclosure button, only when changes.length > 3
```

No third column. **The audit entry has no row actions** — an audit entry is a fact about the past, the
same argument `stage-change-entry.tsx` makes for itself. Nothing about it is editable or deletable from
the timeline, in this phase or any other.

### The rail carries the ACTOR KIND

Phase 35's rail answers "who or what": an author avatar for a note, a type icon for an activity, an
`ArrowRight` for a stage change. The audit entry continues that, and it is also how SC-3 is satisfied at
a glance:

| `actorKind` | Rail | Rationale |
|-------------|------|-----------|
| `user` | `Avatar size-8` with `AvatarFallback` initials, via the same `getInitials` helper `note-entry.tsx` uses | A human change should look like a human change — identical to a note's rail |
| `workflow_run` | `bg-muted size-8 rounded-full` circle containing `Workflow` `h-4 w-4 text-muted-foreground` | `Workflow` is already the nav icon for workflows (`nav-header.tsx:9`) |
| `api_key` | same circle, `Key` icon | `Key` already means API key in `user-menu.tsx` and `admin-sidebar.tsx` |
| `import` | same circle, `Download` icon | Data arriving from outside |
| `system` | same circle, `Cog` icon | Not `Bot` — nothing here is an AI, and the icon should not suggest one |

All rail icons are `aria-hidden="true"`, exactly as in the three sibling renderers.

**An icon alone never carries the actor kind.** Because the rail glyphs are `aria-hidden`, every
non-`user` entry ALSO renders a `Badge variant="secondary"` on line 1 carrying the icon plus the
translated kind label. Screen-reader users and colour-blind users get the same information sighted
users get, and SC-3 is satisfied in text, not just in pixels.

### Line 1 — attribution

`flex flex-wrap items-center gap-2`, in this order:

1. **Actor name**, `text-sm leading-tight font-semibold` (the Label role, matching notes and stage
   changes). The name resolves in this order, and the *fallback is the kind label, never a guess*:

   | `actorKind` | Name rendered |
   |-------------|---------------|
   | `user` | `actor.name ?? actor.email`; when `actor` is null → `audit.unknownActor` ("Unknown user") |
   | `workflow_run` | `workflowRun.workflowName`, wrapped in a `Link` to `/workflows/{workflowId}/runs/{runId}` with `text-primary hover:underline` (sanctioned accent use). Workflow deleted → the plain kind label, no link |
   | `api_key` | `apiKeyName`; null → the kind label |
   | `import` / `system` | the kind label |

   This mirrors the locked backend rule that an unknown actor records `system` and **never** falls back
   to the event's `userId`: a confidently wrong name in an audit log is worse than an honest "unknown",
   and the UI must not re-introduce the guess the data layer refused to make.

2. **Predicate**, `text-sm leading-normal`: one of the twelve `audit.entry.{action}.{entityType}`
   strings ("updated this deal", "created this person", …). Per-entity messages, not a `{entity}`
   placeholder — Spanish and Portuguese inflect the demonstrative with the noun's gender
   ("este trato" vs "esta actividad"), and a placeholder would produce broken grammar in two of the
   three shipped locales.

3. **`<time dateTime={iso} title={absolute}>`** wrapping `<RelativeTime />`, `text-muted-foreground
   text-xs` — byte-identical to the three sibling renderers, including the `format.dateTime` options
   (`year: numeric, month: long, day: numeric, hour: numeric, minute: numeric`).

4. **Actor-kind badge**, only when `actorKind !== 'user'`:
   `<Badge variant="secondary" className="gap-1 font-normal">` + the 12px icon + the kind label.
   `font-normal` matches how Phase 35's badges are rendered.

### Line 2 — the field diff

A `<dl className="mt-1 space-y-1">`. One `<div className="flex flex-wrap items-baseline gap-2">` per
change:

```
<dt class="text-muted-foreground text-xs">{label}</dt>
<dd class="text-sm leading-normal min-w-0 break-words">
  {from}  <span class="sr-only">{audit.value.changedTo}</span>
  <ArrowRight class="inline h-3 w-3 text-muted-foreground align-middle" aria-hidden="true" />
  {to}
</dd>
```

- `from` renders `text-muted-foreground`, `to` renders at default foreground. That contrast **is** the
  before/after signal (see § Color for why it is not red/green).
- **On a `created` entry** `from` is null: the arrow and the `sr-only` connector are omitted and only the
  `to` value renders. A create is an initial state, not a transition, and drawing an arrow from nothing
  would be a fiction.
- **On a `deleted` entry** `changes` is empty: the `<dl>` is not rendered at all. Line 1 alone
  ("Ana deleted this deal") is the entry. Restoring is Phase 37; the copy here promises nothing.
- `break-words` on the `<dd>` so a 200-character unbroken URL cannot blow out the card — the same
  defence `note-entry.tsx` applies to note bodies.

### Value rendering rules (exhaustive, and prescriptive)

| `AuditValue.type` | Rendered as |
|-------------------|-------------|
| `empty` | `audit.value.empty` — the word **"empty"** — in `italic text-muted-foreground`. Not `null`, not `—`. `—` is indistinguishable from a real em-dash a user typed, and `null` is not a word |
| `text` | The string, after normalization + truncation (below) |
| `number` | `format.number(value)` — locale grouping, **no currency symbol**. The field label ("Value") supplies the meaning; the deal's currency lives on its organization and inventing one here would be a guess |
| `boolean` | `audit.value.yes` / `audit.value.no`. Never the literals `true` / `false` |
| `date` | `format.dateTime(new Date(iso), { year:'numeric', month:'short', day:'numeric' })`, plus `{ hour:'numeric', minute:'2-digit' }` when `withTime` (Due date, Completed at). Not `RelativeTime` — a diff needs the value that was stored, not how long ago it was |
| `list` | `format.list(items)`, then truncated as one string |
| `reference` | `label`, or — when `label` is null — `audit.value.unavailable` ("no longer available") in `italic text-muted-foreground`. An id is never shown to a user |
| `files` | `audit.value.files` — "{n} files" (ICU plural). A file array's JSON is meaningless in a timeline row |
| `json` | The compacted JSON string, normalized + truncated. **No JSON viewer.** `json-viewer.tsx` exists on the run detail page and belongs there; a collapsible code block inside a timeline row would wreck the shared skeleton |

**Normalization, then truncation — in that order, for every string-producing case:**

1. Collapse every run of whitespace (including newlines and tabs) to a single space, then trim. A note
   pasted into a text field would otherwise contribute forty blank-ish lines to a history row.
2. If the result exceeds **120 characters**, cut to 119 and append `…` (U+2026, one character — not
   three dots).
3. The truncated element carries `title={full.slice(0, 1000)}`. A native `title`, **not** a Radix
   Tooltip: `tooltip.tsx` is not vendored and `components.json` declares an empty `registries` object,
   so pulling one would contradict § Registry Safety. This is exactly the reasoning `note-entry.tsx`
   already records for the "Migrated" badge. The `title` itself is capped at 1,000 characters because a
   5,000-character tooltip is not a tooltip.

120 characters is roughly two lines in the content column at 14px, which keeps a three-field entry the
same visual weight as a note entry.

### Progressive disclosure

**Three field rows render by default.** Three is the number at which an audit entry occupies the same
vertical space as a typical note, which is the whole point: this is a fourth voice in an existing
conversation and it must not shout.

When `changes.length > 3`:

```
<Button variant="ghost" size="xs"
        className="text-muted-foreground mt-1"
        aria-expanded={expanded} aria-controls={`audit-fields-${entry.id}`}>
  <ChevronDown|ChevronUp class="h-3 w-3" aria-hidden="true" />
  {expanded ? t('showFewerFields') : t('showMoreFields', { count: changes.length - 3 })}
</Button>
```

- The `<dl>` carries `id={`audit-fields-${entry.id}`}`.
- **Plain `useState` + conditional render — deliberately NOT the vendored `Collapsible`.** Two
  reasons, and only these two: there is no animation requirement, and a conditional render is one
  line. The `step-detail.tsx` precedent exists for a panel with an animated body and a nested error
  block; this is a three-row list.
  **CFUI-01 is NOT a reason here and must not be cited as one.** That gate governs a *server*
  component passing a React element across the RSC boundary into a client `asChild` slot.
  `audit-entry.tsx` is `'use client'` end to end and is reached through Phase 35's client
  `TimelineList` subtree, so no server→client crossing occurs and the gate would not engage even if
  `Collapsible` were used. Nor does the primitive require `asChild`: `step-detail.tsx:70` passes it
  and `step-detail.tsx:94` does not, in the same file. The decision above stands on its own two
  reasons — it does not need a boundary rule that does not apply, and a wrong reason quoted as
  precedent by a later phase is worse than no reason.
- State is per entry and resets on unmount. Nothing is persisted.

### Defensive state

An `updated` entry whose `changes` array is empty (every changed field was excluded — a formula-only
recalculation that slipped through) renders line 1 plus a single muted line:
`audit.entry.noVisibleChanges` — "No field-level detail was recorded." Such rows should not be created
by the subscriber, but a renderer that silently draws an empty `<dl>` would make that bug invisible.

### The dispatcher edit

`timeline-entry.tsx` gains exactly one branch:

```tsx
case "audit":
  return <AuditEntry entry={entry} />
```

The file's `never` check is the reason this is safe, and it is **not to be defeated**: adding `'audit'`
to `TimelineEntryKind` fails `tsc` in that file until the branch exists. Phase 35 wrote that guard
specifically for this phase (see its module header). Do not add a `default: return null` that swallows
the union, and do not widen the props — `AuditEntry` takes `entry` only, because an audit entry has no
row actions and therefore needs neither `canManage` nor the two callbacks.

### Consequences for the Phase 35 empty state — declared, not fixed

Every record **created after the deploy** carries at least one audit entry. Had audit entries always
rendered, `notes.empty.*` would have become unreachable for those records — but surface 4 hides them by
default, so the opposite is true: **Phase 35's empty state stays fully reachable, and a new third
variant is required for the case where the list is empty only because the filter is closed.** That
variant is specified in § Surface 4 → The empty-state trap, and it is the single most likely way this
feature misleads someone if it is skipped.

All three variants coexist:

| Situation | Variant |
|-----------|---------|
| No history of any kind, pre-audit record | Phase 35's `notes.empty.*` / `notes.emptyNotes.*`, unchanged |
| No history of any kind, post-audit record with the toggle ON | the same Phase 35 copy, still correct |
| No notes / activities / stage changes, but audit entries exist behind the closed toggle | the new `audit.filter.emptyHidden.*` variant |

Phase 35's copy and component are therefore **unchanged**; `empty-timeline.tsx` is extended with a
third variant, not replaced. This phase must not "simplify" it on the theory that any branch is now
dead code. None of them is.

### Density — measured, and the reason surface 4 exists

**This section previously argued that no filter was needed. That was written before the phase research
measured the feed, and it was wrong.** `36-CONTEXT.md` § Post-Research Addendum (decided 2026-08-16)
records the measurement and the decision it forced:

> **15 of the top 21 merged entries would be audit rows.**

Audit applies to all four entity types, so it does not merely add to the feed — it *takes it over*, and
it buries the human-written notes Phase 35 exists to surface. Two alternatives were considered and
rejected by the user: interleaving everything regardless, and grouping consecutive audit rows into a
summary. The decision taken is **a filter toggle with audit entries OFF by default**, and it is
authoritative over anything this document said before it.

The structural mitigations still matter, because they govern what the feed looks like once the toggle
is ON: one entry per event rather than per field, three fields inline, formula noise excluded upstream,
no colour, no toast, no row actions, and the smallest type in the card for labels and counts. The
toggle is what keeps the default view readable; those choices are what keep the opened view readable.

## Surface 4 — The Audit Filter Toggle

Locked by `36-CONTEXT.md` § Post-Research Addendum: *"The timeline gets a filter toggle, with audit
entries OFF by default. Notes, activities and stage changes render as today; audit entries appear when
the toggle is on."*

### Placement: the card header, in the `CardAction` slot

```
<CardHeader>                       ← already `grid-cols-[1fr_auto]` in card.tsx:23
  <CardTitle>  Timeline (12)       ← 1fr column, unchanged from Phase 35
  <CardAction> [Show field changes (47)] ( ●)   ← auto column, NEW
</CardHeader>
```

`CardAction` is already exported by `card.tsx` (line 89) and `CardHeader` already lays out
`grid-cols-[1fr_auto]` for it, so this needs **no new layout CSS and no change to the card's
structure** — it fills a slot that has been sitting empty.

The header is the right home because the toggle scopes the *whole card*, and it is where the count it
has to stay consistent with already lives. Placing it inside `CardContent` above the `<ol>` was
considered and rejected: it would push the newest entry down, diluting Phase 35's declared anchor, and
it would separate the control from the count it changes.

**Layout:** `<CardAction className="flex items-center gap-2">` holding
`<Label htmlFor="timeline-audit-filter" className="text-muted-foreground text-xs">` (the label plus a
muted `({auditTotal})`, matching how the header already renders its own count) and
`<Switch id="timeline-audit-filter" size="sm" />`. Both are existing primitives; `switch.tsx` is
vendored and is not currently used anywhere in the timeline.

**Responsive:** `CardHeader`'s grid keeps the title and the action on one line down to 320px because
the label is 12px and the switch is 24px wide. If the two ever collide, the label truncates — the
switch never wraps below the title, because a control that moves is a control the user has to re-find.

### State lives in the URL, not in React

**`?changes=1` on the record's detail page.** Absent or any other value → OFF.

This is the load-bearing decision of surface 4, and it is what makes everything else fall out
correctly:

| Consequence | Why it matters |
|-------------|----------------|
| The header count, the `<ol>` contents, `hasMore` and the cursor are all computed by the **same server render** from the same flag | They cannot disagree. There is no state that lives in two places |
| First paint stays server-rendered | Phase 35's "no skeleton, no spinner on initial load" survives, in both toggle states |
| Toggling re-runs the page's RSC render | Pagination resets to page 1 for free — see the cursor trap below |
| The choice is shareable, bookmarkable and survives reload and back/forward | "Look at this deal's history" is a link someone can send |

**Rejected alternatives**, recorded so they are not re-litigated:

- *React state in `TimelineList`* — the count lives in the server-rendered `CardTitle`, so the header
  would go stale the moment the toggle moved. Fixing that means either hoisting the card header into
  the client subtree (churning Phase 35's approved server/client split and its degraded-state branch)
  or duplicating the count. Both are worse than a search param.
- *`localStorage` or a user preference row* — see persistence below.

**Persistence: per record, per URL. It does NOT follow the user.** Navigating to a different record
starts OFF again. The reason is the same measurement that created the toggle: a user who once opened
changes on one deal would otherwise get an audit-dominated timeline on *every* record forever, which is
precisely the failure the default exists to prevent. A reading choice made about one record is not a
statement about all records. This also avoids a new persistence layer, an `app_settings` key, and the
`localStorage` hydration mismatch that would follow from reading it during render.

### What `Timeline (N)` counts

**N is the number of entries the list can actually show under the current filter.**

| Toggle | Header | List |
|--------|--------|------|
| OFF (default) | `Timeline (12)` | 12 notes / activities / stage changes |
| ON | `Timeline (59)` | those 12 plus 47 audit entries |

The count moves when the toggle moves. The alternative — a fixed count meaning "everything that ever
happened" — was rejected because with the toggle off it would render `Timeline (59)` above a list the
user can exhaust at 12 by pressing Load more until it disappears. A header number that does not match
what the header is on top of is a defect the user can see and cannot explain.

The hidden volume is not lost: it is carried by the toggle's own count, `({47})`, which always reports
the audit total regardless of toggle state. Two numbers, each with one fixed meaning, neither ever
stale.

This requires `countTimeline` to be scoped by the same flag as the query — see the consumption-path
note below.

### The cursor trap (correctness, not polish)

**Toggling MUST discard already-loaded pages and restart at page 1.** Merging is not an option.

The keyset predicate is applied *per branch* (`sources.ts`, each `branch()`), so a cursor minted with
audit OFF, replayed with audit ON, would return audit entries older than the cursor and **silently omit
every audit entry newer than it** — the ones inside the window the user has already scrolled past.
`sources.ts` states the standard for this class of bug in its own words: *"On an audit surface,
omitting history is the worst failure available."*

The URL-param design gives this for free: toggling is a navigation, the RSC page re-renders, and
`TimelineList` receives a fresh `initialEntries` / `initialCursor` for the new scope. **`Load more`
must carry the current flag** to the server action so page 2 is drawn from the same source set as
page 1.

### The empty-state trap

A record whose *only* history is audit entries shows an empty list with the toggle off. Rendering
Phase 35's "Nothing has happened yet" there would be a **lie told by the UI about its own data**, and
it is the single most likely way this feature misleads someone.

Three cases, and the third is new:

| Filtered list | `auditTotal` | Rendered |
|---------------|--------------|----------|
| empty | 0 | Phase 35's existing empty state, **unchanged** (`notes.empty.*` / `notes.emptyNotes.*`) |
| non-empty | any | the list |
| **empty** | **> 0** | **the new hidden-history empty state below** |

```
heading  audit.filter.emptyHidden.heading
         "No notes, activities or stage changes yet"
body     audit.filter.emptyHidden.body
         "47 field changes are hidden on this record. Turn on Show field changes to see them."
```

Same visual treatment as `empty-timeline.tsx` (heading at Label 14/600, body at Body 14/400 muted) —
this is a third variant of an existing component, not a new component. The body **names the count and
names the control**, so the way out is on screen and quantified. It must not say "no history".

### Consumption-path note for the planner (this is not display-only)

`TIMELINE_SOURCES` is consumed **unconditionally** today. `assemble.ts:43-45`:

```ts
function applicableSources(entityType: EntityType): TimelineSource[] {
  return TIMELINE_SOURCES.filter((source) => source.appliesTo(entityType))
}
```

`appliesTo(entityType)` is the *only* filter dimension that exists. The toggle adds a second one, so
`applicableSources`, `buildTimelineQuery`, `assembleTimeline` and `countTimeline` each have to accept
the kind scope, and `record-timeline.tsx` has to thread it in from `searchParams` — which means the
four detail pages pass `searchParams` through. Nothing in the current code filters sources.

Two properties worth designing to, both consequences of the default being OFF:

1. **The default path stays byte-identical to Phase 35's measured plan.** With audit off,
   organization / person / activity timelines still have exactly one applicable source, so
   `buildTimelineQuery`'s "one applicable source means no union at all" branch still fires and the
   `assemble.test.ts:232` assertion (no `UNION ALL` for those three) still holds **in the default
   state**. It is falsified only with the toggle on. That is a far cheaper test migration than the
   research's estimate assumed, and the planner should scope the assertion by flag rather than delete
   it.
2. **`countTimeline` must return both numbers in one pass** — the filtered total for the header and the
   audit total for the toggle label — because both are needed on every render and each `countBranch` is
   an index-only count.

## Surface 2 — Workflow Run → Records Changed

**Route:** `/workflows/[id]/runs/[runId]`. **Placement:** the last block in the page's existing
`container py-6 space-y-6` stack, **after `<RunStepList />`**. Reading order on that page is cause →
effect: the header says what ran, the step list says what it did, and this section says what it
changed. Putting effects above causes would invert it.

### Data contract

```ts
interface RunChangedRecord {
  entityType: EntityType
  entityId: string
  /** Best-known title at read time; null when the row is gone. */
  title: string | null
  /** The most significant action this run took on this record: deleted > created > updated. */
  action: AuditAction
  /** Distinct fields this run changed on this record. */
  fieldCount: number
  /** The latest audit instant for this record within this run. */
  occurredAt: Date
  /** Currently soft-deleted → not linkable. */
  deleted: boolean
}
```

**One row per distinct record, not per audit entry.** A workflow that updates the same deal in three
steps produces three audit rows and exactly one row here, with `fieldCount` covering the union. This is
what makes "links to **every** record that run mutated" (SC-2) both true and bounded — the list length
is the number of records touched, which is the number the operator is actually asking about. There is
no cap and no pagination.

### Anatomy

Reuses the `RunStepList` idiom verbatim so the page keeps one visual language:

```
<section>
  <h2 class="text-base font-semibold leading-tight mb-4">    {t('run.heading')} ({count})
  <ul role="list" class="rounded-md border divide-y">
    <li class="flex items-center justify-between gap-2 px-4 py-3">
      left:  [entity icon h-4 w-4 text-muted-foreground] [title]
      right: [action badge] [field count, text-xs muted] [<time> RelativeTime, text-xs muted]
```

**Entity icons are the app's own nav vocabulary** (`nav-header.tsx:9`), so zero new symbols enter the
product: organization → `Building2`, person → `Users`, deal → `Kanban`, activity → `CheckCircle2`.
All `aria-hidden="true"`.

| Element | Treatment |
|---------|-----------|
| Title, record live | `<Link href={/{entityType}s/{entityId}}>` at `text-sm leading-tight font-semibold text-primary hover:underline` — sanctioned accent use #2 |
| Title, record deleted | Plain `<span class="text-sm leading-tight font-semibold text-muted-foreground">` — **not a link**, because the detail page 404s. A dead link is worse than an honest dead end |
| Title, unknown (`title === null`) | `audit.run.untitledRecord` — "Untitled record" — muted |
| Action badge | `Badge variant="outline"` for `created` / `updated`; `Badge variant="secondary"` for `deleted`. **Never `variant="destructive"`** — a completed deletion is a fact, not a warning, and destructive is reserved |
| Field count | `audit.run.fieldCount` ICU plural ("3 fields"), `text-xs text-muted-foreground`. Omitted entirely when `action === 'deleted'` (a tombstone has no field count) |
| Timestamp | `<time dateTime title>` + `RelativeTime`, `text-xs text-muted-foreground` — same treatment as everywhere else in the product |

**Primary visual anchor:** the column of record titles down the left edge. This panel has no
accent-filled element by its own colour table — the only `--primary` in it is the title links — so the
anchor is the 14/600 linked titles, which are the strongest contrast in the block. Everything to the
right (action badge, field count, timestamp) is 12px muted or a `secondary`/`outline` badge and is
deliberately subordinate. The operator's question is "which records", so the records carry the eye.

**Ordering:** `occurredAt` descending — newest first, matching the timeline and the runs list.

**Responsive:** the row is `flex … justify-between` with `flex-wrap` on the right-hand cluster. Below
`sm` the metadata wraps under the title; nothing truncates and nothing scrolls horizontally at 320px.

### States

| State | Rendering |
|-------|-----------|
| Has records | The list above, count in the heading |
| Empty | `rounded-md border p-6 text-center text-sm text-muted-foreground` containing `audit.run.empty` — **the exact treatment `RunStepList` already uses for "No execution steps recorded"** |
| Query failed | The same panel, containing `audit.run.unavailable`. Server-rendered inside a route with no `error.tsx` anywhere under `src/app/`, so an unguarded throw takes the whole run page down — the section degrades to a message instead, exactly as `record-timeline.tsx` does |

### i18n — a deliberate, declared inconsistency

The `/workflows` tree contains **zero** `next-intl` call sites today; its strings ("Back to Runs",
"Duration:") are English literals. The new section nonetheless uses `getTranslations('audit')` and adds
its keys to all three locale files.

Chosen knowingly: `locale-parity.test.ts` (Phase 35) makes translated keys the enforced default, three
locales ship, and writing new untranslated English in 2026 to match legacy debt propagates the debt.
The result is one translated section on an otherwise-English page for `es-ES` and `pt-BR` users. That is
a visible seam and it is the right trade — the seam shrinks as the workflows tree is migrated, whereas
new English literals would have to be found and rewritten later. **Do not "fix" the inconsistency by
translating the rest of the run page in this phase**; that is unrelated scope.

`Input` is `max-w-32` (128px) — a day count is at most four digits, and a full-width number input
invites the reader to expect a full-width amount of data.

**No "keep entries forever" affordance.** The pruner's unset state exists as a *fail-safe* (locked in
`36-CONTEXT.md`: "does nothing at all when retention is unset or unparseable"), not as a product option.

undercut it. The unset state is still rendered honestly when it occurs — `retention.notSet`,
"Not set — entries are never pruned." — so an operator who lands on a fresh install understands the
state they are in and what saving a number will do.

**Primary visual anchor:** the filled **Save retention window** button, with the number `Input`
immediately above it. That button is the only `--primary`-filled element on the page. The page has
exactly one thing to do, and the eye should land on the field and then on the control that commits it.
The cost card below is 14/600 values on 12/400 muted labels with no fill, no border accent and no
icon, so it reads as evidence for the decision rather than competing with it.

### Split

`page.tsx` is a **server component**: it reads `AuditRetentionSettings` and passes plain serializable
values down. `retention-form.tsx` is `'use client'` and owns the input state, the transition, the toast,
and the `AlertDialog`. **The `AlertDialog` and its trigger live entirely inside the client module** —
CFUI-01 is a hard boundary and the repo-wide gate from `44-06` fails the build if a non-client module
renders a children-forwarding `asChild` component. No React element and no function crosses the
boundary; the props are `number | null`, `number`, and `string | null` (the oldest instant as an ISO
string).

The stat card may stay in `page.tsx` (it renders no `asChild` component), but the two `Card`s must not
be interleaved with client state.

### Destructive confirmation

One destructive action exists in this phase: **shortening the retention window**, which schedules the
permanent deletion of audit rows.

| Field | Copy / treatment |
|-------|------------------|
| Trigger | The **Save retention window** button, but only when the submitted value is **lower** than the saved value. Raising or leaving the window unchanged saves immediately with no dialog — nothing is destroyed |
| Dialog | `AlertDialog` (focus trap, ESC, focus restoration all from Radix), rendered from the client module |
| Title | Shorten retention window? |
| Description | Entries older than {days} days will be permanently deleted the next time pruning runs. This can't be undone. |
| Cancel | **Keep current window** — not "Cancel" |
| Confirm | **Shorten retention window**, `bg-destructive text-destructive-foreground hover:bg-destructive/90`, with `Loader2 animate-spin` while in flight — the exact treatment `delete-note-dialog.tsx` uses |

The description says "the next time pruning runs", not "immediately", because the pruner is a daily
`setTimeout` chain and nothing is deleted at save time. Copy must not describe a deletion the system
does not perform when the button is pressed.

### Copy rules for this phase (inherited from `35-UI-SPEC.md`, restated because they bind here too)

- **No generic CTA labels.** Every button names its object: "Save retention window", "Shorten retention
  window", "Keep current window", "Show fewer fields". A bare "Save", "Cancel", "Confirm", "OK" or
  "Apply" is forbidden in these surfaces, including inside the confirmation dialog.
- No exclamation marks. No "Oops". No standalone "Something went wrong" — every error names the failed
  action and the next step.
- Every error states what happened **and** what to do next.
- **No success toast where the result is visible.** Saving the retention window *does* get
  `toast.success(audit.retention.saved)`, because the number in the input looks identical before and
  after a successful save — there is no visible result to serve as the confirmation. This is the mirror
  image of Phase 35's rule ("the note appearing IS the confirmation"), not an exception to it.
- Audit copy is **factual, never editorial**. "updated this deal", not "made changes to this deal";
  "empty", not "nothing"; "no longer available", not "missing". A record of what happened has no
  opinion about it.

## Interaction Contract

**Audit entry**

| Trigger | Behavior |
|---------|----------|
| Entry with ≤3 changes | Renders fully; no disclosure button |
| Entry with >3 changes | First 3 render; ghost disclosure shows the remainder count |
| Disclosure click | Toggles the full `<dl>`; `aria-expanded` flips; the button label swaps to "Show fewer fields"; no animation, no scroll jump (the list grows downward, below the fold-anchor) |
| Long value | Truncated at 120 chars with `…`; full value (≤1,000 chars) in a native `title` |
| Workflow-run actor click | Navigates to `/workflows/{workflowId}/runs/{runId}` |
| Anything else | **Nothing.** No hover reveal, no context menu, no row actions, no edit, no delete |

**Audit filter toggle**

| Trigger | Behavior |
|---------|----------|
| Toggle ON | Navigates to `?changes=1` (client-side, replacing history rather than pushing — the toggle is a view scope, not a destination, and it must not take four back-presses to leave a record). The page re-renders server-side: header count, entries and cursor all recomputed |
| Toggle OFF | Same, removing the param |
| Either direction | **Already-loaded pages are discarded and the list restarts at page 1** — never merged (see § The cursor trap) |
| During the transition | The switch stays interactive and keeps focus; no skeleton is shown, because the list is being replaced by a server render and a skeleton would flash for one round trip |
| Record has zero audit entries | The toggle still renders, with `(0)`. It is **not** hidden — a control that appears and disappears between records is worse than one that reports nothing to show |

**Load more** paginates every *currently included* kind together through Phase 35's existing keyset
cursor, and **must send the current filter flag** so page 2 is drawn from the same source set as
page 1. This phase adds a source and one filter dimension; it does not change the paging contract, the
page size (20), or the `Load more` copy.

**First paint is server-rendered**, as in Phase 35: page 1 of the timeline and the whole
records-changed section arrive with their RSC page. No skeleton, no spinner on initial load.

**Retention form**

| Trigger | Behavior |
|---------|----------|
| Input is empty, non-integer, `<1` or `>3650` | **Save disabled.** The always-visible helper text states the allowed range; no error colour, no error message appears and disappears. A rule the user can read before failing beats one that scolds after |
| Value unchanged from saved | Save disabled — there is nothing to save |
| Value **raised** (or set for the first time) | Saves directly. Button shows `Loader2 animate-spin` + `audit.retention.saving`; Input goes `disabled`; on success `toast.success(audit.retention.saved)` |
| Value **lowered** | Opens the shorten `AlertDialog` first. Confirm runs the same save; Cancel closes and **leaves the typed value in the Input** so the operator can adjust rather than retype |
| Save fails | Input re-enabled with the typed value **retained**, `toast.error(audit.retention.saveFailed)` — the same retain-on-failure rule the note composer follows |
| After a successful save | The two readouts are **not** optimistically updated. The entry count and oldest entry only change when the pruner next runs, and pretending otherwise would be a lie told by the UI |

**Records-changed section:** entirely static. Links navigate. There is no filter, no sort control and
no expansion — a run's effects are a short list, and controls on a short list are furniture.

## Accessibility Contract

- The timeline stays a single `<ol>`/`<li>` list; an audit entry is one `<li>`, in DOM order matching
  visual order. This phase adds a row **inside** Phase 35's list, never a nested list.
- Every field diff is a `<dl>` with paired `<dt>` (label) and `<dd>` (values), so assistive technology
  reads "Owner, Ana Lima changed to Bruno Sá" rather than four unlabelled fragments.
- The `→` arrow is a decorative `aria-hidden` icon; the direction is carried in text by an
  `sr-only` `audit.value.changedTo` span between the two values. **An icon must never be the only
  carrier of the before/after relationship.**
- Actor kind is carried by a **text badge**, not only by the rail icon; all rail icons and entity icons
  are `aria-hidden="true"`.
- The disclosure button has `aria-expanded` and `aria-controls` pointing at the `<dl>`'s id, and its
  accessible name states the count ("Show 9 more fields") rather than "Show more".
- **The filter toggle is a `Switch`, and that choice is an accessibility choice.** Radix renders
  `role="switch"` with `aria-checked`, so the state is programmatically determinable with no bespoke
  ARIA — which a ghost `Button` with an icon would not have been. It carries a **visible**
  `<Label htmlFor="timeline-audit-filter">`, never an `sr-only` one, following Phase 35's rule that a
  placeholder (or here, an icon) is not a label.
- The toggle carries `aria-controls` pointing at the timeline `<ol>`'s id, because it changes that
  list's contents rather than its own subtree.
- Toggling changes the list without a page-level navigation announcement, so the change is announced in
  the **`aria-live="polite"` region Phase 35 already put inside the card** — `audit.filter.announceShown`
  / `announceHidden`. A new live region is not added; the existing one gains two messages.
- The hidden-history empty state is ordinary heading + paragraph text in the normal flow, so it is
  reachable by screen reader and by find-in-page. The count in it is real text, not an aria attribute.
- Every timestamp is `<time dateTime={iso} title={absolute}>` wrapping `RelativeTime`, which already
  handles the SSR/CSR hydration guard.
- The retention `Input` has a visible `<Label htmlFor="retention-days">`; the helper text is associated
  with `aria-describedby` so it is announced, and the placeholder is never the label.
- The shorten confirmation is an `AlertDialog` — focus trap, ESC and focus restoration come from Radix.
- Focus rings are inherited from `globals.css` `:focus-visible`. Do not add per-component focus styling
  and do not set `outline: none` anywhere in this phase.
- Contrast: everything uses `foreground` / `muted-foreground` on `card` / `background`, the audited
  pairs already shipped. This phase introduces **no** pastel badge, so it adds no new contrast risk —
  unlike the two inherited light-mode-only maps Phase 35 reused.
- Truncated values rely on a native `title`, which is keyboard- and screen-reader-reachable; the
  truncation marker is a real `…` character so it is announced as an ellipsis rather than as three
  periods.

## Out of Scope (do not build, do not design for)

From `36-CONTEXT.md` § Deferred Ideas and § Out of scope, plus the boundaries this contract draws:

- A per-kind filter for **notes, activities or stage changes** — surface 4 is a single toggle over the
  audit source only, not a general facet UI. The other three kinds always render
- Grouping or collapsing consecutive audit rows into a summary entry — considered and rejected by the
  user in favour of the toggle (`36-CONTEXT.md` § Post-Research Addendum)
- Tabs. The audit entry remains a fourth source in one feed; the toggle hides it, it does not move it
- Restoring or undoing a record from an audit entry (Phase 37 owns trash/restore); no "Restore" control
  and no copy that implies one is coming
- A full-page or admin-wide audit **browser** — the only audit read surfaces in this phase are the
  per-record timeline, the run's records-changed list, and the read-only REST route (no UI)
- Exporting, downloading or streaming the audit log
- Auditing non-CRM entities (users, workflows, pipelines, custom field definitions) — so no audit entry
  may appear on a workflow, pipeline or admin field page
- Per-field or per-entity access control on audit reads beyond the REST route's admin-only gate
- Diff colouring (red/green), a JSON tree view, or a monospace value column
- Translating the rest of the `/workflows` tree
- Any change to `deal_stage_history` or its timeline entry — the two coexist by design

## Assumptions Flagged for the Planner

1. ~~**Audit entries in a record's timeline are visible to every user who can see the record.**~~
   **CONFIRMED, no longer an assumption.** `36-CONTEXT.md` § Post-Research Addendum accepts it
   explicitly: gating them would change the `TimelineSource` interface, and the record itself is
   already visible to that user. The header count and both empty states in § Surface 4 are specified
   on that basis.
2. **`AuditFieldChange.label` is resolved and localized server-side.** The alternative — shipping raw
   column names and translating in the client — would put a 20-branch switch inside a render function.
   If the assembler cannot reach a translator, the fallback is to ship the message **key** and resolve
   it in `audit-entry.tsx`; the rendered result must be identical either way.
3. **`workflowRun.workflowId` must be resolvable from the audit row.** The locked schema stores
   `workflow_run_id`; the link target needs the workflow id too, which is one join away on
   `workflow_runs`. If that join proves costly at the timeline's page size, the fallback is to link to
   `/workflows/{workflowId}/runs/{runId}` only when the join is already loaded and to render the plain
   kind label otherwise — never a broken link.
