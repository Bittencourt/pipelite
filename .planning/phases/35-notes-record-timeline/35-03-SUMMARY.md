## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Applied the migration via `drizzle-kit migrate` inside the running app container instead of `docker compose up -d --build`**

- **Found during:** Task 3, step 2
- **Issue:** The plan's apply path is `docker compose up -d --build`. Executing that from this git worktree is unsafe in two independent ways. First, `.env` is gitignored and therefore absent from the worktree, so Compose would interpolate `${DATABASE_URL}`, `${AUTH_SECRET}` and every other variable in `docker-compose.yml` to the empty string; the recreated app container would run `docker-entrypoint.sh` with no `DATABASE_URL`, `npx drizzle-kit migrate` would fail, and `set -e` plus `restart: unless-stopped` would crash-loop the user's live application — inducing the exact T-35-16 failure the plan's idempotency guard exists to avoid. Second, `--build` would rebuild the live `pipelite-app` image from an unmerged feature-branch worktree that is force-removed after execution.
- **Fix:** Copied the three new migration artifacts into the running container with `docker cp` (md5 verified identical on both sides), then ran `docker exec pipelite-app-1 sh -c 'cd /app && npx drizzle-kit migrate'`. This is the *same binary, same `drizzle.config.ts`, same container-provided `DATABASE_URL`, same single-transaction semantics* as the entrypoint — minus the image rebuild and the env-interpolation hazard. Afterwards the container was restarted so `docker-entrypoint.sh` ran for real, producing the `Running database migrations... / Starting application...` log evidence the acceptance criteria require; the entrypoint's migrate is now a verified no-op.
- **Files modified:** none (this was an execution-path change, not a code change)
- **Commit:** recorded in this SUMMARY

**2. [Rule 3 - Blocking] Symlinked `node_modules` from the main checkout to run `drizzle-kit generate`**

- **Found during:** Task 1
- **Issue:** The worktree has no `node_modules`. Running `npx drizzle-kit generate` would have triggered a registry fetch, violating the plan's `T-35-SC` disposition ("zero packages installed; `npx drizzle-kit` invokes the already-installed 0.31.9 from `node_modules`, not a registry fetch").
- **Fix:** Created a symlink to the main checkout's `node_modules`, verified `drizzle-kit: v0.31.9 / drizzle-orm: v0.45.1`, ran `generate` through `./node_modules/.bin/drizzle-kit`, and deleted the symlink afterwards. `node_modules` is gitignored, so it never entered a commit; the main checkout's `node_modules` was verified intact after removal. Zero packages were installed.
- **Files modified:** none committed
- **Commit:** n/a
