<hard_constraint>
## The Notes value MUST stay in entityAttributes

Notes is a first-class formula attribute for all four entity types
(src/lib/formula-recalc.ts lines 103-130) and every detail page passes it into CustomFieldsSection:
deals/[id]/page.tsx line 260, organizations/[id]/page.tsx line 198, people/[id]/page.tsx line 206,
activities/[id]/page.tsx line 259.

buildClientFieldValues seeds the formula evaluation map from these attributes. An absent key makes
the engine answer "Unknown field: X" and render #ERROR — a bug this repo already shipped and fixed
as CFUI-03.

So: delete ONLY the rendered block. The Notes value stays in entityAttributes on all four pages.

Accepted consequence to record in the SUMMARY: because the legacy column goes dormant while the
Notes formula attribute still reads it, any formula referencing Notes FREEZES at its migration-time
value. That is not a bug to fix here — the column drop is deferred, and re-pointing the Notes
attribute at the notes feed is a semantic change (which note?) that nobody has decided. State it out
loud so the next phase inherits it as a known state rather than a surprise.
</hard_constraint>
