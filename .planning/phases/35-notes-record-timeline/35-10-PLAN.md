<interfaces>
<!-- Contracts this plan CREATES for external consumers. -->

GET    /api/v1/{deals|organizations|people|activities}/{id}/notes
       200 with { data: SerializedNote[], meta: { total, offset, limit } } and an X-Total-Count header
       404 Problem when the parent record does not exist or is soft-deleted
POST   /api/v1/{deals|organizations|people|activities}/{id}/notes
       body { content: string }
       201 with { data: SerializedNote }; 400 Problem on validation; 404 Problem on a missing parent
PATCH  /api/v1/notes/{noteId}
       body { content: string }
       200 with { data: SerializedNote }; 403 Problem when neither author nor admin; 404 Problem
DELETE /api/v1/notes/{noteId}
       204 No Content; 403 Problem; 404 Problem

SerializedNote (camelCase, ISO date strings, matching the existing v1 serializers):
  id, entityType, entityId, content, authorId, source, createdAt, updatedAt
  deletedAt is NEVER serialized.

Paging on this surface is OFFSET/LIMIT via parsePagination, deliberately NOT the UI's keyset cursor.
Two paging schemes on two surfaces is the right answer here: every other v1 list route uses the
{ data, meta: { total, offset, limit } } envelope and external clients expect it. Do not force the
keyset cursor into the public API.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external client (Bearer API key) → route handler | Fully untrusted body, path params and headers; authentication and rate limiting come only from withApiAuth |
| API-key context → role | ApiAuthContext carries no role, so the admin decision must be re-read from the database rather than trusted from the request |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-08 | Elevation of Privilege | a route that forgets withApiAuth is unauthenticated and unrated | mitigate | Every handler in all five files is wrapped; asserted by a per-file grep gate in task 1 and task 2 verification |
| T-35-03 | Elevation of Privilege | IDOR on PATCH and DELETE of another user's note | mitigate | findNoteById then resolveActorRole then isAuthorOrAdmin, returning Problems.forbidden before any mutation; asserted by tests that also check the mutation mock was never called |
| T-35-09 | Elevation of Privilege | authorization drift between the v1 route and the server action | mitigate | Both import the same predicate from src/lib/notes/authorize.ts; grep gate forbids an inline role comparison in the route |
| T-35-04 | Tampering | cross-record note injection through a mismatched parent id | mitigate | Parent-existence check filtered on the parent deletedAt column before createNoteMutation, plus the mutation layer's own check |
| T-35-06 | Information Disclosure | soft-deleted notes returned by the API, or a deletedAt field leaking soft-delete state | mitigate | Every read filters isNull(notes.deletedAt); serializeNote omits deletedAt entirely and the OpenAPI Note schema does not declare it |
| T-35-10 | Information Disclosure | raw Postgres error or an existence oracle in a Problem response | mitigate | try/catch with console.error for detail and Problems.internalError for the client; a missing note and a soft-deleted note return the identical 404 |
| T-35-25 | Elevation of Privilege | failing open when the role lookup errors | mitigate | resolveActorRole returns null on error and the route maps null to Problems.forbidden |
| T-35-28 | Spoofing | forged note attribution via a body-supplied authorId | mitigate | The POST zod schema accepts only content; authorId is always context.userId |
| T-35-SC | Tampering | npm installs | accept | Zero packages installed |
</threat_model>
