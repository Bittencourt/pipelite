## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | `gap-1` — icon-to-label gaps inside badges and meta rows |
| sm | 8px | `gap-2` / `space-y-2` — author↔timestamp gap, composer button row, entry meta line, timeline icon rail → entry content column |
| md | 16px | `space-y-4` — vertical gap between timeline entries; composer → first entry |
| lg | 24px | `px-6` / `py-6` — Card padding (inherited from the `Card` primitive); `mt-6` between the details card, `CustomFieldsSection`, and the timeline card |
| xl | 32px | Timeline icon-rail column width (`w-8`) and avatar size (`size-8`) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | `min-h-16` — composer textarea minimum height |

**Exceptions:**

1. **32px icon buttons.** Per-note Edit and Delete render as `Button variant="ghost" size="icon-sm"`
   (`size-8`, 32×32), below the 44px touch guidance. Accepted because it matches the existing row-action
   precedent in `src/app/activities/activity-list.tsx`, the surface is a desktop-first CRM, the actions
   are **always visible** (never hover-only reveal, which would make them unreachable on touch), and every
   primary flow in this phase (composer textarea, Add note, Load more) uses a ≥36px target.

No other exception. Every other value in this phase is one of the seven declared tokens — including the
composer textarea, which uses `min-h-16` (64px, the `3xl` token) rather than an off-scale height, and the
timeline rail gap, which uses `gap-2` (8px, the `sm` token).

## Typography

Three sizes, two weights. All values are real Tailwind v4 tokens — no arbitrary values.

| Role | Size | Weight | Line Height | Tailwind | Applies to |
|------|------|--------|-------------|----------|-----------|
| Heading | 16px | 600 | 1.25 | `text-base font-semibold leading-tight` | Timeline card title |
| Label | 14px | 600 | 1.25 | `text-sm font-semibold leading-tight` | Note author name, stage-change actor, activity subject |
| Body | 14px | 400 | 1.5 | `text-sm leading-normal` | Note content, entry descriptions, composer textarea |
| Meta | 12px | 400 | 1.33 | `text-xs` | Timestamps, "edited" marker, "Migrated" badge, entry count |
| Display | — | — | — | — | **Not used.** The page `<h1>` (`text-3xl font-bold`) belongs to the existing page shell and is out of this phase's scope |

**Declared weights: 400 (normal) and 600 (semibold).**

**Weight exception:** the shared `button.tsx` primitive hardcodes `font-medium` (500) in its base class,
so every button label in this phase renders at 500. This phase does **not** patch a shared primitive to
satisfy its own contract — the exception is declared rather than eliminated.

**Line-height note:** headings use 1.25 (`leading-tight`) rather than the 1.2 guidance, because 1.25 is
an exact Tailwind token and 1.2 would require an arbitrary value. `CardTitle`'s built-in `leading-none`
is overridden with `leading-tight` at the call site.

**Note body rendering:** plain text with line breaks preserved — `whitespace-pre-wrap`, matching the
legacy block being replaced (`src/app/deals/[id]/page.tsx:245`). No markdown renderer, no rich-text
editor, no new dependency (locked in `35-CONTEXT.md` § Notes Data Model). Note bodies must also carry
`break-words` so a pasted URL cannot blow out the card width.

## Color

| Role | Token | Value (light) | Usage |
|------|-------|---------------|-------|
| Dominant (60%) | `--background` / `--card` | `oklch(1 0 0)` | Page background and the timeline card surface (`bg-card`) |
| Secondary (30%) | `--muted` / `--border` | `oklch(0.97 0 0)` / `oklch(0.922 0 0)` | Avatar fallback fill, the vertical timeline rail (`bg-border`), the "Migrated" badge (`variant="secondary"`), and all meta text (`text-muted-foreground`) |
| Accent (10%) | `--primary` | `oklch(0.205 0 0)` | See reserved list below |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` | See reserved list below |

**Accent (`--primary`) reserved for exactly three things — nothing else:**

1. The composer's **Add note** submit button fill (`Button variant="default"`) — the only filled button
   inside the timeline card.
2. Links from a timeline entry to a related record (`text-primary hover:underline`), matching the link
   treatment already used on the detail pages.
3. The keyboard focus outline, which is already global (`button:focus-visible` in `globals.css:151`).

Explicitly **not** accent: Load more (`variant="outline"`), Edit/Delete (`variant="ghost"`), entry type
icons (`text-muted-foreground`), timestamps, avatars.

**Destructive (`--destructive`) reserved for exactly two things:**

1. The `AlertDialogAction` confirm button in the delete-note dialog.
2. Sonner `toast.error(...)` styling, which is owned by the `sonner.tsx` primitive.

Never used for the Delete trigger itself (that stays `variant="ghost"` with a neutral `Trash2` icon,
matching `activity-list.tsx`), and never for validation hints in the composer.

**Data-driven color — inherited, not introduced.** Stage-change entries render the from/to stages with
the existing pastel map in `src/app/deals/[id]/page.tsx:80-89` (`bg-slate-100 text-slate-800`, etc.).
Activity entries render the existing type map in `src/app/activities/activity-list.tsx:98-103`
(`Call → bg-blue-100`, `Meeting → bg-purple-100`, `Task → bg-green-100`, `Email → bg-amber-100`).
**Zero new hues.** These maps are light-mode-only in the current codebase; this phase reuses them as-is
and does not add new instances of the problem.

**Forbidden:** any hardcoded hex, `bg-white`, `text-black`, or a color outside the token set or the two
inherited maps above.

**Destructive confirmation** — one destructive action exists in this phase: deleting a note.

| Field | Copy |
|-------|------|
| Trigger | Icon-only `Trash2`, `variant="ghost"`, `aria-label` = `notes.deleteNote` |
| Dialog title | Delete note |
| Dialog description | This removes the note from the record's timeline. You can't undo this here. |
| Cancel | Keep note (`notes.deleteDialog.cancel`) |
| Confirm | Delete note (`bg-destructive text-destructive-foreground hover:bg-destructive/90`, with `Loader2` spinner while in flight) |
| Keys | `notes.deleteDialog.title`, `notes.deleteDialog.description`, `notes.deleteDialog.cancel` |

The description deliberately does **not** promise restoration: notes are soft-deleted via `deletedAt`,
but trash/restore is Phase 37 and no restore surface exists yet. Copy must not write a cheque the
product cannot cash.

**Copy rules for this phase:**
- **No generic CTA labels.** Every button names the object it acts on — "Add note", "Save note",
  "Cancel edit", "Delete note", "Keep note". A bare "Save", "Cancel", "Confirm", "OK" or "Submit" is
  forbidden in this surface, including in the confirmation dialog.
- No exclamation marks. No "Oops". No "Something went wrong" as a standalone error — every error names
  the failed action and the next step.
- Every error message states what happened **and** what the user does next.
- The empty state's body ends by pointing at the composer that is already on screen.
- Success has **no toast**. The note appearing at the top of the timeline is the confirmation; a toast
  on top of a visible result is noise. Failures do get a `toast.error(...)` (existing sonner precedent).

## Layout & Composition

**Placement** (all four detail pages): details `Card` → `CustomFieldsSection` → **Timeline `Card`**,
separated by `mt-6` (24px), matching the existing gap `CustomFieldsSection` already uses.
Record data stays contiguous; history sits last. Not a sidebar, not a tab
(locked in `35-CONTEXT.md` § Timeline Composition).

**Timeline card anatomy, top to bottom:**

```
Card
├── CardHeader          Timeline  (16/600)   ({count} in 14px muted, matching CustomFieldsSection)
├── CardContent
│   ├── NoteComposer    Textarea (min-h-16) + right-aligned "Add note" button row (gap-2, mt-2)
│   ├── separator       border-t, mt-4 pt-4
│   ├── <ol>            entries, newest first, space-y-4
│   │   └── <li>        [32px icon rail] [gap-2] [entry content column, flex-1 min-w-0]
│   └── Load more       full-width, variant="outline", size="sm", mt-4 — rendered only when more exist
```

**Entry row structure** — identical skeleton for all three entry kinds so the timeline reads as one list:

| Column | Content |
|--------|---------|
| Rail (`w-8`, shrink-0) | Note → `Avatar size-8` with author initials (`getInitials` precedent). Activity → `size-8` rounded-full `bg-muted` holding the lucide type icon at `h-4 w-4 text-muted-foreground`. Stage change → same `bg-muted` circle holding `ArrowRight`. |
| Content (`flex-1 min-w-0`) | Line 1 (`flex flex-wrap items-center gap-2`): actor name (Label 14/600) · entry predicate · `<time>` (Meta 12/400 muted) · `edited` · `Migrated` badge. Line 2: the body — note text (`whitespace-pre-wrap break-words`), or the activity subject link, or the from/to stage badges. |
| Actions (shrink-0) | Notes authored by the current user or viewed by an admin: `Edit` + `Delete` at `size="icon-sm"`. All other entry kinds: nothing. |

**Primary visual anchor:** the composer's filled **Add note** button and the newest (topmost) entry are
the primary visual anchors of the timeline card — the Add note button is the only `--primary`-filled
element in the card, and the newest entry sits directly beneath the composer at the top of the list, so
the eye lands on "write something" and "what happened most recently" in that order. Every other element
(Load more, Edit, Delete, timestamps, rail icons) is deliberately subordinate: outline, ghost, or muted.

**Vertical connector:** a 1px `bg-border` line behind the rail, from the center of each icon to the next
one, omitted after the last loaded entry. Purely decorative — `aria-hidden="true"`.

**Responsive:** single column at every breakpoint. Below `sm`, line 1 wraps (`flex-wrap`) rather than
truncating; the rail and action buttons keep their widths. No horizontal scroll at 320px.

**Legacy removal (mandatory, `35-CONTEXT.md` § Specifics):** the `mt-6 pt-6 border-t` legacy notes block
is **deleted**, not left alongside the timeline, at all four sites:

| File | Block |
|------|-------|
| `src/app/deals/[id]/page.tsx` | lines 238-248 |
| `src/app/organizations/[id]/page.tsx` | lines 175-185 |
| `src/app/people/[id]/page.tsx` | lines 182-192 |
| `src/app/activities/[id]/page.tsx` | lines 238-248 |

The `notes` value stays in each page's `entityAttributes` prop passed to `CustomFieldsSection` — formulas
reference `Notes` and removing it would break live formula fields. Only the rendered block goes.

## Interaction Contract

**Composer**

| Trigger | Behavior |
|---------|----------|
| Empty or whitespace-only text | Submit button `disabled` — no validation error text, the disabled state is the message |
| `Cmd/Ctrl + Enter` in the textarea | Submits, identical to clicking Add note |
| `Enter` alone | Inserts a newline (line breaks are preserved content, not a submit gesture) |
| Submit | Button shows `Loader2 animate-spin` + `notes.adding`; textarea goes `disabled` |
| Success | Textarea clears, new entry is prepended optimistically at the top of the `<ol>`, `aria-live="polite"` region announces `notes.announceAdded`. **No toast.** |
| Failure | Textarea text is **retained**, `toast.error(notes.error.saveFailed)`, controls re-enabled |

**Entry actions** (author or admin only — server-enforced; the UI simply does not render the buttons for
anyone else)

| Trigger | Behavior |
|---------|----------|
| Edit | The note body swaps in place for a `Textarea` pre-filled with the current text, plus **Save note** / **Cancel edit** at `size="sm"`. Not a dialog — an inline swap keeps the surrounding timeline readable. |
| Cancel edit (`notes.cancelEdit` — "Cancel edit") | Reverts to the rendered body; no confirmation (nothing is lost that the user did not just type) |
| Save note (`notes.saveEdit` — "Save note") | Optimistic update; on success the `edited` marker appears (`updatedAt > createdAt`); on failure the previous text is restored and `toast.error(notes.error.editFailed)` fires |
| Delete | Opens `AlertDialog` (focus-trapped, ESC-dismissable). Confirm removes the entry from the list; failure restores it and fires `toast.error(notes.error.deleteFailed)` |

**Pagination** — 20 entries per page, newest first, Load more extends the list
(locked in `35-CONTEXT.md` § Timeline Composition).

| State | Rendering |
|-------|-----------|
| More entries exist | `Load more` button, full-width `variant="outline" size="sm"` |
| Fetch in flight | Same button, `disabled`, `Loader2 animate-spin` + `notes.loadingMore` |
| Fetch failed | Button returns to idle, `toast.error(notes.error.loadMoreFailed)` — never a silent no-op |
| No more entries | Button not rendered (no "That's all" terminal text) |

**First paint is server-rendered.** Page 1 arrives with the RSC page; there is no skeleton and no
loading spinner on initial load. Only `Load more` and the mutations are client fetches.

## Accessibility Contract

- The timeline is an ordered list: `<ol>` with one `<li>` per entry. Newest first, so the DOM order and
  the visual order agree.
- Every timestamp is a `<time dateTime={iso}>` element wrapping `RelativeTime`, with `title` carrying the
  absolute localized datetime. `RelativeTime` already handles the SSR/CSR hydration guard.
- The composer textarea has a `<Label className="sr-only">` — the placeholder is not the label.
- Icon-only Edit/Delete carry `aria-label` from `notes.editNote` / `notes.deleteNote`.
- The decorative vertical connector and all entry-rail icons are `aria-hidden="true"`.
- A `aria-live="polite"` region inside the card announces `notes.announceAdded` after a successful add.
- The delete confirmation uses `AlertDialog` (focus trap + ESC + focus restoration come from Radix).
- Focus rings are inherited from `globals.css` `:focus-visible` — do not add per-component focus styling
  and do not set `outline: none` anywhere in this phase.
- Contrast: all text uses `foreground` / `muted-foreground` on `card` / `background`, which are the
  audited pairs already shipped. The inherited stage/activity pastel badges are unchanged.
