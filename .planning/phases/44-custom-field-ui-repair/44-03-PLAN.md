<objective>
Give the browser the same field-value map the server builds, as a pure, directly testable function.

Purpose: CFUI-03 is a divergence between two evaluators. `recalculateFormulas` seeds `null` for
every active definition name (D-14) so an unset source can only ever be blank;
`custom-fields-section.tsx` does `{...entityAttributes, ...localValues}` and seeds nothing, so
`formula-engine.ts` takes its `!(dep in fields)` branch and fabricates `#ERROR — Unknown field: X`.
Reimplementing the seeding inline in the component would leave the parity unassertable, which is
exactly how this bug survived. So the seeding becomes a pure exported helper with its own tests —
`44-VALIDATION.md` names this the preferred route.

Output: `buildClientFieldValues`, tested against the server's own `buildFormulaFieldValues`. The
component wiring is plan 44-07.
</objective>

The server behaviour this helper must mirror, from `src/lib/formula-recalc.ts` (do NOT import this
module from client code — it imports `@/db`; importing it in a **test** is fine under `vi.mock("@/db")`):

```ts
export function buildFormulaFieldValues({ entityType, definitions, row }): Record<string, unknown> {
  const values: Record<string, unknown> = {}
  for (const [attribute, column] of Object.entries(ENTITY_NATIVE_ATTRIBUTES[entityType])) {
    values[attribute] = row?.[column] ?? null            // 1. natives
  }
  for (const definition of definitions) {
    values[definition.name] = null                        // 2. D-14 null seed
  }
  const stored = (row?.customFields ?? {}) as Record<string, unknown>
  for (const [key, value] of Object.entries(stored)) {
    values[key] = unwrapFormulaValue(value)               // 3. stored, unwrapped
  }
  return values
}
```

The engine branch this exists to avoid, from `src/lib/formula-engine.ts:207-212`:

```ts
if (!(dep in fields)) {
  const fromRelated = getFromRelatedEntities(dep, relatedEntities)
  if (fromRelated === undefined) return { value: null, error: `Unknown field: ${dep}` }
} else if (fields[dep] === null && propagateNull) {
  return { value: null, error: null }        // blank — what we want
}
```

Client-safe imports (verified: no `@/db` in the import graph):
```ts
import { unwrapFormulaValue } from '@/lib/formula-helpers'   // formula-helpers imports only ./formula-engine
```

The client already holds the natives in a different shape from the server: the detail pages pass
`entityAttributes` keyed by **attribute** name (`{ Value, Title, Notes, ExpectedCloseDate }`), whereas
the server maps attribute → column against the row. So the helper takes the already-resolved
attribute map; it does not need `ENTITY_NATIVE_ATTRIBUTES`.
