<objective>
Put the replay control on a failed run's detail page: an outline trigger, a consequential-confirm dialog
whose body is the most important string in this phase, a pending state, and navigation to the new run.
Plus the lineage line, the dry-run badge, and the two container fixes the added elements require.

Purpose: criterion 1 is *"gets a new run with its own step history"*, and the operator has to be able
to SEE it — hence the navigation. The confirmation is load-bearing rather than a courtesy: a replay is a
fresh run from node 1, so every step that already *succeeded* before the failure runs again, and its
emails send again, its HTTP calls fire again, its CRM writes repeat. `.env` points SMTP at a real relay.
An operator clicking a button labelled "Replay" on a failed run does not necessarily expect to duplicate
the successful half of it.
Output: one new client component, four edits to the page, and the G-6 gate.
</objective>

<recorded_decisions>
**G-6 is reshaped, per RESEARCH C-1.** UI-SPEC's G-6 asks for a component render test. This repo has
**no** `@testing-library/react`, no `jsdom`, no `happy-dom`, no `@vitejs/plugin-react`, and zero React
render tests, by construction — `vitest.config.ts` sets `environment: 'node'` globally and no file in
`src/` carries a `@vitest-environment` pragma. The gate is therefore the repo's `enclosingConditional`
source-scan idiom, which asserts the same claim.

**That reshaping is a HARD CONSTRAINT on the implementation.** `enclosingConditional` requires the
`{<test> && ( … )}` form and THROWS on a ternary, an extracted `const replayControl = …`, or an early
return (`source-scan.ts:290-303`) — a throw reads as a broken test rather than a broken implementation.
So the render site must be written literally as `{run.status === "failed" && (<ReplayRunButton … />)}`.
The page already uses that shape.

**Consequential, not destructive.** Follow `delete-workflow-dialog.tsx`'s shape — plain `Dialog`,
`DialogFooter`, outline Cancel — but **omit its `AlertTriangle` in a `bg-destructive/10` tile**. That
tile is what marks the delete dialog as destructive, and copying it would tell the operator that
replaying a run is dangerous rather than consequential. Replay's dialog carries **no icon** and the
confirm button is `variant="default"`.

**Two UI-SPEC line references drifted** (RESEARCH C-3): R-1 is at `page.tsx:148` not 145, R-2 at 154 not
152. Every *class string* UI-SPEC quotes is correct. **The gates key on class strings, never on line
numbers.**

**No back-link on the origin run.** One direction only. A "replayed as …" reverse link would need a
reverse query and a list (a chain can fan out) for no criterion.
