<objective>
Make a persisted dry run reachable but not intrusive: hidden from both places runs are listed, revealed
by one checkbox, and badged when shown so it cannot be mistaken for a real run whose changed-records
panel is inexplicably empty.

Purpose: CONTEXT locks a dry run as a real `workflow_runs` row "filtered out of the runs list by
default". *By default* implies a way to see them, and without one a dry run is unreachable once its tab
is closed. And without the badge, criterion 2's proof — an empty changed-records panel — reads as a bug
report rather than as evidence.
Output: the filter in SQL (not the client), the reveal checkbox, a new server-safe badge, its render
site in the runs table, the same filter in the overview's Recent Runs, and one wiring gate.
</objective>

<recorded_decisions>
**D-A7 / `recent-runs-mini.tsx` is a QUERY-ONLY edit, not an out-of-inventory UI surface.** It is
deliberately absent from UI-SPEC's Surface Inventory, whose completeness rule says "an addition is a
scope violation rather than an improvement". This edit renders no new element, changes no class string
and adds no copy — it adds `eq(workflowRuns.dryRun, false)` to a `where`. Without it a dry run appears
in the workflow overview's Recent Runs, unbadged, indistinguishable from a real run, and pushes a real
run out of the top 5. Stated here explicitly so the UI checker does not read it as scope creep.

**The filter is in SQL, not in the client.** A client-side filter would still ship dry-run rows to the
browser and would break the pagination count, which is computed from the same `whereClause`.

**A `Checkbox`, not a fifth `SelectItem`.** Dry-run-ness is orthogonal to status; folding it into the
status Select would make "failed" and "test" mutually exclusive, when a failed test run is the most
interesting row on the page.

**The badge is `variant="outline"` + `border-dashed`, not a colour** (UI-SPEC C-41-2). A new colour pair
would violate C-41-1 in a directory that already ships six; `variant="secondary"` is taken by `pending`.
A dashed border is this app's existing idiom for "provisional / not real content" —
`runs-table.tsx:36` renders its empty state in `rounded-lg border border-dashed`. Token-only, so
theme-correct for free, and distinguishable from `skipped` (also `outline`) by border style rather than
hue, which survives a monochrome display.

**`run-status-badge.tsx` is NOT modified.** Its `Record<Status, …>` map is exhaustive-by-type on purpose
and `dryRun` is not a `WorkflowStatus`. The badge is an orthogonal dimension, so it lives in its own
component and renders BESIDE the status badge, never instead of it.
</recorded_decisions>
