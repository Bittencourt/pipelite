Build the two pure, database-free modules the rest of the phase depends on: the closed `?type=`
vocabulary (which is the input-validation control for the trash surface) and the "deleted by"
presenter (which carries the one genuinely new piece of logic in TRASH-01 — the discrimination between
"no audit row was ever written" and "a user did this and that user is gone").

they must be importable from every boundary and must not drag `@/db` into a browser bundle.
Output: `src/lib/trash/entity-types.ts` and `src/lib/trash/present.ts`, each with a unit test.
</objective>

Create `src/lib/trash/present.ts` as a pure, database-free presenter. It converts one raw joined
`audit_log` row (or its absence) into a discriminated presentation the trash column can render.

Declare:

  - `export interface DeletedByRow { entityId: string; actorKind: AuditActorKind; actorId: string | null;
    actorName: string | null; actorEmail: string | null; runId: string | null; workflowId: string | null;
    workflowName: string | null; createdAt: Date }` — the exact projection `queries.ts` will select.
  - `export type DeletedByPresentation` as a discriminated union on `kind`:
    `{ kind: "notRecorded" }` | `{ kind: "user"; name: string | null; email: string | null }` |
    `{ kind: "unknownUser" }` | `{ kind: "workflowRun"; runId: string | null; workflowId: string | null; workflowName: string | null }` |
    `{ kind: "apiKey" }` | `{ kind: "import" }` | `{ kind: "system" }`.
  - `export function presentDeletedBy(row: DeletedByRow | undefined): DeletedByPresentation`.

Implementation rules, each of which must carry a comment saying why:

  - `row === undefined` returns `notRecorded`. Absence from the batched lookup means nobody wrote it
    down, because the record was deleted before change history existed. It is NOT the same fact as
    "a user did this and that user row is gone", and the two must not collapse into one string
    (CONTEXT.md § Specific Ideas, RESEARCH Pitfall 4).
  - For `actorKind === "user"`, the `actorKind === "user" && actorId !== null && actorEmail !== null`
    guard from `sources.ts:754-761` decides between the `user` and `unknownUser` shapes. The kind test
    must come FIRST — that is what stops an `api_key` row, which stores the key's owner in
    `actor_user_id`, being attributed to that person.
  - `api_key` returns the bare `apiKey` kind with no name field at all. `audit_log` has no api-key
    reference; `sources.ts:771-782` documents that resolving one through `actor_user_id` would pick an
    arbitrary key of that user and print it as fact. UI-SPEC § "Deleted by" says "the key name beside
    it when known" — that is unachievable and this plan corrects it rather than under-delivering it
    silently. The same applies to `import`: every `runWithActor({ kind: "import", ... })` call site in
    `src/app/import/actions.ts` passes a null session id.
  - The switch is exhaustive with the `const unhandled: never = row.actorKind` guard from
    `audit-entry.tsx:311-315`, so a sixth actor kind is a compile error.

This module returns data, not JSX, and must import no React and no `@/db`. Message keys are chosen by
the consuming component; the presenter carries no translation keys and duplicates none of the existing
`audit.actorKind.*` / `audit.unknownActor` keys (UI-SPEC § Reused keys forbids that).

Write `src/lib/trash/present.test.ts` first (RED), using `src/lib/audit/settings.test.ts` for describe/it
structure only. Build a `baseRow()` helper so each test overrides one field.

`feat(37-02): add the deleted-by presenter with notRecorded discrimination`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser URL → `/trash` server component | `?type=` and `?page=` are attacker-controlled strings that select a table and an offset |
| `audit_log` row → rendered actor label | Stored attribution crosses into a claim the UI makes about who did something |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-03 | Tampering | `parseTrashTab` / `parseTrashPage` | mitigate | `?type=` is narrowed to the four `TRASH_TABS` literals and `?page=` to a digits-only integer clamped to [1, 200] **before** either value can reach a predicate or an offset. Proven by hostile-input tests including a SQL-fragment string |
| T-37-02 | Information Disclosure | `parseTrashPage` upper clamp | mitigate | An unbounded `?page=` would let a caller walk arbitrarily deep offsets and time the response; the clamp bounds it |
| T-37-REP2 | Repudiation | `presentDeletedBy` | mitigate | "Not recorded" and "Unknown user" stay distinct kinds, so the UI cannot invent an attribution for a record deleted before the audit log existed. Asserted by a direct inequality test |
| T-37-09 | Information Disclosure | `presentDeletedBy` for `api_key` | mitigate | The presenter returns no name for an api-key actor, so the key owner's identity is never printed as the actor. `audit_log` has no api-key reference and one must not be fabricated through the owner join |
| T-37-SC | Tampering | npm/pip/cargo installs | accept | This phase installs nothing (`37-RESEARCH.md § Package Legitimacy Audit`) |
</threat_model>
