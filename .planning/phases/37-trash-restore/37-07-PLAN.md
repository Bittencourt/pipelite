`resolveDeletedBy(entityType: EntityType, entityIds: string[]): Promise<Map<string, DeletedByRow>>`

Return early with an empty `Map` when `entityIds` is empty. Otherwise issue ONE `db.execute` of a raw
drizzle `sql` template implementing RESEARCH Pattern 3:

  SELECT DISTINCT ON (al.entity_id) al.entity_id, al.actor_kind, al.created_at,
         u.id, u.name, u.email, wr.id, w.id, w.name
  FROM audit_log al
  LEFT JOIN users u ON u.id = al.actor_user_id
  LEFT JOIN workflow_runs wr ON wr.id = al.workflow_run_id
  LEFT JOIN workflows w ON w.id = wr.workflow_id
  WHERE al.entity_type = <bound> AND al.action = 'deleted' AND al.entity_id = ANY(<bound>)
  ORDER BY al.entity_id, al.created_at DESC

`ORDER BY entity_id, created_at DESC` is required by `DISTINCT ON` and is also exactly
`audit_log_entity_idx`'s column order for a fixed entity type, so the planner produces an index scan
feeding at most an incremental sort with `Presorted Key: entity_id`. Prefer `DISTINCT ON` over a
`LATERAL` join: both are one round trip, but `LATERAL` needs one index descent per row.

Every value binds. The entity type is typed as the closed `EntityType` union and must never be
interpolated into the template text — the timeline assembler is the repo's only other hand-composed
SQL and it is documented as such precisely because this is the risky construct. Bind the id array so
Postgres receives it as a parameter for `= ANY(...)`.

Map the raw rows onto `DeletedByRow` and key them by `entity_id`. Wrap the whole thing in try/catch

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser `?type=` / `?page=` → SQL | Attacker-controlled strings select a table and an offset |
| authenticated session → other users' records | The trash list is the only surface that shows records the live lists hide |
| hand-composed `DISTINCT ON` fragment → database | The one raw SQL statement this phase writes |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

Asserted by compiling the predicate with `PgDialect` for both roles |
