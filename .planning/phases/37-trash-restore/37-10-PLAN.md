  <action>
Create `src/app/trash/actions.ts`, beginning with `"use server"`.

Export a discriminated result type shared by all three actions:

  `export type TrashActionResult<T = Record<string, never>> =
     | ({ success: true } & T)
     | { success: false; code: "NOT_AUTHENTICATED" | "NOT_AUTHORIZED" | "NOT_ADMIN" | "NOT_IN_TRASH" | "FAILED" }`

The client switches on `code` and string-matches nothing — that is why the failure carries a code rather
than prose, and it is what lets the UI say `trash.error.alreadyPurged` for `NOT_IN_TRASH` and
`trash.error.purgeNotPermitted` for `NOT_ADMIN` instead of telling a user to retry a record that no
longer exists.

`restoreRecord(tab: TrashTab, id: string)`:

  1. `const session = await auth()`; no session id returns `NOT_AUTHENTICATED`.
  2. Narrow the tab: `const entityType = TRASH_TAB_TO_ENTITY[parseTrashTab(tab)]`. Never index the map
     with an unnarrowed argument.
  3. `const record = await findTrashedRecord(entityType, id)`; null returns `NOT_IN_TRASH`.
  4. `if (record.ownerId !== session.user.id && session.user.role !== "admin") return NOT_AUTHORIZED` —
     the exact guard shape from `src/app/deals/actions.ts:83`, inverted only in that the lookup used
     `isNotNull(deletedAt)`.
  5. `const result = await runWithActor({ kind: "user", userId: session.user.id }, () => restoreRecordByType(entityType, id))`.
     The actor scope opens AFTER the session check, never before it, so an unauthenticated call
     establishes no actor at all. `userId` is `session.user.id` and nothing else — never a form field,
     never a search param.
  6. On failure, forward `NOT_IN_TRASH` as itself and map anything else to `FAILED`.
  7. On success, `revalidatePath("/trash")` and return `{ success: true, name: record.name, tab }`.

`restoreWithLinked(tab: TrashTab, id: string)`:

  Same steps 1-4 for the record itself. Then `const parents = await findTrashedParents(entityType, id)`.
  Restore the PARENTS FIRST, outermost first — organization before person before deal — then the record
  itself. Order matters: `cascadeToChildren` in the formula engine filters on the child relation's null
  `deletedAt`, so a parent restored after its child means the child's cascade ran while the parent was
  still trashed. Re-check owner-or-admin for EACH parent independently against its own `ownerId`; skip a
  parent the caller may not touch rather than failing the whole operation, because the record the user
  actually clicked should still come back. Count the successes and return `{ success: true, count }`.
  Every parent restore is inside the same `runWithActor` scope.

  A parent whose restore fails is skipped and not counted; the action still succeeds if the record
  itself came back. Log the skipped and failed ids with a `[trash-actions]` prefix — identifiers and
  counts only, never record contents.

`purgeRecord(tab: TrashTab, id: string)`:

  1. Session check.
  2. `if (session.user.role !== "admin") return { success: false, code: "NOT_ADMIN" }` — placed BEFORE
     any lookup, so a non-admin cannot use the action to probe whether an id exists. Carry forward the
     comment from `src/app/admin/audit/actions.ts`: a server action is a POST endpoint the browser can
     invoke directly with no page involved, so the hidden client button is never the gate.
  3. Narrow the tab, `findTrashedRecord`, null returns `NOT_IN_TRASH`. No owner check is needed on top
     of the admin check — an admin may purge any record — but the `isNotNull(deletedAt)` predicate on
     the lookup and again inside the purge mutation is what stops a live record being destroyed.
  4. `runWithActor({ kind: "user", userId: session.user.id }, () => purgeRecordByType(entityType, id))`.
  5. `revalidatePath("/trash")`, return `{ success: true, name: record.name, detached: result.detached }`.
