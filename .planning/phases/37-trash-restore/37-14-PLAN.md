  <action>
Create `src/app/trash/trash-tabs.tsx` as a `'use client'` module exporting a `TrashTabs` component
taking `{ tab: TrashTab; counts: Record<TrashTab, number> | null; children: React.ReactNode }`.

Render a Radix `Tabs` with a CONTROLLED `value={tab}` and an `onValueChange` that pushes the new URL —
never `defaultValue`. The handler builds a `URLSearchParams` from `window.location.search`, sets `type`
to the new tab, DELETES `page` (switching tabs resets paging to page 1; preserving a page-3 cursor
across a tab change would show an empty table for no visible reason), and calls
`router.push('/trash?' + sp.toString())`.

`activationMode="manual"` is REQUIRED, not optional. Radix `Tabs` defaults to `automatic`, which selects
on focus; with tab changes wired to `router.push`, arrowing across four tabs would fire four server
navigations. `manual` moves focus with the arrow keys and activates on Enter or Space — one navigation,
one round trip. This is a performance decision and an accessibility one, and it must not be dropped.
Write that reason in a comment.

`TabsList` holds four `TabsTrigger`s, one per `TRASH_TABS` value, each with `className="gap-2"`, an icon
at `h-4 w-4` with `aria-hidden="true"`, the label from the EXISTING `nav.*` key for that entity, and —
when `counts` is non-null — the count in a `<span className="text-muted-foreground text-xs">`.

Tab labels reuse `nav.deals`, `nav.people`, `nav.organizations` and `nav.activities` rather than four new
keys. This is not key thrift: it guarantees the tab is named identically to the nav item the record
returns to, which is the sentence the restore toast then repeats. Tab icons are the app's own nav
vocabulary — `Kanban`, `Users`, `Building2`, `CheckCircle2` — so zero new symbols enter the product.

When `counts` is null (the count query failed), render the labels without counts rather than printing a
zero. A count a user cannot explain is a visible defect; a missing count is merely quiet.

Render `{children}` inside a single `TabsContent value={tab} className="mt-4"`. Only the ACTIVE tab has a
content node at all — the other three values simply have none. Fetching four tables to show one is the
obvious wrong turn and this line exists so it is not taken.

Do not style the active tab with `--primary`. Radix's active state is `data-[state=active]:bg-background`
plus `text-foreground` on a `bg-muted` track — background, not primary. Do not "fix" this.

A tab with zero records is still rendered, still labelled `(0)` and still selectable. A tab that appears
and disappears between visits is worse than one that reports nothing to show.

Steps:

  1. `const params = await searchParams`; `const tab = parseTrashTab(params.type)`;
     `const page = parseTrashPage(params.page)`. Both parsers are the input-validation control — no raw

     error, never an empty shell.
  2. `const session = await auth()`. Redirect to sign-in when there is no session, following whatever

     `const viewer = { userId: session.user.id, role: session.user.role }` and
     `const isAdmin = session.user.role === "admin"`.

     the page renders even when the database is unhappy. Carry that comment forward from
     `admin/audit/page.tsx`. Only the ACTIVE tab is queried for rows; the other three contribute counts

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser URL → server component | `?type=` and `?page=` are attacker-controlled and select a table and an offset |
| session → visible records | `/trash` is the only surface that lists records the live lists hide |
| server component → client components | Props crossing the RSC boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-03 | Tampering | `?type=` and `?page=` | mitigate | Both narrowed through `parseTrashTab` / `parseTrashPage` (plan 37-02) before reaching any query; `?page=` is clamped to [1, 200]. Gated by a grep assertion that the raw params are not used directly |
| T-37-02 | Information Disclosure | the rows and the four counts | mitigate | `viewer.role` comes from the server session, never from a search param or a prop, and the owner scope is applied inside `countTrashed`/`listTrashed`. The counts are scoped identically to the rows, so a count a user cannot explain never appears |
| T-37-01 | Elevation of Privilege | the `isAdmin` prop | mitigate | Derived server-side from `session.user.role` and used only to decide whether to RENDER the purge control. It is never the authorization: `purgeRecord` and the REST route both re-check the role independently |
| T-37-20 | Denial of Service | an unguarded query throw | mitigate | All three reads fail closed inside their own modules and the page renders the `trash.error.unavailable` panel instead of throwing. `/trash` has no `error.tsx` above it, so this is the only thing standing between a bad query and a dead page |
| T-37-23 | Tampering | RSC boundary violation (CFUI-01) | mitigate | Only plain serializable values cross; `Date` values are converted to ISO strings before they do. Enforced by the repo-wide scan |
| T-37-35 | Denial of Service | arrow-key tab navigation | mitigate | `activationMode="manual"` means arrowing across four tabs fires one navigation on Enter rather than four on focus |
| T-37-SC | Tampering | npm/pip/cargo installs | accept | This phase installs nothing and runs zero `shadcn add` commands |
</threat_model>
