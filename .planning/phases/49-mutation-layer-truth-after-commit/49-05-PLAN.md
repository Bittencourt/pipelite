<objective>
Prove DATA-02 behaviourally, for all four entities, against a divergence this test manufactures itself.

Plan 49-03 landed the canonical read and inverted the two assertions that pinned the defect. But those
are unit assertions over a mocked recalc, and 49-03's own ablation recorded the limit plainly: **the
REJECTED in-process merge passes the unit proof.** `{ ...row, customFields: recalculatedCustomFields }`
and a real re-read produce the same bytes today, because the recalc writes exactly `customFields` and
nothing else. That equivalence is a coincidence, not a contract.

So this is the proof that means something: **one request creates the record, a second request reads
it, and the two bodies' `custom_fields` are compared.** No mocks between the handler and the database.
Real keys through the real `withApiAuth`.

And it manufactures its own subject, because otherwise it proves nothing. Measured: **zero
`type='formula'` definitions.** `recalculateFormulas` writes only when `inScope.length > 0`, which
needs at least one formula definition with a non-empty `config.expression`. With none, there is **no
field, native or custom, on which a 201 body and a subsequent GET can currently differ** — so a
DATA-02 test written against live definitions is green before the fix and green after it. That is the
SC-3 trap arriving in SC-4, and the ROADMAP does not warn about it. Plan 49-01 built the fixture that
escapes it.

Purpose: DATA-02, proven per entity rather than per shape.
Output: one live-database proof file and four per-entity ablation transcripts.
