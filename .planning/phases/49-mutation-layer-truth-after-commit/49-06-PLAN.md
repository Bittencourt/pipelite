<objective>
Prove SC-1 the way it has to be proven: two real users, two real records, real bytes on a real
filesystem, and a request that must come back empty.

Plan 49-04 closed the three holes and proved it at the handler level with a mocked `@/db`. That proof
is real — it drove the shipped route and watched it serve another user's file — but it mocks the
lookup, so it proves the guard *calls* a resolver, not that the resolver's predicate actually excludes
a foreign row in PostgreSQL. Those are different claims, and Phase 48 learned the difference the hard
way: `db-errors.ts`'s first version had 24 green unit assertions and answered 500 where 409 was
expected the moment a real database was involved.

So this file mocks two things and no more — `@/auth`, because a session cannot be minted over an
in-process handler call, and `next/cache` if the route touches it. **`@/db` is not mocked.** Nothing
that decides the outcome under test is substituted.

**`mintApiKey` does not apply here.** The file route authenticates with `auth()`, not `withApiAuth`,
and CONTEXT.md forbids inventing a `withApiAuth` twin for files. The correct harness is the
`vi.hoisted` + `vi.mock("@/auth")` + real-`db` pattern at `import-owner-scope.db.test.ts:69-81`.

**One mechanical trap decides whether this file works at all.** The route reads
`const UPLOAD_DIR = process.env.UPLOAD_DIR || '/tmp/uploads'` at **module-evaluation** time. A test
that sets the variable after importing the route has no effect, and the host test process cannot see
the container's `/app/uploads` volume. So the assignment must happen inside `vi.hoisted`, which runs
before the static imports are evaluated. Get that wrong and every cell either passes vacuously against
`/tmp/uploads` or fails for the wrong reason.

**Scope: `FILE_STORAGE=local`.** Under `s3` nothing reads through this route at all (SEC-49-A). No S3
claim appears in this plan's output.

Purpose: SEC-04's first half, proven behaviourally, so the phase's headline security criterion does not
rest on a mocked lookup.
Output: one live-database proof file and two ablation transcripts reproducing the IDOR against real
PostgreSQL.
</objective>
