<objective>
Make a merge leave the survivor consistent — and prove it against the one fixture shape that can
actually tell the difference.

**The survivor's formula fields are recomputed nowhere today**, and by construction, not by oversight.
`recalcReparentedChildren` (`dedup.ts:735-802`) builds its work list as `[...movedDeals,
...movedPeople]`, returns immediately if that list is empty, and calls `recalculateFormulas` **only**
with `entityId: child.id`. `survivorId` appears in that function only inside a `log.warn` diagnostic.
`dedup.ts` has exactly one `recalculateFormulas` call site. So: not inside the transaction, not after
it, and not by a cascade. And a merge with **no** reparented children — an organization pair with no
shared deals or people, which is common — recomputes literally nothing at all.

Even a survivor-rooted cascade would not help: `cascadeToChildren` short-circuits on
`if (changed.size === 0) return 0`, which the block being edited already documents.

**Placement is settled: extend the existing post-commit block at `dedup.ts:629-650`.** The block's own
comment explains why: `recalculateFormulas` and its whole cascade use the module-level `db` and take no
`tx`, so calling it inside the transaction would read a snapshot without the uncommitted reparenting
and write outside the transaction's atomicity.

**The single likeliest way this half-ships is a spelling.** `dedup.ts:325-334` builds `fieldChanges`
with keys `customFields.${key}` — one screen above the insertion point, and it reads like the right
array. It is the **audit diff**. `scopeFormulasToChangedFields` matches a formula's dependency ref
against `changedFields` three ways: the bare name, a native attribute via its COLUMN name, or the
literal sentinel `"customFields"`. `"customFields.Origem"` matches none of them. Passing
`Object.keys(fieldChanges)` would produce a call that recomputes **nothing** — a fix that ships green
over the defect.

**And the fixture must take the loser's value.** If the survivor wins every field, the correct answer
and the stale answer are the same number and the test passes either way. That is the zero-definitions
trap one level down, and this plan measures it rather than describing it.

Purpose: DATA-01.
Output: one post-commit block, five unit cells, a behavioural proof, and a vacuity control that passes
without the fix on purpose.
</objective>
