<objective>
Make the create response tell the truth, at the route, for all four entities — and amend the six
assertions that pin the defect in the same plan that removes it.

Today `POST /api/v1/organizations` ends `return createdResponse(serializeOrganization(result.organization))`
— the row as the insert returned it, captured **before** `recalculateFormulas` writes `customFields`.
The user settled the contract: **re-read the record through the same path `GET` uses and serialize
that.** One code path defines truth, so the 201 body and a subsequent read cannot drift — including
for derived fields that do not exist yet. The accepted cost is one extra `SELECT` per create.

**DATA-02 is a purely LATENT defect and nothing diverges today.** Measured: zero `type='formula'`
definitions, so `recalculateFormulas` never writes (`inScope.length === 0` → no read, no evaluation,
no write); `stripCallerFormulaKeys` runs before the insert; the recalc does not bump `updatedAt`; the
serializers are derivation-free. So a test written against live definitions is green before AND after
the fix. **This plan's proof is therefore the unit level, against mocked recalc results that are
deliberately unequal to the stored blob** — and the behavioural, real-PostgreSQL, four-entity proof
belongs to plan 49-05 with its own manufactured formula definition.

Two structural facts decide the shape. **The four POSTs are TWO shapes, not one:** organizations and
activities hold `result.{entity}` from a create mutation; people and deals inline `db.insert` +
`recalcCustomFields` + `crmBus.emit` in the route and **already hold the post-recalc blob in a local**
— which makes reaching for the rejected in-process merge easiest in exactly those two files. And
**there is no `get{Entity}` helper for any of the four**; the GET-by-id read is inlined in each
`[id]/route.ts`, and only `organizations/[id]/route.ts:121-127` does a real re-read. The other three
PUTs assemble `{ ...updated, customFields: recalculatedCustomFields }` — the rejected merge, three
times, one directory over from the one correct analog.

Purpose: DATA-02, decided once and applied identically to all four entities.
Output: four re-reads, six amended assertions, one new test file, three corrected comments.
</objective>
