<objective>
Make the shared declaration bite at the producer end: give each of the three data-tables a required-member
contract derived from the same one interface.

Purpose: this is what makes criterion 2 worth satisfying rather than merely satisfied. A single interface
shared by every table in the app **cannot have required members** — `src/app/admin/users/data-table.tsx:41`
passes only `meta: { refresh }`, so a required `onEdit` breaks it with TS2741. Every augmented member is
therefore optional, which means plan 43-01 on its own traded fourteen suppressions for callbacks that are
`… | undefined` at every read. That is not a regression (those reads were `any` before, which is strictly
worse) but it is not the win either: rename a callback in one file and the other silently reads `undefined`.

`Required<Pick<TableMeta<Organization>, "onEdit" | "onDelete" | "refresh">>` closes it at the consumer
without introducing a second declaration — it is a narrowing of the one shared interface, which is exactly
the shape `src/app/trash/trash-table.tsx:295` has used since Phase 37. Research built this variant, got
`tsc` exit 0, then deleted one member and measured:

```
src/app/organizations/data-table.tsx(395,9): error TS2741: Property 'onDelete' is missing in type
'{ refresh: () => void; onEdit: (org: Organization) => void; }' but required in type
'Required<Pick<TableMeta<Organization>, "refresh" | "onEdit" | "onDelete">>'.
```

So the contract genuinely fails when violated. Task 2 exists to reproduce that failure on purpose, because
this project has just spent a phase discovering what an unproven gate is worth.

Output: three typed `meta` consts, one negative proof, and a full suite run.
</objective>

<interfaces>
Plan 43-01 created `src/types/tanstack-table.d.ts`, augmenting the library's own interface:

```ts
declare module "@tanstack/react-table" {
  interface TableMeta<TData extends RowData> {
    onEdit?: (row: TData) => void
    onDelete?: (row: TData) => void
    onSetDefault?: (row: TData) => void
    settingDefaultId?: string | null
    refresh?: () => void
    renderActions?: (row: TData) => ReactNode
  }
}
```

Every member is optional and must STAY optional — that is asserted by
`src/types/__tests__/no-standing-suppressions.test.ts`. Required members are enforced here instead.

**The three contracts, and the exact member set each needs** (grep-verified inventory, § A3):

```ts
type OrganizationTableMeta = Required<Pick<TableMeta<Organization>, "refresh" | "onEdit" | "onDelete">>
type PersonTableMeta       = Required<Pick<TableMeta<Person>, "refresh" | "onEdit" | "onDelete">>
type PipelineTableMeta     = Required<Pick<TableMeta<Pipeline>, "onEdit" | "onDelete" | "onSetDefault" | "settingDefaultId">>
```

`settingDefaultId` is a VALUE, not a callback (`admin/pipelines/data-table.tsx:40`,
`useState<string | null>(null)`), and it is passed but never read by the columns file. It is in the
contract because it is in the literal, and `Required<>` keeps its `string | null` type intact.

**The consumer shape to copy — `src/app/trash/trash-table.tsx:295` and `:355`:**

```ts
const meta: TrashTableMeta = { renderActions: (row) => { … } }
// …
const table = useReactTable({ data: rows, columns, getCoreRowModel: getCoreRowModel(), meta })
```

A named const with an explicit annotation, then `meta,` in the options object. That is what D-2 asked
for and it is already green in this repo.
