<objective>
Create the one shared `TableMeta` declaration and delete all fourteen `@ts-expect-error` suppressions
in the SAME commit.

Purpose: POLISH-01, criteria 1 and 2. Fourteen identical suppressions exist because
`@tanstack/react-table@8.21.3` declares `TableMeta<TData>` as an **empty interface**
(`node_modules/@tanstack/table-core/build/lib/types.d.ts:31`), so `table.options.meta?.onEdit` has no
property to resolve against and every `meta:` literal in the app is currently unchecked in both
directions. Augmenting that interface is the library's own mechanism for this: it **removes** the
assertion rather than relabelling it, and it starts checking the producer as well as the consumer.

The atomicity is not a preference, it is measured. 43-RESEARCH § A1 ran a partial augmentation and
observed `TS2578: Unused '@ts-expect-error' directive` on all eight suppressions the probe did not
delete. The augmentation is global and instantaneous: the moment the `.d.ts` lands, every REMAINING
suppression becomes a compile ERROR for being unnecessary. So "add the type" and "delete the fourteen"
cannot be two tasks or two commits — either order leaves `tsc` red in between.

Output: `src/types/tanstack-table.d.ts`, three retyped columns modules, and a gate that holds the
count at zero without touching the two suppressions that are deliberate.
</objective>

<interfaces>
The exact `.d.ts` content, measured to produce `tsc --noEmit` exit 0 with all fourteen deletions and

```ts
// src/types/tanstack-table.d.ts
import type { ReactNode } from "react"
import type { RowData } from "@tanstack/react-table"

declare module "@tanstack/react-table" {
  interface TableMeta<TData extends RowData> {
    onEdit?: (row: TData) => void
    onDelete?: (row: TData) => void
    onSetDefault?: (row: TData) => void
    settingDefaultId?: string | null
    refresh?: () => void
    renderActions?: (row: TData) => ReactNode
  }
}
```

Every member above is required to be there, and every member is required to be OPTIONAL. Both halves
were measured:

| Member | Who needs it | What breaks without it |
|---|---|---|
| `onEdit`, `onDelete` | all five tables | the TS2339 this plan removes |
| `onSetDefault`, `settingDefaultId` | `admin/pipelines/data-table.tsx:114-118` | `TS2353: 'onSetDefault' does not exist in type 'TableMeta<Pipeline>'` — excess-property checking now applies to `meta:` literals |
| `refresh` | `organizations`, `people`, `admin/users` data-tables | TS2353 at three sites |
| `renderActions` | `src/app/trash/trash-table.tsx:355` | `TS2559: Type 'TrashTableMeta' has no properties in common with type 'TableMeta<TrashRow>'` — an all-optional non-empty interface is a WEAK TYPE, so an object sharing no member is rejected outright |

**Why no member may be required:** `src/app/admin/users/data-table.tsx:41` passes only
`meta: { refresh }`. A required `onEdit` gives it `TS2741`. Required members are enforced
per-consumer instead, in plan 43-02, with `Required<Pick<TableMeta<T>, …>>`.

**Generic, not flat.** `(row: TData) => void` means `Table<Pipeline>`'s `meta.onEdit` is
`(row: Pipeline) => void` automatically. A flat `(row: unknown)` interface would compile and hand
every consumer an unusable parameter.

**`src/types/` is the established home:** `src/types/next-auth.d.ts` and
`src/types/react-server-dom-webpack.d.ts` are the two existing `declare module` precedents.
`tsconfig.json`'s `include` is `**/*.ts` so it is picked up, and `eslint.config.mjs` ignores only
`next-env.d.ts` so it is linted — measured `eslint` exit 0 on exactly this content.
