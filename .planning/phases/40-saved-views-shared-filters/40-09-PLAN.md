## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| switch toggle → server action | `setViewShared` and `setViewDefault` are public endpoints; plan 40-06 authorizes independently |
| delete click → irreversible write | a shared view's deletion changes what every teammate sees |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-39 | Elevation of privilege | the share `Switch` and delete `Button` | mitigate | rendered only when `view.canEdit`, and **that is visibility only** — plan 40-06's `canMutateView` is the authorization. A row hidden in the UI is never the control |
| T-40-40 | Repudiation | a failed toggle | mitigate | the switch reverts to its previous position on failure, so the UI never asserts a state the database does not hold. Asserted structurally per handler |
| T-40-41 | Denial of service (functional) | dialog + list height | mitigate | two clamps: `max-h-[calc(100dvh-2rem)]` on the content and `max-h-[50vh]` on the list, so the footer survives any list length. Plan 40-15 measures it with ≥8 seeded views |
| T-40-42 | Tampering | the delete confirmation copy | mitigate | `views.delete.body`'s three clauses are transcribed whole; a shortened body would hide the shared-view blast radius or invite the belief that records were deleted |
| T-40-43 | Information disclosure | `views.manage.readOnly` `{owner}` | mitigate | `ownerLabel` is server-computed (`name \|\| email`, `null` when soft-deleted); a uuid never reaches this sentence |
| T-40-SC | Tampering | npm installs | mitigate | `dialog`, `alert-dialog`, `switch`, `button`, `label`, `separator`, `sonner` all exist. **Do not run `shadcn add`** (N-1): it bumps `radix-ui` and rewrites ~1184 lines of `package-lock.json` |
