<objective>
Add a `?view=<id>` carrier to the URL contract, so which view is open is something the URL says rather
than something inferred from filter equality — and "this view, modified" becomes a state that can
exist.

Purpose: plan 40-05 measured that `isModified` is structurally always `false`. `selectedViewId` was
derived from exact equality between the URL's validated filters and a view's stored filters, and
`computeIsModified` then compared those same two sets — so `selected && modified` is unrepresentable
by construction. Verified over 10 URLs x 3 views: 2 selections, zero modified. Three designed
surfaces are therefore unreachable: the "view selected, modified" state, slot 2's
`views.saveChanges` (B-5), and the save dialog's target `RadioGroup` (S-3/S-4). **"Update an existing
view" is impossible as currently wired.** The user was offered the choice and chose the URL carrier;
this plan implements it.

Output: two merged modules extended, two merged test files extended. No migration, no dependency, no
Docker rebuild, no schema change.
</objective>
