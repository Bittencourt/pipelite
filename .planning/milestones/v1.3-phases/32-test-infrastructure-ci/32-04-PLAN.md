    Rules and placement:
    - `react-hooks/set-state-in-effect` in `reset-password/page.tsx` — above the `setStatus("error")` call inside the `useEffect([token])`

    - `react-hooks/set-state-in-effect` in `profile-settings-form.tsx` — above the `setLocale(...)` call inside the `useEffect([initialSettings])`
    - `react-hooks/set-state-in-effect` in `relative-time.tsx` — above the `setMounted(true)` call inside the `useEffect([])`
    - `react-hooks/preserve-manual-memoization` in `import-wizard.tsx` — above the `handleMappingNext` `useCallback`

    The reason text must be specific to the site: what the effect actually does, why a mechanical fix is not safe inside an infrastructure phase, and that a proper fix is deferred. Examples of the required specificity (adapt to what you read, do not copy blindly):
    - `relative-time.tsx`: the `mounted` flag is a deliberate SSR/CSR hydration guard so the first paint renders an absolute date; removing the effect-set requires switching to `useSyncExternalStore` and re-verifying hydration.
    - `verify-email/page.tsx`: `verifyEmail` is a `const` arrow declared after the effect; hoisting it or wrapping it in `useCallback` changes identity semantics for a network call that must fire exactly once per token.
    - `import-wizard.tsx`: the compiler infers a `customFieldTypes` dependency the manual array omits; adding it re-creates the callback whenever `customFieldsByEntity` changes, which needs wizard step-transition testing that this phase does not have.

    - **Do not refactor any effect.** Do not move `verifyEmail` above the effect, do not add `customFieldTypes` to the `useCallback` dep array, do not replace the `mounted` guard. D-02 makes the refactor out of scope; a partial attempt is worse than an honest suppression.
    - Re-run eslint after each insertion. React Compiler rules sometimes report at a node one line off from where the comment must sit; if the error survives, move the comment rather than widening the suppression.

    Record all five suppression sites (file, rule, one-line reason) in the plan SUMMARY so Plan 32-05 can turn them into a single backlog entry.
