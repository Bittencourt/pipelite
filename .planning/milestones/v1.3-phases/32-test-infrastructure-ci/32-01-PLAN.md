<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build output (`.next/`) → test collection | Generated, gitignored artifacts were being executed as if they were reviewed source tests |
| `node_modules/` → test collection | Third-party vendored `*.test.js` files would execute in the developer's and CI's shell if the default exclude is dropped |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-01 | Tampering | `vitest.config.ts` `test.exclude` | mitigate | Spread `...configDefaults.exclude` rather than replacing it, so `node_modules/**` and `.git/**` stay excluded. Replacing would cause vitest to walk and **execute** arbitrary vendored test code from 1003 installed packages. Verified by the acceptance criterion `grep -c node_modules` on the collected file list returning 0. |
| T-32-02 | Tampering | `vitest.config.ts` `test.include` | mitigate | Anchoring `include` at `src/` means a stale, unreviewed copy of a test under `.next/standalone/` cannot influence the merge gate. Both `include` and `exclude` are kept so a single-key mistake cannot silently widen collection. |
| T-32-03 | Denial of Service | local + CI test run | mitigate | Same fix as T-32-01. An unbounded `node_modules` walk turns a 14 s suite into a multi-minute run and would make the CI required check time out at the 15-minute cap set in Plan 32-05. |
| T-32-04 | Repudiation | `package.json` `scripts.test` | mitigate | `vitest run`, never bare `vitest`. Watch mode never exits, so a CI step would hang until timeout and report an ambiguous failure rather than a truthful pass/fail. |
| T-32-SC | Tampering | npm/pip/cargo installs | accept | **This plan installs zero packages.** `vitest@4.0.18` and `typescript@5.9.3` are already in the committed `package-lock.json` from prior phases. The researcher confirmed no candidate package exists, so the Package Legitimacy Gate has nothing to audit. No install task appears anywhere in this plan. |
</threat_model>
