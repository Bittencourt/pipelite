<verified_commands>
**Reuse these verbatim. Every one was executed against this stack during research; do not re-derive,
re-order or "improve" them.** Where a flag looks redundant, the table below the block says what it
costs to omit.

Backup — Docker:
```bash
# Database. -Fc streams cleanly through `exec -T`: verified, 34,299,898 bytes, 9.0s,
# `file` reports "PostgreSQL custom database dump - v1.15-0".
docker compose exec -T postgres pg_dump -U pipelite -Fc pipelite > "pipelite-db-$(date +%F).dump"

# Uploaded files. A database-only backup restores rows pointing at files that are gone.
docker run --rm -v pipelite_uploads_data:/data:ro -v "$PWD:/backup" alpine:3 \
  tar czf "/backup/pipelite-uploads-$(date +%F).tar.gz" -C /data .
```

Restore — Docker, into a fresh empty database:
```bash
docker compose stop app                                        # nothing writes during the restore
docker compose exec -T postgres createdb -U pipelite pipelite
docker compose exec -T postgres pg_restore -U pipelite -d pipelite \
  --no-owner --no-privileges < pipelite-db-2026-08-23.dump
docker run --rm -v pipelite_uploads_data:/data -v "$PWD:/backup:ro" alpine:3 \
  tar xzf /backup/pipelite-uploads-2026-08-23.tar.gz -C /data
docker compose up -d app
docker compose logs --tail=20 app                              # migrate must report nothing to do
```

Bare metal:
```bash
sudo -u postgres pg_dump -Fc pipelite > "pipelite-db-$(date +%F).dump"
sudo -u postgres createdb pipelite
sudo -u postgres pg_restore -d pipelite --no-owner --no-privileges "pipelite-db-2026-08-23.dump"
sudo tar czf "pipelite-uploads-$(date +%F).tar.gz" -C "$UPLOAD_DIR" .
```

| Detail | Measured consequence of getting it wrong |
|---|---|
| service is `postgres`, not `db` | `docker compose exec -T db pg_dump --version` exits nonzero. The credentials `-U pipelite pipelite` ARE correct (`POSTGRES_USER=POSTGRES_DB=pipelite`); only the service name was wrong. |
| `--no-owner --no-privileges` **mandatory** | Restoring into a cluster whose superuser is not `pipelite`: **45 `ALTER … OWNER TO pipelite` errors and exit 1 — while restoring all the data correctly.** The worst outcome available, because it neither cleanly fails nor cleanly succeeds. With both flags: exit 0, 0 errors, byte-identical row counts. Harmless when the role names DO match. There is no case where omitting them is better. |
| `-Fc` | 34,299,898 bytes vs 121,722,344 plain (3.55×), zlib built in, selective restore via `pg_restore -l/-L`, and `--clean --if-exists` becomes possible at all. |
| **never** `--schema=public` / `-n` / `-t` | `drizzle.__drizzle_migrations` lives in its own `drizzle` **schema**. Narrowing the dump omits the migration ledger, and the container entrypoint's unconditional `npx drizzle-kit migrate` would then re-run all 20 migrations against restored data. With the whole database dumped it is a verified no-op (12 rows, `max(created_at)=1787441440793`, identical before and after). |
| **never** `-j` with `<` | `pg_restore: error: parallel restore from standard input is not supported`, exit 1. Measured `-j 4` from a file inside the container: 20.1s. Single-threaded from host stdin: 9.9s. At 228 MB it buys nothing. Mention it once, as a note, for tens-of-GB databases and only with the dump file copied inside the container first. |
| **never** `docker compose exec app tar …` | That runs as uid 1001. The `docker run --rm -v … alpine:3` form runs as root, which is why uid/gid 1001 ownership survives a `tar czf`/`tar xzf` round trip into a different fresh volume (verified). |
| `--clean --if-exists` | Second choice only, for restoring OVER an existing database. Verified idempotent (exit 0, row count unchanged); without `--clean` a re-restore is exit 1 with 193 errors. But it issues `DROP` statements against a live database, so a mistyped target turns a mistake into data loss. Lead with restore-into-a-fresh-database; never use it in a drill. |

Post-restore verification to document, in this order:
```bash
# 1. AUTHORITATIVE and it cannot be wrong: migrate must find nothing to do.
docker compose exec -T app npx drizzle-kit migrate

# 2. The restored database's recorded position.
docker compose exec -T postgres psql -U pipelite -d pipelite -qAt \
  -c "select count(*), max(created_at) from drizzle.__drizzle_migrations;"

# 3. Extensions, BEFORE restoring on managed Postgres.
docker compose exec -T postgres psql -U pipelite -d pipelite -qAt \
  -c "select name, default_version from pg_available_extensions where name in ('pg_trgm','unaccent');"
```
`drizzle/meta/_journal.json` is **[ASSUMED ABSENT] from the runner image** — the runner stage's `COPY`
lines are `drizzle.config.ts`, `src/db`, `package.json`, `node_modules`, and do NOT include `drizzle/`.
So do **not** write a verification step that reads the journal from inside the container without first
checking. If it is absent, tell the operator to read `drizzle/meta/_journal.json` from their git
checkout, which they have anyway. Step 1 leads because it is the check that cannot be wrong.

Row-count parity, for an operator who wants one number (this is the drill's own check, plan 43-05):
a md5 over per-table counts across BOTH the `public` and `drizzle` schemas, 37 tables in one line of
output. Say plainly in the doc that it does NOT verify column values — a checksum over counts is not
"identical database".

Extensions: `pg_trgm 1.6` and `unaccent 1.1` are created by `drizzle/0016_dedup_functions.sql:31-32`
and both are `trusted = true` on PostgreSQL 16 (read from the container's `.control` files), so a
database owner can create them **without superuser**. Do not tell operators to use a superuser.
[ASSUMED] Managed providers (RDS, Cloud SQL, Neon, Supabase) gate extensions on their own allow-list
regardless of `trusted`; `pg_trgm` and `unaccent` are on essentially every such list but this was not
verified against any provider — so the doc tells the operator to run the `pg_available_extensions`
query first, which is correct advice either way. And say explicitly that a failed `CREATE EXTENSION` is
**not** salvageable by ignoring it: 38 dependent routines and the dedup indexes go with it.
