<objective>
Create the single floating bulk action bar: one component, four surfaces, three actions plus Clear,
owning both dialogs, the in-flight state, the over-cap state, and the CSV download.

Purpose: this is the load-bearing layout decision of the phase and the one integration point each
surface mounts. A fixed bottom bar is chosen because the two alternatives fail concretely: a row
inserted above the table would push every row down ~48px WHILE the user is mid-selection, so the
second checkbox they aim at sits under a different record; and both alternatives scroll out of view
long before the user finishes selecting on a list that accumulates 150+ rows through Load More.
Output: one `'use client'` component plus a comment-stripped source gate.

Return `null` when `selectedIds.length === 0` — 38-UI-SPEC: with nothing selected the bar is ABSENT
from the DOM, along with its spacer. No reserved strip, no ghost bar.

Layout contract, verbatim from 38-UI-SPEC § Surface 3 with the D-22 z-index correction applied:
  outer:   fixed inset-x-4 bottom-4 z-[60] mx-auto w-fit max-w-[calc(100%-2rem)]
           rounded-lg border bg-card shadow-lg
  a11y:    role="region" aria-label={t("actionBarLabel", { count })}
  inner:   flex flex-wrap items-center justify-center gap-2 p-2
  count:   <span className="text-sm leading-tight font-semibold px-1">{t("selected", { count })}</span>
  spacer:  a sibling <div aria-hidden className="h-20" /> rendered AFTER the fixed div

**z-[60], NOT z-30.** This is D-22, found during 38-PATTERNS and measured: `ShortcutsHint`
(src/components/keyboard/shortcuts-hint.tsx:33, mounted at src/app/layout.tsx:53) is
`fixed bottom-0 left-0 right-0 z-50` for the first 10 seconds of any session whose
`localStorage.pipelite_shortcuts_hint_dismissed` flag is unset, so on a fresh browser profile a `z-30`
bar renders BEHIND it. `z-[60]` is deterministic and couples nothing; the hint still auto-dismisses.
A z-index is not a spacing token, so this does not touch the UI-SPEC spacing exception list.

**No change to `<Toaster />`.** Sonner's own container carries `z-index: 999999999`
(node_modules/sonner/dist/styles.css), so a toast always renders above the bar regardless of the bar's
z-index and regardless of the default bottom-right position. 38-UI-SPEC's checklist item "the bar does
not cover the Sonner toast region" is satisfied structurally (D-23).

`max-w-[calc(100%-2rem)]` + `flex-wrap` is a HARD requirement, not styling: a `fixed` element that
exceeds the viewport DOES contribute to `document.scrollWidth`. At 320px the bar must wrap to two or
three lines and never scroll horizontally.

Controls, left to right (38-UI-SPEC § Surface 3). Every one carries a VISIBLE text label — no
icon-only buttons anywhere, because no tooltip primitive is vendored (`"registries": {}`) so a label is
the only reachable accessible name, and a bare red trash glyph floating over the user's data is the
single most dangerous unlabelled control this phase could ship:
  1  count            a <span>, Label 14/600
  2  Reassign owner   Button variant="outline" size="sm"   UserPen h-4 w-4     bulk.reassignOwner
  3  Export CSV       Button variant="outline" size="sm"   Download h-4 w-4    bulk.exportCsv
  4  Delete           Button variant="ghost" size="sm" + className="text-destructive hover:text-destructive"
                                                          Trash2 h-4 w-4      bulk.delete
  5  Clear selection  Button variant="ghost" size="sm"     X h-4 w-4           bulk.clearSelection

The bar has ZERO accent-filled and zero destructive-filled controls, deliberately: it floats above the
rows with `bg-card shadow-lg` so it already has the strongest visual weight on the page, and a filled
button inside it would read as the page's dominant element while sitting permanently over the user's data.

Download helper to copy (src/app/admin/export/export-form.tsx:31-40) — do NOT write a third variant:
  Blob -> URL.createObjectURL -> a synthetic <a download> appended to body -> click -> remove ->
  URL.revokeObjectURL. The CSV mime string, verbatim from :42-46, is "text/csv;charset=utf-8;".

Toast pattern to copy (src/app/trash/trash-table.tsx:178-241): `startTransition`, `toast.success(...,
{ action: { label, onClick } })`, and a SECOND `toast.warning(...)` for a shortfall. `toast.warning` is
already in production use in this repo, so 38-UI-SPEC assumption #6 is confirmed by a call site rather
than only by the type surface.

Trash deep link: `ENTITY_TO_TRASH_TAB` from `@/lib/trash/entity-types` (the CLIENT-SAFE sibling —
importing `@/lib/trash/dispatch` here would pull `@/db` into the client bundle). Navigate to
`/trash?tab=${ENTITY_TO_TRASH_TAB[entityType]}` (D-09).
