<objective>
Add `updateOrganizationOwnerMutation` and `updatePersonOwnerMutation` — two narrow single-field
mutations — and pin the emitted payload shape with a `buildChanges` gate in `diff.test.ts`.

Purpose: this is the phase's single most important correctness fix. `ownerId` is ABSENT from
`organizationSchema` and `personSchema`, and Zod's default object mode strips unknown keys silently,
so `updateOrganizationMutation(id, { ownerId }, userId)` returns `{ success: true }` having written
only `updatedAt`, emits an empty diff, and the audit subscriber drops the row entirely. A bulk
reassign built on the existing update mutations would report success, change nothing, write no audit
row, and keep the whole 1703-test suite green. Verified by executable Zod probe in 38-RESEARCH
Pitfall 1.
Output: two new mutations, their unit coverage, and a pure `diff.ts` gate proving the audit row lands.
</objective>

Target signature, identical for both entities:

  export async function updateOrganizationOwnerMutation(
    id: string,
    ownerId: string,
    userId: string,
  ): Promise<{ success: true } | { success: false; error: string }>

  export async function updatePersonOwnerMutation(
    id: string,
    ownerId: string,
    userId: string,
  ): Promise<{ success: true } | { success: false; error: string }>

Module-private helper already present in each mutation module (positional, do not change it):

  function buildEventPayload(
    entityId: string,
    action: "created" | "updated" | "deleted",
    data: Record<string, unknown>,
    userId: string,
    changedFields: string[] | null = null,
    previous?: Record<string, unknown>,
  ): CrmEventPayload

Audit diff contract (src/lib/audit/diff.ts:136-146) — for an UPDATE, `before` comes from
`payload.previous` and `after` from `payload.data`, and native keys ABSENT from `data` are skipped
on updates only. That is why `data` must be the FULL post-write row, not `{ id, ownerId }`.

Column facts, all four entities: `owner_id text NOT NULL REFERENCES users(id)`. There is no
nullable owner, so there is no unassign.

`ownerId` is absent from `ENTITY_NATIVE_ATTRIBUTES` for all four entities
(src/lib/formula-recalc.ts:103-130), so `changedFields: ["ownerId"]` scopes formula recalculation
to zero evaluations. Passing it is correct and costs nothing.

| mutation → crmBus subscribers | The emitted payload is the only evidence the audit subscriber has; a narrow payload silently narrows the audit record |
