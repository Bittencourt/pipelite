<objective>
Migrate the eight `src/lib/dedup` modules — 28 of the phase's 273 `console.*` call sites — and repair
the verification gate this migration breaks.

Purpose: OBS-01, plus two of amendment A7's three sites.

A7 matters here more than anywhere else. `cleanupStaleDedupScans` is one of the two one-shot boot
cleanups that CONTEXT correctly excludes from `/api/health`, which means its ONLY verification is a
container log grep — and `src/lib/dedup/scan-cleanup.ts` spends nineteen lines arguing for exactly that
gate, naming `grep -F '[dedup-scan-cleanup] Starting'`. This migration changes that string. The comment
and the test header are prose, invisible to `no-console`, so nothing forces the update. Breaking the
string without replacing it silently removes the only check the reaper has.

**A correction to the source artifacts, found while planning:** PATTERNS names one orphaned prefix
constant (`scan-cleanup.ts`'s `LOG`). There are in fact **eight** — every module in this directory
declares its own `LOG` or `LOG_PREFIX`, and all eight become unused the moment their last call site
migrates. `no-unused-vars` will flag each one, so all eight must be deleted in this plan.

Output: eight migrated modules with their prefix constants removed, a repaired gate comment, and six
updated test files.
</objective>

<migration_contract>
Signature: `log.<level>(scope, msg, ctx?)` — exactly three arguments, the error ALWAYS under `ctx.err`.
Import: `import { log } from "@/lib/log"`.
Level map: `console.error`→`log.error`, `console.warn`→`log.warn`, `console.log`→`log.info`,
`console.info`→`log.info`. **A warn stays a warn.**

**Scope rule.** Every site in this directory interpolates a module-level prefix constant. Harvest the
bracket name from that constant verbatim — read the constant, do not guess from the filename. The eight
constants and their names are listed in the site inventory below.

**Message rule.** The trailing `:` leaves the message. The `${LOG}` / `${LOG_PREFIX}` interpolation
disappears entirely (the scope field replaces it). Every OTHER interpolated value — `scanId`,
`entityType`, `pairId`, a field name, a count, an outcome — moves out of the string into a named `ctx`
key, and the message becomes a fixed string. **Never add a value that was not already in the string.**
`scan-cleanup.ts:36` states the standing constraint for this directory: logs carry counts only, never
row contents (T-37-09).

**Constant deletion.** After a file's last site migrates, delete its `LOG` / `LOG_PREFIX` declaration.
Check for other uses first — if a constant is referenced anywhere besides the migrated log calls, keep
it and say so in the summary.

**Control flow rule.** Byte-for-byte equivalent. Swallow-and-log catches keep swallowing. In
`scan-cleanup.ts` the startup line is OUTSIDE the try/catch on purpose (stated at lines 33-36): if it
sat after the first query, a DB hiccup at boot would make the gate report that the reaper never ran.
Keep it where it is.
</migration_contract>
