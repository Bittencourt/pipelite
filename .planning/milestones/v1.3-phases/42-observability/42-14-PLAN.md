<migration_contract>
Signature: `log.<level>(scope, msg, ctx?)` — exactly three arguments, the error ALWAYS under `ctx.err`.
Import: `import { log } from "@/lib/log"`.
Level map: `console.error`→`log.error`, `console.warn`→`log.warn`, `console.log`→`log.info`,
`console.info`→`log.info`.

**Scope rule**, identical to plans 10, 11 and 15. A `[bracket]` prefix already in the string always
wins. Otherwise derive from the module path: strip the leading `src/`, strip a leading `app/`, strip a
trailing `/route.ts` or `/page.tsx` or the file extension, and keep every remaining segment verbatim
including dynamic segments. Worked examples: `src/app/import/actions.ts` → `import/actions`;
`src/app/admin/pipelines/actions.ts` → `admin/pipelines/actions`;
`src/app/admin/fields/[entityType]/trigger-child-guard.ts` → `admin/fields/[entityType]/trigger-child-guard`;
`src/actions/user-settings.ts` → `actions/user-settings` (no `app/` to strip).

**Message rule.** The trailing `:` leaves the message. Interpolated values move into named `ctx` keys.
**Never add a value that was not already in the string.** These are import paths: a row, a column
value or a parsed CSV cell must never enter `ctx`.

**Control flow rule.** Byte-for-byte equivalent. Every site here sits in a catch that returns
`{ success: false, error }` or deliberately swallows; the return shape and the catch structure are
unchanged.
</migration_contract>

<client_component_note>
`src/app/admin/import/pipedrive-api/pipedrive-api-wizard.tsx` is a `"use client"` component and is one
of the eight client-side call sites in the whole migration. Three rules apply:

- **Same code path as the server. No `typeof window` branch, no separate output contract.** The logger
  is environment-agnostic — `console.*` plus `JSON.stringify` plus `Date`, zero imports — so
  `log.error(scope, msg, { err })` behaves identically in the browser. An isomorphic logger with two
  output formats was considered and rejected as unearned complexity for eight diagnostic call sites.
- `import { log } from "@/lib/log"` in a `"use client"` file is valid **only because** `log.ts` has zero
  imports. That is the reason its zero-dependency header is a hard rule rather than a style preference.
- Line 76 logs `result.error`, not a caught `Error`. Carry exactly that value; do not wrap it in a
  synthetic `Error` and do not pass the whole `result`.
</client_component_note>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| uploaded CSV → import actions → log line | The most data-dense path in the application. Every catch in `import/actions.ts` has parsed rows in scope. |
| admin invite / approval flow → email-send catch | A recipient address and an invite token are in scope at both `admin/users/actions.ts` sites |
| browser → `pipedrive-api-wizard.tsx` | A client component whose log output lands in the user's browser console, not in container stdout |
| admin form input → pipeline/stage actions | Names and ordering values typed by an administrator |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-42 | Information disclosure | the eight `src/app/import/actions.ts` sites | mitigate | No row, filename, column or parsed cell enters `ctx` — none is in the current strings. Enforced by a grep criterion over the file. An import log line carrying row contents would disclose customer data at the highest volume of any path in the app. |
| T-42-43 | Information disclosure | `admin/users/actions.ts` × 2 | mitigate | `err` is the only `ctx` key. An invite token in a log line is a credential that grants account creation; a recipient address is PII. Both are in scope at these catches and neither is in the current string. Both migrated lines must be quoted verbatim in the summary. |
| T-42-44 | Information disclosure | the client-component log line | accept | `pipedrive-api-wizard.tsx`'s output goes to the browser console of the administrator who triggered the action, and carries `result.error` — the same value it carries today. The decision to emit JSON in the browser rather than branch on `typeof window` is recorded in RESEARCH as assumption A5 and is reversible in one commit. |
| T-42-04 | Information disclosure | the remaining eleven sites | mitigate | Each logs exactly what its original string logged. Pipeline and stage names are not added to `ctx`. |
| T-42-05 | Tampering / Repudiation | CSV cell content and admin-typed names reaching a log line | mitigate | Inherited from plan 01: `JSON.stringify` escapes newlines. A CSV is the most plausible source of newline-bearing text in this application, so this is the file set where log-line forgery was most reachable before the phase. |
| T-42-41 | Tampering | the four `[audit-import]` swallows | mitigate | All four keep swallowing. The import rows are already committed when these catches run; converting one to a rethrow would fail an import that actually succeeded, leaving the operator to re-run it against already-imported data. |
</threat_model>
