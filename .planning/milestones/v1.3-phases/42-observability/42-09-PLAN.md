<migration_contract>
Signature: `log.<level>(scope, msg, ctx?)` — exactly three arguments, the error ALWAYS under `ctx.err`.
Import: `import { log } from "@/lib/log"`.
Level map: `console.error`→`log.error`, `console.warn`→`log.warn`, `console.log`→`log.info`,
`console.info`→`log.info`.

**Scope rule.** A `[bracket]` prefix ⇒ use that name verbatim as `scope`; no bracket ⇒ derive from the
module path with `src/` and the extension stripped and `/` kept. **ONE FILE MAY MIX BOTH** — never
blanket-apply a per-file scope.

**Message rule.** The trailing `:` leaves the message. Interpolated values move OUT of the string into
named `ctx` keys. **Never add a value that was not already in the string.**

**Control flow rule.** Byte-for-byte equivalent. A swallow-and-log catch keeps swallowing; a
`.catch(...)` stays attached; never turn a swallow into a rethrow. Read any header comment above a
catch before touching it.

**Style rule.** Match the surrounding file's quote style. Do not reformat anything you are not migrating.
</migration_contract>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user form input / API request body → mutation function → log line | CRM write paths; every value in scope at a catch site is potentially a customer record field |
| merge candidate pair → dedup merge path → log line | The merge path holds two full records at once, making it the highest-exposure logging surface in this file set |
| application → container stdout | Migrated lines cross into Docker's json-file driver |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-04 | Information disclosure | the 24 migrated call sites, and `dedup.ts` above all | mitigate | Each site logs exactly what its original string logged. The dedup merge path has both the surviving and the merged record in scope; neither is added to `ctx`. Enforced by the `git diff` criterion and by the rule that any new `ctx` key must be quoted in the summary with its original string. |
| T-42-05 | Tampering / Repudiation | user-controlled text reaching a log line | mitigate | Inherited from plan 01: `JSON.stringify` escapes newlines, so an organization name or activity note containing a newline cannot forge a second log line. |
| T-42-27 | Tampering | control flow of the destructive merge path | mitigate | Byte-for-byte equivalent control flow. The catches at `dedup.ts:649` and `:688` swallow deliberately so a failed post-merge step cannot undo a completed merge; converting either to a rethrow would leave the CRM in a half-merged state. The existing `src/lib/mutations` and `src/lib/dedup` suites are the regression detector. |
| T-42-28 | Repudiation | loss of the `[audit]`, `[formula-recalc]` and `[dedup-merge]` scope names | mitigate | Eight of these 24 sites carry scope names that file headers, runbooks and test assertions refer to by name. Preserving them verbatim as `scope` keeps every existing operational query answerable. Enforced by the exact-scope-set criterion per file. |
</threat_model>
