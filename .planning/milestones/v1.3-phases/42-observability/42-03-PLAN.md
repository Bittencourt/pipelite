<objective>
Land every configuration and dependency change the phase needs, in one plan that owns all five shared
root files so no other plan has to touch them.

Purpose: two of these are load-bearing rather than housekeeping.

Amendment A5: `docker-compose.yml` enumerates its eleven environment variables one by one and has no
`env_file:`. A variable that is not listed simply never reaches the container. Without this change,
`LOG_LEVEL=debug` in `.env` would change nothing and `SENTRY_DSN` would never be seen — both features
would appear to work while neither functioned, and nothing would fail.

The `@sentry/nextjs` install must land before plan 04 writes `src/lib/observability/sentry.ts`,
because `await import("@sentry/nextjs")` has to typecheck. It adds 104 packages and mutates
`package-lock.json`; CI runs `npm ci`, which fails on any lockfile/manifest mismatch, so the lockfile
is committed here.

Amendment A8 constrains this plan as much as it directs it: add NO healthcheck to the `app` service.
Combined with `restart: unless-stopped`, a healthcheck on an endpoint that legitimately returns 503
when a daily pruner reads stale could restart-loop the container, turning an observability feature
into an outage.

Output: env pass-through, documented example values, the Sentry dependency, and a Dockerfile that
fails loudly on the exact silent breakage this phase exists to detect.
</objective>
