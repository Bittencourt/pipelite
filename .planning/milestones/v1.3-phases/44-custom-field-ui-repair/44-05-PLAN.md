<objective>
Turn Radix's silent `null` into a loud development-time failure (D-44-03).

Purpose: when `DialogTrigger asChild` receives something that is not a valid React element,
`SlotClone` returns `null` — no throw, no `console.error`, no dev warning. That silence is why
CFUI-01 cost a full browser end-to-end pass to find. This plan adds a dev-only guard so any future
regression announces itself in the console during development. It is deliberately **not** a
production throw: the user's decision is explicit that converting a degraded page into a hard crash
for end users is not worth it.

Output: a pure, unit-tested guard called from `FieldDialog`. Production rendering is byte-identical.
</objective>

The predicate Radix itself uses, from `node_modules/@radix-ui/react-slot/dist/index.js`:

```js
if (React.isValidElement(children)) { ... return React.cloneElement(children, props2) }
return React.Children.count(children) > 1 ? React.Children.only(null) : null
```

The call site to guard, `src/app/admin/fields/[entityType]/field-dialog.tsx:146-148`:

```tsx
return (
  <Dialog open={open} onOpenChange={setOpen}>
    <DialogTrigger asChild>{children}</DialogTrigger>
```

`FieldDialog` has two callers today: `page.tsx` (a **server** component — the broken one, repaired
by plan 44-06) and `fields-list.tsx` (a client component, always correct because its children are
created in the browser and never serialized).

What a Flight-deferred child looks like at runtime — the exact value the guard must catch:
`{ $$typeof: Symbol.for('react.lazy'), _payload, _init }`. `isValidElement` is `false` for it and
`React.Children.count` is `1`, which is why Radix's early-out fires.
