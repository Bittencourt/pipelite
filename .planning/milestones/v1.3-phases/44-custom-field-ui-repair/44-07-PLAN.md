<objective>
Wire the client display to the server's answer — the last mile of CFUI-02 and CFUI-03.

Purpose: two lines in `custom-fields-section.tsx` are the reason the UI disagrees with the database.
`allFieldValues` is `{...entityAttributes, ...localValues}` with no `null` seed and no unwrapping, so
an unset source produces `#ERROR — Unknown field: X` (CFUI-03). And `localValues` is
`useState(values)`, merged only with the key the user edited and never re-synced, so the stored
formula wrapper it holds is the one from page load — the display is literally one save behind
(CFUI-02 Part B). Plan 44-02 made the server return the recomputed blob and plan 44-03 built the
seeding helper; this plan connects them.

Output: the component seeds its evaluation map exactly as the server does and takes the server's
recomputed values as authoritative after every save.
</objective>

The two lines being replaced, `custom-fields-section.tsx:50-53` and `:55-73`:

```tsx
const allFieldValues = useMemo(() => ({ ...entityAttributes, ...localValues }), [entityAttributes, localValues])

const handleSave = useCallback(async (fieldName: string, value: unknown) => {
  const newValues = { ...localValues, [fieldName]: value }
  setLocalValues(newValues)
  try {
    const result = await saveCustomFields(entityType, entityId, newValues)
    if (result.success) { onValuesChange?.(newValues) }
    else { console.error('Failed to save field:', result.error); setLocalValues(values) }
  } catch (error) { console.error('Failed to save field:', error); setLocalValues(values) }
}, [entityType, entityId, localValues, values, onValuesChange])
```

The local `saveCustomFields` fetch wrapper at the top of the file types the response as
`{ success: boolean; error?: string }` — widen it to carry `values?: Record<string, unknown>`.

Why `formula-field.tsx` needs no change: with the merge in place, the `{formula:true,...}` wrapper
in `localValues` is always the one the server just wrote, so its cached branch displays the fresh
value. The live branch stays as the pre-first-save fallback and becomes correct because the map it
evaluates over is now seeded.

Deliberately NOT done here (RESEARCH ranked these and rejected them): `revalidatePath` in the route
handler does not push a fresh RSC payload to a mounted client; `router.refresh()` refreshes the
`values` prop, which `useState(values)` permanently shadows, and refetches the whole detail page for
one field; converting to a Server Action is a larger blast radius than this phase needs.
