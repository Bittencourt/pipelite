# Phase 37 — UI Design Contract

> Visual and interaction contract for the `/trash` recovery surface, its restore and purge actions,
> the trash nav entry, and the `/admin/trash` retention control.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Sources:** `37-CONTEXT.md` (16 locked decisions — none re-asked, none re-litigated here),
`.planning/REQUIREMENTS.md` (TRASH-01..03), `.planning/ROADMAP.md` (Phase 37 SC-1..SC-4), and —
above all — **`36-UI-SPEC.md`**, whose spacing scale, type roles, colour reserve, copy rules and
accessibility contract this phase inherits wholesale.

**Inheritance is the governing rule of this document, exactly as it was for Phase 36.** Phase 35
declared the scale, Phase 36 restated it for a second set of surfaces, and this phase restates it for
a third. Where a section below repeats an inherited value it is to make the executor's job
single-file; where it *adds* something, the addition is called out and justified. Nothing here
contradicts `36-UI-SPEC.md`.

**No new dependencies. No new shadcn component. No new registry fetch.** Every primitive these
surfaces need is already vendored in `src/components/ui/` — including `tabs.tsx` and `table.tsx` —
and `components.json` declares `"registries": {}` (verified 2026-08-16).

## Spacing Scale

Identical to `36-UI-SPEC.md` and `35-UI-SPEC.md`. All multiples of 4.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | `gap-1` icon↔label inside badges; `mt-1` from a record name to its linked-in-trash badge |
| sm | 8px | `gap-2` between the two row-action buttons, between tab icon and label, between the page-header icon tile and its text block; `p-2` `TableCell` padding (from `table.tsx`); `space-y-2` inside the retention card |
| md | 16px | `space-y-4` on the table block (matches the four existing data tables); `mt-4` on `TabsContent`; `mb-4` above a table |
| lg | 24px | `space-y-6` page shell; `px-6` / `py-6` `Card` padding (from the `Card` primitive) |
| xl | 32px | `py-8` container padding on `/trash` (matches `organizations/page.tsx:73`); `h-8` row-action buttons (`size="sm"`); `gap-x-8` in the retention cost `<dl>` |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used (no textarea on any surface in this phase) |

**Exceptions: two, both inherited, neither introduced here.**

1. **32px row controls.** The `Restore`, `Restore with linked records` and `Delete permanently` row
   actions render at `size="sm"` (32px tall) — below the 44px touch guidance. Accepted for exactly
   the reason Phase 35 and Phase 36 accepted it: desktop-first CRM, the controls are **always
   visible** (never a hover-only reveal), and every control in a dialog or on `/admin/trash`
   (the number `Input`, its Save button, the `AlertDialog` buttons) is ≥36px.
2. **`h-24` on the empty-table cell** is inherited verbatim from the four existing data tables.
   96px is 4×24, so it is inside the scale and is listed here only so nobody flags it as novel.

No other exception. Every value on all six surfaces is one of the seven declared tokens.

## Typography

Five roles, four sizes, two declared weights, two declared weight exceptions.

| Role | Size | Weight | Line Height | Tailwind | Applies to |
|------|------|--------|-------------|----------|-----------|
| Display | 30px | 700 *(exception 2)* | 1.2 | `text-3xl font-bold` | The `<h1>` on `/trash` and on `/admin/trash` |
| Heading | 16px | 600 | 1.25 | `text-base font-semibold leading-tight` | The two `/admin/trash` card titles |
| Label | 14px | 600 | 1.25 | `text-sm leading-tight font-semibold` | **The record name in every trash row**; the two retention stat values |
| Body | 14px | 400 | 1.5 | `text-sm leading-normal` | Every other table cell; page descriptions; dialog descriptions; empty-state body |
| Meta | 12px | 400 | 1.33 | `text-xs` | Timestamps, tab counts, badge text, retention helper text, stat labels |

**Declared weights: 400 (normal) and 600 (semibold).**

**Weight exception 1 (inherited, three sources, one value).** 500 (`font-medium`) is hardcoded in
shared primitives this phase declines to patch: `button.tsx` base class, `table.tsx` `TableHead`, and
`tabs.tsx` `TabsTrigger`. Every button label, every column header and every tab label therefore
renders at 500. Phase 35 and Phase 36 both took this posture toward `button.tsx`; this phase extends
it to two more primitives of the same kind. **It is the same exception, not a new one** — no new
weight value enters the product.

**Weight exception 2 (inherited).** The two `<h1>`s use `text-3xl font-bold` (700). This is not a
choice this phase makes; it is the class string every page-level heading in the app already carries —
`organizations/page.tsx:80`, `admin/page.tsx:51`, `admin/audit/page.tsx:62`, users, fields, pipelines,
webhooks. A seventh admin page or a fifth list page whose title alone sat at 600 would read as a
rendering bug rather than as restraint.

**Two exceptions is the ceiling, and neither is this phase's invention.** A later phase citing this
document should read it as "inherit an existing exception, never mint a new one".

**The record name is Label (14/600), not Body.** In a five-column table the name is the only thing
the user is scanning for, and it is this page's primary visual anchor (see § Color). Every other cell
— deleted-at, deleted-by, the secondary column — is Body or Meta and muted, so the name column is the
strongest contrast in the block. `TableCell` is `whitespace-nowrap` by default; the name cell
**must** override to `whitespace-normal` so the linked-in-trash badge can sit under a long title.

## Color

| Role | Token | Value (light) | Usage |
|------|-------|---------------|-------|
| Dominant (60%) | `--background` / `--card` | `oklch(1 0 0)` | Page background; the card wrapping each tab's table; both `/admin/trash` cards |
| Secondary (30%) | `--muted` / `--border` | `oklch(0.97 0 0)` / `oklch(0.922 0 0)` | The `TabsList` track (`bg-muted`); every table border and row divider; row hover (`hover:bg-muted/50`, from `table.tsx`); the linked-in-trash and actor-kind badges (`variant="secondary"`); every timestamp, every "Not recorded", every empty secondary cell (`text-muted-foreground`) |
| Accent (10%) | `--primary` | `oklch(0.205 0 0)` | See reserved list |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` | See reserved list |

**Accent (`--primary`) reserved for exactly four things in this phase — nothing else:**

1. **The `/trash` page-header icon tile** — `<div class="p-2 bg-primary/10 rounded-lg">` containing
   `Trash2 h-6 w-6 text-primary`. This is the header idiom every user-facing list page already uses
   (`organizations/page.tsx:76-78`, and its siblings on people and deals). `/trash` is a sibling of
   those four pages and joins their decision. `/admin/trash` gets a **bare `<h1>` with no icon tile**,
   because that is the idiom of the six existing `/admin/*` pages. Two shells because there are two
   established shells; this phase mints neither.
2. **Save retention window** on `/admin/trash` — `Button variant="default"`, the only filled
   `--primary` element this phase adds.
3. The keyboard focus outline, already global (`globals.css:154`, `2px solid var(--primary)`).
4. Nothing else.

**`/trash` itself has zero accent-filled controls, and that is deliberate.** A `variant="default"`
Restore button repeated down fifty rows would put the accent on ~40% of the page's pixels, which is
the 10% rule inverted. `Restore` is therefore `variant="outline"` and `Delete permanently` is
`variant="ghost"`. The page's **primary visual anchor is the column of record names** at Label 14/600
against Body/Meta muted everywhere else — the same argument `36-UI-SPEC.md` makes for the
records-changed panel, and the correct one here, because the user's question on this page is
literally "which record".

**Explicitly not accent:** the tab indicator (Radix's active state is
`data-[state=active]:bg-background` + `text-foreground` on a `bg-muted` track — background, not
primary; do not "fix" this to primary), the record names (they are **not links** — see
§ Surface 1), the `Trash2` icon in the admin sidebar, the trash entry in the user menu.

**Destructive (`--destructive`) reserved for exactly four things:**

1. The **`Delete permanently` row action** — `Button variant="ghost" size="sm"` with
   `className="text-destructive hover:text-destructive"`. Text-only, no fill. This is one more
   sanctioned destructive use than Phase 36 declared, and it is declared here rather than allowed to
   appear undeclared. It is admissible because it is the **only** thing distinguishing an
   irreversible action from a reversible one in a row that offers both, because it is text and not
   fill (≈110×20px of red text per row, on admin views only), and because it matches the existing
   `text-destructive` ghost row action in `organizations/columns.tsx:121`.
2. The `AlertDialogAction` confirm button in the **purge** dialog (filled,
   `bg-destructive text-destructive-foreground hover:bg-destructive/90`).
3. The `AlertDialogAction` confirm button in the **shorten-retention** dialog on `/admin/trash`.
4. Sonner `toast.error(...)`, owned by the `sonner.tsx` primitive.

**Never destructive:** the `Trash2` icon in the nav entry or the admin sidebar (a route is not a
danger), the linked-in-trash badge (a trashed parent is a **fact**, not a warning — the same reason
Phase 36 refused `variant="destructive"` on a completed-deletion badge), the retention `Input`'s
out-of-range state (the always-visible helper text and the disabled Save button are the message), or
any trash row itself. **A trashed record must not be rendered in red.** It is not an error; it is a
record waiting to be recovered, and colouring the whole page as danger would make the one genuinely
dangerous control invisible.

**Forbidden:** any hardcoded hex, `bg-white`, `text-black`, `text-red-*`, `text-green-*`,
`bg-red-*`, `bg-green-*`, or any colour outside the token set anywhere in the six surfaces.

## Surface 1 — `/trash`

### Route and tab mechanics

**One route, `?type=` search param, four tabs.** `37-CONTEXT.md` locks the one-route/four-tabs shape
and grants discretion over the mechanics. The mechanics are:

| Decision | Value |
|----------|-------|
| Param | `?type=deals` \| `people` \| `organizations` \| `activities`. Absent or unrecognised → `deals` |
| Component | `Tabs` with a **controlled `value`** + `onValueChange` → `router.push`. Never `defaultValue` |
| Activation | `activationMode="manual"` — **required**, not optional |
| Paging | `?type=…&page=N`, `Load more` button, page size **50** (matching the four existing list tables) |
| Mounted content | **Only the active tab's `TabsContent` is rendered.** The other three values simply have no content node |
| Ordering | `deleted_at` **descending**, always. No sort control |

**Why the URL and not React state** — the same reasoning `36-UI-SPEC.md` § Surface 4 records, and it
applies here for stronger reasons: the rows, the page cursor and every tab's count are computed by
one server render, so they cannot disagree; first paint stays server-rendered with no skeleton;
switching tabs resets paging to page 1 for free; and "look at what's in trash" is a shareable link.

**Why `activationMode="manual"` is required.** Radix `Tabs` defaults to `automatic`, which selects on
focus. With tab changes wired to `router.push`, arrowing across four tabs would fire four server
navigations. `manual` moves focus with the arrow keys and activates on Enter/Space — one navigation,
one round trip. This is a performance decision *and* an accessibility one, and it must not be dropped.

**Only the active tab is queried.** The four tab labels carry counts, which come from four cheap
scoped `count(*)` reads; the rows come from one query for the active type only. Fetching four tables
to show one is the obvious wrong turn here, and this line exists so it is not taken.

### Page anatomy

```
<div class="container py-8">
  <div class="space-y-6">
    <div class="flex items-center gap-3">                      ← the list-page header idiom
      <div class="p-2 bg-primary/10 rounded-lg"><Trash2 class="h-6 w-6 text-primary" /></div>
      <div>
        <h1 class="text-3xl font-bold">        {t('trash.title')}
        <p  class="text-muted-foreground">     {t('trash.description')}

    <Tabs value={type} onValueChange={…} activationMode="manual">
      <TabsList>
        <TabsTrigger value="deals" class="gap-2">
          <Kanban class="h-4 w-4" aria-hidden="true" /> {tNav('deals')}
          <span class="text-muted-foreground text-xs">({dealsCount})</span>
        … three more
      <TabsContent value={type} class="mt-4">
        <Card><CardContent>  <TrashTable … />  </CardContent></Card>
```

**Tab labels reuse the existing `nav.*` keys** — `nav.deals`, `nav.people`, `nav.organizations`,
`nav.activities` — not four new ones. This is not key-thrift: it guarantees the tab is named
identically to the nav item the record returns to, which is the sentence the restore toast then
repeats. Tab icons are the app's own nav vocabulary (`nav-header.tsx:9`): `Kanban`, `Users`,
`Building2`, `CheckCircle2`. **Zero new symbols enter the product.** All are `aria-hidden="true"`.

**Tab counts are scoped exactly as the rows are** — owner-or-admin, per `37-CONTEXT.md`. A tab that
says `Deals (12)` above a table a non-admin can only see 3 rows of is a defect the user can see and
cannot explain. This is the same rule `36-UI-SPEC.md` states for `Timeline (N)`.

### Columns

Four shared columns plus one entity-appropriate secondary, per `37-CONTEXT.md`.

| # | Column | Header key | Content |
|---|--------|-----------|---------|
| 1 | Record | `trash.column.{deal\|person\|organization\|activity}` | Name/title at **Label 14/600**, plus the linked-in-trash badge below it when applicable. `whitespace-normal` |
| 2 | *(secondary — see table below)* | *(see below)* | Body 14/400; `—` in `text-muted-foreground` when empty |
| 3 | Deleted | `trash.column.deletedAt` | `<time dateTime={iso} title={absolute}>` wrapping `<RelativeTime />`, `text-muted-foreground text-xs` |
| 4 | Deleted by | `trash.column.deletedBy` | See § Deleted by, below |
| 5 | *(actions)* | `common.actions`, wrapped in `<span class="sr-only">` | Right-aligned, `whitespace-nowrap` |

The secondary column, one per tab:

| Tab | Secondary | Header key | Why this one |
|-----|-----------|-----------|--------------|
| Deals | Organization name | `trash.column.organization` | A deal title alone rarely identifies a deal; the account does |
| People | Email | `trash.column.email` | The disambiguator between two people with the same name |
| Organizations | Website | `trash.column.website` | Organizations have no parent; the domain is what separates two "Acme"s |
| Activities | Due date | `trash.column.dueDate` | Activity titles are frequently generic ("Call", "Follow up"); the date is the identity |

**The actions column header is an empty-looking `<th>` carrying `sr-only` text.** The four existing
tables ship a literally empty `<th>`; this phase does not copy that. The visual result is identical
and the header row stops being unlabelled for a screen reader.

**The record name is NOT a link.** A trashed record's detail page either 404s or renders a live view
of a deleted record — both are wrong, and a dead link is worse than an honest dead end (the rule
`36-UI-SPEC.md` states for deleted linked records). Plain text. Viewing a trashed record read-only is
out of scope; see § Out of Scope.

**The trash table does NOT use `useDataTableKeyboard`.** That hook's contract is
`onOpen` / `onEdit` / `onCreate`, and none of the three has any meaning on a trashed record. Wiring
it up would give the user keyboard shortcuts that either do nothing or navigate to a 404.

### Deleted by

`37-CONTEXT.md` requires all five actor kinds to render, and requires honesty about records deleted
before Phase 36 shipped. Reuse Phase 36's presentation vocabulary — do not re-derive actor labels.

| Case | Rendered |
|------|----------|
| `user`, row present | `actor.name ?? actor.email`, Body 14/400 |
| `user`, row gone | `audit.unknownActor` — "Unknown user" — `text-muted-foreground` |
| `workflow_run` | `Badge variant="secondary" class="gap-1 font-normal"` + `Workflow` icon + `audit.actorKind.workflowRun`; the workflow name beside it when known |
| `api_key` | Same badge shape + `Key` icon + `audit.actorKind.apiKey`; the key name beside it when known |
| `import` | Same badge shape + `Download` icon + `audit.actorKind.import` |
| `system` | Same badge shape + `Cog` icon + `audit.actorKind.system` |
| **No audit row at all** | `trash.actor.notRecorded` — **"Not recorded"** — `italic text-muted-foreground`, with `title={t('trash.actor.notRecordedTitle')}` |

**"Not recorded" is not "Unknown user", and the two must not collapse into one string.** "Unknown
user" means *a user did this and that user row is gone*. "Not recorded" means *nobody wrote it down*,
because the record was deleted before change history existed. `37-CONTEXT.md` § Specific Ideas is
explicit: show that honestly rather than defaulting to a system actor. Rendering these five actor
kinds in text — never icon-only — is also how SC-1 ("the actor who deleted them") is satisfied for a
screen-reader user.

The `title` is a native attribute, not a Radix `Tooltip`: `tooltip.tsx` is not vendored and
`components.json` declares `"registries": {}`, so pulling one would contradict § Registry Safety.
Same reasoning `36-UI-SPEC.md` records for truncated audit values.

### The linked-in-trash flag

A record whose parent is also trashed carries, **under its name in cell 1**:

```
<Badge variant="secondary" class="mt-1 gap-1 font-normal"
       title={t('trash.linkedInTrashTitle', { names })}>
  <Trash2 class="size-3" aria-hidden="true" />
  {t('trash.linkedInTrash')}          ← "Linked record in trash"
</Badge>
```

The parent map is fixed and exhaustive:

| Entity | Parents checked |
|--------|-----------------|
| Deal | `organization`, `person` (0, 1 or 2 may be trashed) |
| Person | `organization` |
| Activity | `deal` |
| Organization | none — this badge never renders on the Organizations tab |

`Trash2` at `size-3`, muted inside a `secondary` badge — **no warning icon, no warning colour**. A
trashed parent is a fact about the data, not an error state, and Phase 36 already settled that a
completed deletion never gets destructive treatment. The `title` names the parents via
`format.list(names)` so the user can see *which* linked records without the table growing a column.

`37-CONTEXT.md` locks the behaviour: the flagged row can still be restored on its own, and it offers
one-click "restore the parent too". The interaction is in § Surface 2.

### States

| State | Rendering |
|-------|-----------|
| Rows present | The table |
| **Tab is empty** | A single `TableRow` / `TableCell colSpan={n} class="h-24 text-center"` — the exact treatment the four existing data tables use — containing the heading at Label 14/600 and the body at Body 14/400 `text-muted-foreground`. Copy in § Copywriting |
| More rows exist | `Button variant="outline"` **Load more**, `flex justify-center pt-2` — the existing pagination idiom, verbatim |
| Query failed | The `Card` renders a `rounded-md border p-6 text-center text-sm text-muted-foreground` panel containing `trash.error.unavailable`. `/trash` has no `error.tsx` above it, so an unguarded throw takes the page down; the tab degrades to a message instead, exactly as `record-timeline.tsx` and `run-changed-records.tsx` do |
| Non-admin viewer | Rows they could have seen live (owner-or-admin). Records owned by others are **absent**, not greyed — the same rule the live lists apply, so there is no new empty-state variant for it |

### Responsive

`table.tsx` wraps every table in `overflow-x-auto`. At 320px the five columns scroll horizontally
inside that container, which is the behaviour all four existing tables already have and is correct
for tabular data. **The page shell itself must not scroll horizontally at 320px** — the header, the
`TabsList` (which is `w-fit` and may itself scroll) and the pagination row all fit. This is the one
place where the inherited "no horizontal scroll at 320px" check is scoped to the shell rather than to
every element, and it is stated so the checker does not read the table container as a regression.

## Surface 2 — Restore

**Non-destructive, so no confirmation** — except in the one case where it needs a choice.

### The controls

| Row | Actions cell |
|-----|-------------|
| No trashed parent | `[Restore]` |
| Has ≥1 trashed parent | `[Restore]` `[Restore with linked records]` |
| Viewer is admin | the above, plus `[Delete permanently]` (§ Surface 3) |

- `Restore` — `Button variant="outline" size="sm"` with `RotateCcw class="h-4 w-4"` +
  `t('trash.restore')`. **Text, not icon-only.** Trash is a rarely-visited recovery surface; the one
  user who lands here after deleting the wrong deal has never seen this page before, and an
  unlabelled glyph next to a red glyph is exactly the wrong thing to hand them. No tooltip primitive
  is vendored, so a label is also the only accessible option that does not need `sr-only` text.
- `Restore with linked records` — `Button variant="ghost" size="sm"`, no icon. It restores this
  record **and every trashed parent in the badge's list**, in one click, which is what
  `37-CONTEXT.md` asks for. The label is plural and kind-agnostic on purpose: a deal can have two
  trashed parents, and "Restore with organization" would be a lie half the time.
- Both go `disabled` with `Loader2 class="size-4 animate-spin"` + `t('trash.restoring')` while in
  flight. The other rows stay interactive.

**A row is never blocked from restoring because its parent is trashed** — locked in `37-CONTEXT.md`,
and the reason is recorded there: the common case is *parent deleted by mistake, child needed now*,
and forcing two trips in a fixed order taxes exactly that case.

### After a successful restore

The row leaves the table and the tab count decrements. **A toast is required here, and this is not a
violation of Phase 35's "no success toast where the result is visible" rule — it is the case that
rule was written to exclude.** A row vanishing from trash is ambiguous: it could mean restored, and
it could mean destroyed. The toast is what disambiguates, so it must name the destination:

```
toast.success(t('trash.restored', { name, list: tNav(type) }),
              { action: { label: t('trash.openRecord'), onClick: () => router.push(href) } })
```

→ *"Acme Ltda is back in Organizations."* with an **Open** action. The action earns its place: the
reason someone restores a record is that they need it, and the next click is otherwise "find it in
the list again".

For the linked variant the toast is `trash.restoredWithLinked` — an ICU plural naming how many
records came back — because "3 records restored" is the fact, and reporting only the row the user
clicked would understate what just happened.

### Failure

| Failure | Copy | Treatment |
|---------|------|-----------|
| Generic | `trash.error.restoreFailed` | `toast.error`; the row stays; the buttons re-enable |
| Record was purged in the meantime | `trash.error.alreadyPurged` | `toast.error`; then `router.refresh()` so the stale row leaves. The server action must distinguish this case from a generic failure — a user told "try again" about a record that no longer exists will try again forever |

### Focus

Restoring removes the focused button from the DOM, which drops focus to `<body>`. After any
successful restore or purge, focus moves to the table's wrapper `<div tabIndex={-1} ref={…}>`. The
announcement is carried by Sonner's own live region; no second live region is added.

## Surface 3 — Purge

**Admin-only, per TRASH-03 and `37-CONTEXT.md`.** A record owner can trash and restore their own
records; only an admin can destroy them.

- **Non-admins do not see the control at all.** Not disabled — hidden. A button that is permanently
  disabled for a whole class of user is furniture, and a disabled destructive button invites the
  question "how do I enable this?" The server action re-checks the role regardless (the client is
  never the gate), and a non-admin who reaches the action anyway gets
  `trash.error.purgeNotPermitted`.
- **Control:** `Button variant="ghost" size="sm" class="text-destructive hover:text-destructive"`
  with `Trash2 class="h-4 w-4"` + `t('trash.deletePermanently')`. Ghost, not
  `variant="destructive"` — the filled destructive is reserved for the confirm button inside the
  dialog, and fifty filled red buttons would make the confirm button mean nothing. Text, not
  icon-only, for the same reason `Restore` is: a red trash icon inside a page called Trash is
  genuinely ambiguous.

### Confirmation

`AlertDialog` (focus trap, ESC and focus restoration all from Radix), rendered from inside
`trash-table.tsx` — a `'use client'` module — and **controlled** (`open` / `onOpenChange`) with no
trigger component of its own, the same non-definer shape `retention-form.tsx` and
`delete-note-dialog.tsx` use. See § Component Inventory for why this is a hard boundary.

| Field | Copy / treatment |
|-------|------------------|
| Title | **Delete permanently?** |
| Description | **{name} and its notes will be permanently deleted. This can't be undone. Its change history is kept.** |
| Cancel | **Keep in trash** — not "Cancel" |
| Confirm | **Delete permanently**, `bg-destructive text-destructive-foreground hover:bg-destructive/90`, with `Loader2 animate-spin` while in flight and `event.preventDefault()` on the click so Radix does not close the dialog mid-request |

**The description states what survives, not only what dies.** "Its change history is kept" is true —
`37-CONTEXT.md` locks that a purge preserves the record's `audit_log` rows and writes one more
recording the purge — and it is the single most reassuring thing that can honestly be said at that
moment. Omitting it would leave an admin believing a purge erases the evidence of the purge.

**No type-the-name confirmation.** No precedent for it in this repo, and the record is already
deleted; a second friction gate on a record nobody can see is ceremony, not safety.

After success: `toast.success(t('trash.purged', { name }))`, the row leaves, the tab count
decrements, focus moves to the table wrapper.

## Surface 6 — The Delete-Dialog Honesty Correction

Six CRM delete confirmations currently end with **"This action cannot be undone."** Once this phase
ships, that sentence is false: the record moves to trash and can be restored. A confirmation dialog
that overstates the consequence trains users to distrust every confirmation dialog in the product,
and it is the only existing surface this phase has any business touching.

**Change these six, one sentence each:**

| File | Line (2026-08-16) |
|------|-------------------|
| `src/app/deals/deal-card.tsx` | 258 |
| `src/app/deals/deal-dialog.tsx` | 538 |
| `src/app/organizations/delete-dialog.tsx` | 45 |
| `src/app/people/delete-dialog.tsx` | 45 |
| `src/app/activities/activity-dialog.tsx` | 532 |
| `src/app/activities/activity-list.tsx` | 517 |

Replace `This action cannot be undone.` with **`You can restore it from Trash.`**

**Do NOT change these two — their copy is correct and must stay:**

| File | Why |
|------|-----|
| `src/app/workflows/delete-workflow-dialog.tsx:41` | Workflows are hard-deleted with their run history. Genuinely irreversible |
| `src/app/workflows/[id]/edit/components/config-forms/http-config.tsx:242` | An HTTP config template is hard-deleted. Genuinely irreversible |

Those six strings are **English literals in the source today**, not `next-intl` keys, so this is one
line per file and **no new translation keys**. Half-migrating them into the message catalogues is
unrelated scope and must not be bundled in. The dialogs' structure, buttons, icons and destructive
treatment are unchanged — only the claim about reversibility.

**This is a scope judgement, and it is declared rather than assumed.** `37-CONTEXT.md` scopes out
"changing what the existing live list views show or filter". A confirmation dialog's sentence is
neither what a list shows nor how it filters, and shipping trash while six dialogs deny it exists is
a defect this phase creates. If the planner disagrees, the correct move is to write the
disagreement down — not to leave the sentence and hope.

## Interaction Contract

**Tabs**

| Trigger | Behavior |
|---------|----------|
| Click a tab | `router.push('/trash?type=…')`. Page re-renders server-side: rows, counts and paging all recomputed. Paging resets to page 1 |
| Arrow keys | Move focus only (`activationMode="manual"`). Enter/Space activates |
| Direct load of `?type=people` | That tab active at first paint, server-rendered, no flash of the deals tab |
| Unrecognised or missing `type` | Deals tab. Never an error, never an empty shell |
| A tab with 0 records | Still rendered, labelled `(0)`, still selectable. A tab that appears and disappears between visits is worse than one that reports nothing to show |

**Restore**

| Trigger | Behavior |
|---------|----------|
| `Restore`, no trashed parent | Restores immediately. No dialog — nothing is destroyed. Button shows `Loader2` + "Restoring…" |
| `Restore`, trashed parent present | Restores **this record only**. The parent stays in trash. Permitted by design; not blocked, not warned |
| `Restore with linked records` | Restores this record and every parent named in its badge, in one click |
| Success | Row leaves; tab count decrements; `toast.success` naming the destination list, with an **Open** action; focus moves to the table wrapper |
| Failure | Row stays; buttons re-enable; `toast.error`. A purged-in-the-meantime failure gets its own copy and a `router.refresh()` |

**Purge**

| Trigger | Behavior |
|---------|----------|
| Non-admin | The control does not render |
| `Delete permanently` | Opens the `AlertDialog`. Nothing is sent yet |
| Confirm | `event.preventDefault()` keeps the dialog open while in flight; the confirm button shows `Loader2` + "Deleting…"; Cancel is disabled during the request |
| Success | Dialog closes; row leaves; tab count decrements; `toast.success`; focus moves to the table wrapper |
| Failure | Dialog closes; `toast.error`; the row stays |
| ESC / Cancel / overlay click | Closes; nothing is sent; nothing is destroyed |

**Retention form** — identical in every respect to `/admin/audit`:

| Trigger | Behavior |
|---------|----------|
| Empty, non-integer, `<1` or `>365` | **Save disabled.** The always-visible helper text states the range; no error colour, no message that appears and disappears |
| Unchanged from saved | Save disabled — there is nothing to save |
| Raised, or set for the first time | Saves directly. `Loader2` + "Saving…", Input disabled, `toast.success` on success |
| Lowered | Opens the shorten `AlertDialog` first. Confirm runs the same save; Cancel closes and **leaves the typed value in the Input** so the operator can adjust rather than retype |
| Save fails | Input re-enabled with the typed value **retained**, `toast.error` |
| After a successful save | The two readouts are **not** optimistically updated |

`/admin/trash` page arrive with their RSC render. No skeleton, no spinner on initial load.

## Accessibility Contract

- **Tabs are Radix `Tabs`**, so `role="tablist"` / `role="tab"` / `aria-selected` /
  `aria-controls` come for free with no bespoke ARIA. `activationMode="manual"` is required so
  arrow-key exploration does not fire a navigation per keystroke — an automatic-activation tab bar
  wired to `router.push` is unusable with a keyboard.
- **The table is a real `<table>`** with `<th scope>` header cells from `table.tsx`. The actions
  column's header carries `sr-only` text rather than being empty.
- **Every row action has a visible text label** — no icon-only buttons anywhere on `/trash`. This is
  both a usability decision (a rarely-visited recovery surface must not require icon literacy) and an
  accessibility one (no vendored tooltip primitive, so a label is the only reachable name).
- **The actor kind is carried by text, never by an icon alone.** Every non-user actor renders a
  `Badge` containing the translated kind label; the icons inside those badges are `aria-hidden="true"`,
  exactly as in Phase 36's timeline entry.
- **"Not recorded" is real text**, not an aria attribute and not an em-dash. Its explanation is a
  native `title`, which is keyboard- and screen-reader-reachable.
- **The linked-in-trash badge is text**, and the parent names it references are in its `title`. The
  `Trash2` glyph inside it is `aria-hidden="true"` and carries none of the meaning.
- Every timestamp is `<time dateTime={iso} title={absolute}>` wrapping `RelativeTime`, which already
  handles the SSR/CSR hydration guard. `format.dateTime` options match every other timestamp in the
  product: `year: numeric, month: long, day: numeric, hour: numeric, minute: numeric`.
- **Focus is moved deliberately after a row is removed.** Restoring or purging destroys the focused
  button; focus moves to the table wrapper (`tabIndex={-1}`) rather than being dropped to `<body>`.
- **Result announcements ride Sonner's live region.** No new `aria-live` region is added on either
  route.
- Both confirmations are `AlertDialog`s — focus trap, ESC and focus restoration come from Radix.
- The retention `Input` has a visible `<Label htmlFor="trash-retention-days">` and its helper text is
  associated by `aria-describedby`. A placeholder is never a label.
- Focus rings are inherited from `globals.css` `:focus-visible`. Do not add per-component focus
  styling and do not set `outline: none` anywhere in this phase.
- Contrast: everything uses `foreground` / `muted-foreground` on `card` / `background`, plus
  `secondary` badges — all already-audited pairs. This phase introduces **no** pastel badge and no
  new hue, so it adds no new contrast risk.
- **Colour is never the sole carrier of the destructive action.** `Delete permanently` is red *and*
  says "Delete permanently"; `Restore` is neutral *and* says "Restore". A user who cannot distinguish
  the two colours reads two different words.

## Out of Scope (do not build, do not design for)

From `37-CONTEXT.md` § Deferred Ideas and § Out of scope, plus the boundaries this contract draws:

- **Search or filtering inside `/trash`.** The list is bounded by the retention window (30 days by
  default) and sorted newest-deleted-first, which puts "the thing I just deleted by mistake" at row 1
  — the dominant use case. Search is furniture on a list you scan for five seconds. Revisit only if a
  deployment reports an unusable trash volume.
- **Sort controls.** `deleted_at` DESC, always.
- **Multi-select, bulk restore, or bulk purge.** Phase 38 owns multi-select; this phase must not ship
  a checkbox column that Phase 38 then has to redesign.
- **An "Empty trash now" button** on `/admin/trash`. SC-3 is per-record and SC-4 is automatic;
  a one-click mass-destruction control is neither required nor safe, and it is the single most
  dangerous button this phase could ship.
- **Viewing a trashed record's detail page**, read-only or otherwise. The record name is plain text.
- **A "Restore" control on an audit timeline entry**, and any copy implying one. `36-UI-SPEC.md`
  scoped that out explicitly and this phase does not add it back.
- **Notes as a trash tab.** A note deleted from a timeline is restored from that timeline.
- **A trash badge or count in the nav header.** Trash is a recovery surface, not a daily one; a
  persistent counter would make deleted records feel like an inbox.
- **Changing what the live list views show or filter** — including hiding records whose parent is
  trashed. The six delete-dialog sentences in § Surface 6 are copy, not list behaviour.
- **Translating the rest of the workflows tree, or migrating the four existing tables' hardcoded
  "Load More" strings.** Unrelated debt.
- **Per-entity retention windows.** One global `trash.retention_days`.
- **Undo of a purge.** There is none, and no copy may suggest otherwise.

## Assumptions Flagged for the Planner

1. **A trashed record's "deleted by" is resolvable in one batched query per page.**
   `37-CONTEXT.md` requires it and flags the N+1 risk; the Deleted-by column is specified on the
   assumption that 50 rows cost one lookup against `audit_log_entity_idx`. If it cannot be batched,
   the fallback is a smaller page size — **not** dropping the column, which is half of SC-1.
2. **The linked-in-trash flag is computed server-side, in the same query as the rows.** The parent
   map is fixed (§ Surface 1), so it is at most two left joins with an `IS NOT NULL` on the parent's
   `deleted_at`. If that proves costly, the fallback is to render the badge without the `title`'s
   parent names — never to drop the flag, which is what makes `Restore with linked records`
   discoverable.
3. **`trash.retention_days` is readable from the `/trash` server component**, so the empty-state body
   can name the window. If the read is unavailable or fails closed, the page renders
   `trash.empty.bodyNoRetention` — which is why that key exists rather than a `{days}` default.
4. **The restore server action can distinguish "already purged" from a generic failure.** The copy
   contract has two strings for it. If the mutation layer cannot tell the difference, say so in the
   plan and collapse to `restoreFailed` — do not silently map a purged record onto "try again".
5. **The bounds 1–365 and the default 30 are this document's recommendation, not a locked decision.**
   `37-CONTEXT.md` grants the planner discretion. Whatever ships, `trash.retention.windowHelp` and
   the `Input`'s `min` / `max` must agree with it and with each other.
