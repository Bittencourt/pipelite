Carry the module header comment forward VERBATIM in substance: the range is NOT imported, deliberately.
`RETENTION_MIN` / `RETENTION_MAX` live in `src/lib/trash/settings.ts`, which imports the database, and
importing them here would drag a server-only module into the browser bundle. The two bounds are written
out instead, and if those constants ever change this file changes with them. The `trash.retention.windowHelp`
copy states the same 1-365 range; all three must agree.

Everything else is copied unchanged and must not be "improved":

  - `parseDays` with the digits-only `/^\d+$/` test before `Number()` — that test is what rejects `1.5`,
    `1e3`, `-1`, a space and the empty string, all of which `Number()` alone would accept or coerce to 0.
  - `inRange` / `changed` / `canSave` enablement. Out-of-range input disables Save; it does not turn the
    Input red and it does not show a message that appears and disappears. The always-visible helper text
    is the rule, not a reaction to breaking it.
  - `lowers` — only a LOWERED window destroys anything, so only that path opens the AlertDialog. Raising
    the window, or setting it for the first time, saves directly.
  - The controlled `AlertDialog` with `open` / `onOpenChange`, no `AlertDialogTrigger`, and
    `event.preventDefault()` on `AlertDialogAction` so Radix does not close the dialog mid-request. The
    dialog must stay open with a `Loader2` spinner while the save is in flight, and Cancel is disabled
    during it. Cancelling leaves the typed value in the Input so the operator can adjust rather than
    retype.
  - The `save()` transition, where a refusal and a thrown action are the same event to the operator and
    neither one touches what they typed.
  - `className="max-w-32"` on the Input, `variant="default"` on the Save button (the only accent-filled
    element this phase adds), and the destructive class string on the confirm button.

The confirm label is `Shorten retention window`, the cancel label is `Keep current window` — no bare
"Save", "Cancel" or "Confirm" anywhere, including inside the dialog.

This file is `'use client'` and both the dialog and its state live entirely inside it. No React element
crosses the RSC boundary into a Radix `asChild` slot; the repo-wide gate at
`src/app/admin/fields/[entityType]/__tests__/rsc-boundary.test.tsx` fails the build otherwise.
