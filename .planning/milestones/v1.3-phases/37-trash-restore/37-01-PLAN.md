needed (all four `*_deleted_at_idx` btrees were shipped by migration 0012; CONTEXT.md's claim that
`deals` lacks one is stale). `drizzle-kit generate` with no schema change emits nothing, so the file
must be created as an explicitly empty custom migration:

    ./node_modules/.bin/drizzle-kit generate --custom --name trash_retention_seed

That writes `drizzle/0015_trash_retention_seed.sql` (empty) and registers it in
`drizzle/meta/_journal.json`. If the host invocation fails, run the same command inside the container:
`docker compose exec -T app npx drizzle-kit generate --custom --name trash_retention_seed`. Never use
`npx drizzle-kit` on the host — `npx` resolves to `npm run` in this environment and reports
"Missing script".

Into the generated file write ONLY the seed, preceded by the four-point justification comment adapted
from `drizzle/0014_sloppy_slapstick.sql:28-70`:

  1. WHY IT EXISTS — without it `readTrashRetentionDays()` returns null on a fresh install and the
     pruner purges nothing, so SC-4 is silently unmet.
  2. WHY IT IS DATA AND NOT A CODE FALLBACK — a code-level default would mean a cleared or tampered
     settings row silently RESUMES destroying records. A seeded row plus fail-closed parsing gives
     both a working default and a fail-closed failure mode. Do not "simplify" either away.
  3. WHY HAND-EDITING THIS FILE DOES NOT VIOLATE PHASE 33 D-06 — D-06 forbids hand-written INDEX DDL
     in migration SQL because a later `generate` silently dropped one (0009 to 0010). `generate` does
     not manage data rows at all, so a data seed cannot be clobbered. The distinction is DDL versus
     data. This migration contains no DDL whatsoever.
  4. WHY THE CONFLICT CLAUSE DOES NOTHING RATHER THAN UPSERTING — the seed must be idempotent and must
     never overwrite a value an admin has chosen.

The single statement is:
`INSERT INTO "app_settings" ("key", "value") VALUES ('trash.retention_days', '30'::jsonb) ON CONFLICT ("key") DO NOTHING;`

Then APPLY it against the running database:

    docker compose exec -T app npx drizzle-kit migrate

and confirm the row landed:

    docker compose exec -T postgres psql -U pipelite -d pipelite -c "SELECT key, value FROM app_settings ORDER BY key;"

`docker` needs no `sudo` here and no password may appear in any command.
