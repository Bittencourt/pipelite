For `notes.ts`:
- Import `pgTable, text, timestamp, index, uniqueIndex` from `drizzle-orm/pg-core`, `sql` and
  `type InferSelectModel` from `drizzle-orm`, `users` from `./users`, and
  `type EntityType` from `./custom-fields`. Do NOT redeclare the `EntityType` union — there is
  exactly one definition in the repo today and a second would drift (D-01).
- Export `type NoteSource = 'user' | 'migration'` and apply it via `.$type<NoteSource>()` on the
  `source` column with `.default('user')` (D-09: migrated rows carry `source: 'migration'` forever
  so they stay countable separately from user-written notes).
- `entityId` gets NO `.references(...)`. It is polymorphic across `deals`, `organizations`,
  `people`, `activities`. Add a comment saying so, and saying that the database will therefore NOT
  catch a dangling reference — the parent-existence check in `src/lib/mutations/notes.ts`
  (plan 35-04) is the only defence (T-35-04).
- `authorId` is nullable (`.references(() => users.id)` with no `.notNull()`): a migrated row on a
  deployment whose source record has no owner renders as "Unknown" (D-09).
- Declare all three indexes in the second-argument object form. `notes_live_idx` uses
  `.on(table.entityType, table.entityId, table.createdAt.desc())` and
  `.where(sql`${table.deletedAt} is null`)`. `notes_migration_uniq` uses `uniqueIndex(...)` on
  `.on(table.entityType, table.entityId)` with `.where(sql`${table.source} = 'migration'`)`.
  Add a comment on `notes_migration_uniq` recording that it is the NOTE-03 idempotency guard
  (D-11) and is a permanent database invariant, not a one-shot script guard.
- Do NOT pass a `mode` option to any `timestamp(...)` call. Drizzle's default builder yields
  `Date`, matching `createdAt`/`updatedAt` on every existing CRM table. The keyset cursor
  (plan 35-05) compares `createdAt` values, so a `string`-vs-`Date` surprise there is a real bug —
  this decision is what prevents it.
- Export `export type Note = InferSelectModel<typeof notes>`.

For `deal-stage-history.ts`:
- Import `pgTable, text, timestamp, index` from `drizzle-orm/pg-core`, `type InferSelectModel` from
  `drizzle-orm`, `users` from `./users`, `deals` from `./deals`, `stages` from `./pipelines`.
- Add a file-header comment recording the resolved discretion item from 35-CONTEXT.md: this table
  is deal-specific by design. A generic table would either become Phase 36's audit log (explicitly
  out of scope) or a half-generic shape Phase 36 must migrate anyway. Pluggability lives in the
  assembler's source interface (plan 35-08), not in the table shape. The payoff is real FKs, which
  the polymorphic `notes` table cannot have.
- Add a second comment on the table explicitly declaring the deliberate deviation from repo
  convention: NO `updatedAt`, NO `deletedAt`. History rows are immutable append-only facts. Every
  other CRM table carries both, so the absence otherwise reads as an oversight.
- Export `export type DealStageHistoryRow = InferSelectModel<typeof dealStageHistory>`.

Do NOT hand-write any `CREATE INDEX` SQL anywhere (Phase 33 D-06 — a hand-written index was
silently dropped by a later generate, 0009 → 0010). Do NOT run `drizzle-kit generate` in this
plan; plan 35-03 owns that.
