  <action>
Create src/components/timeline/timeline-list.tsx with the 'use client' directive first.

State it owns:
- entries, seeded from initialEntries
- cursor, seeded from initialCursor
- more, seeded from hasMore
- loading, a boolean for the in-flight Load more request

Structure, top to bottom, matching 35-UI-SPEC.md Layout and Composition:
1. NoteComposer, pinned at the top, with onAdded prepending the returned entry to entries. The
   composer is rendered ALWAYS, including when the list is empty, because the empty-state copy ends
   by pointing at it.
2. A separator using border-t with mt-4 pt-4.
3. When entries is empty, render EmptyTimeline with variant full for entityType deal and notesOnly
   for the other three. Otherwise render an ordered list element with space-y-4 and one list item
   per entry, newest first, so the DOM order and the visual order agree.
   Each list item renders TimelineEntryRow with canManage computed as
   entry.kind is note AND (isAdmin OR entry.author?.id equals currentUserId).
   onUpdated replaces that entry in state by id; onDeleted removes it by id.
4. A decorative vertical connector: a 1px bg-border line behind the rail running from the centre of
   each icon to the next, omitted after the last loaded entry, carrying aria-hidden true.
5. The Load more button, rendered only when more is true: full width, variant outline, size sm,
   mt-4.

The four-state Load more machine, all four required and none of them optional:
- idle and more entries exist: the button renders with the notes.loadMore label and is enabled.
- in flight: the SAME button, disabled, showing Loader2 with animate-spin and the notes.loadingMore
  label.
- failed: the button returns to idle (enabled, loadMore label) and toast.error fires with
  notes.error.loadMoreFailed. Never a silent no-op. The cursor is NOT advanced on failure, so a
  retry fetches the same page.
- exhausted: the button is not rendered at all. There is no terminal text such as "That's all".

Load more handler: set loading, call loadMoreTimeline with entityType, entityId and the current
cursor inside useTransition or a plain async call. On success append page.entries to entries, set
cursor to page.nextCursor and more to page.hasMore. On a false result or a thrown error, handle both
identically: toast the error and leave entries, cursor and more untouched. Always clear loading in a
finally.

Deduplicate on append: filter any incoming entry whose id already exists in state. Keyset paging
makes a duplicate structurally unlikely, but an optimistically prepended note plus a concurrent page
fetch is a real interleaving and a duplicated React key is a visible bug.

Do not use useOptimistic. It has zero uses in this repo; the manual local-state-plus-revert idiom
from custom-fields-section.tsx is the established pattern and introducing a new idiom here would be
an undeclared convention change.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server component to client component | Props are serialized across the Flight boundary; a React element crossing into a Radix asChild slot returns null silently |
| client to server action | The cursor and the entity identifiers are round-tripped through the browser and must be re-validated server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-30 | Denial of Service | a silently broken RSC boundary rendering nothing with no error | mitigate | record-timeline.tsx renders only Card primitives and TimelineList, and the class-wide asChild gate is run after both tasks. The failure mode this guards is silent at runtime, so the gate is the only detector |
| T-35-02 | Tampering | a tampered cursor round-tripped from the client | mitigate | The cursor is opaque to this component; loadMoreTimeline passes it to assembleTimeline, which zod-validates it and degrades to page one on anything malformed |
| T-35-33 | Repudiation | a failed Load more silently doing nothing, so the user believes the record has no more history | mitigate | The failure branch is mandatory: the button returns to idle and toast.error fires with notes.error.loadMoreFailed. The existing activities-client.tsx analog has no failure path at all, which is exactly why it must not be copied |
| T-35-34 | Information Disclosure | a note the viewer may not manage exposing Edit and Delete affordances | mitigate | canManage is computed from the server-supplied currentUserId and isAdmin, and is cosmetic only; the server actions and the v1 route re-check with isAuthorOrAdmin |
| T-35-SC | Tampering | npm installs | accept | Zero packages installed |
</threat_model>
