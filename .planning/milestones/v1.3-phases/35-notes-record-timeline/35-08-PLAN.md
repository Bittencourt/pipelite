<objective>
Build the timeline assembler: a pluggable set of SQL-fragment sources composed into ONE pre-limited
`UNION ALL` statement with keyset paging, plus two-step hydration into the `TimelineEntry` union.

Purpose (TDD): the pre-limit is the entire measured optimisation (1.0 ms warm vs materialising a
record's whole history), the keyset predicate is the correctness control under concurrent inserts,
and parameter binding is the injection control. All three are assertable against the rendered SQL
string and parameter array before a database is ever touched.
Output: `src/lib/timeline/sources.ts`, `src/lib/timeline/assemble.ts`, and their test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client-supplied cursor + entityId → composed SQL | This is the ONLY place in the phase where raw SQL is hand-composed; it is the single highest-risk spot |
| database rows → TimelineEntry union | Untyped snake_case raw rows are cast and mapped; a wrong cast silently mislabels an entry kind |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-01 | Tampering | SQL injection via the hand-built timeline SQL | mitigate | `entityType` validated against the four literals BEFORE any SQL is composed; `entityId` and all cursor values passed as `${}` bound parameters inside `sql` templates, never concatenated. Asserted by rendering the query with `PgDialect().sqlToQuery` and proving the probe payload appears in `params` and not in the SQL text. Grep gate forbids `sql.raw` and string concatenation |
| T-35-02 | Tampering | SQL injection via the paging cursor | mitigate | `decodeCursor` (plan 35-05) validates with zod and returns `null` on anything malformed; the decoded `Date` and bounded id are then bound, never interpolated |
| T-35-06 | Information Disclosure | soft-deleted notes appearing in the timeline | mitigate | Explicit `deleted_at IS NULL` in the notes and activities branch predicates, grep-gated. `notes_live_idx` is partial on that predicate but does not enforce it |
| T-35-26 | Denial of Service | a record's entire history materialised before the outer LIMIT | mitigate | Per-branch `ORDER BY … LIMIT n+1` before the union, asserted by counting `order by` / `limit` occurrences in the rendered SQL. Measured 1.0 ms warm on a 503-note / 117-activity / 302-stage-change deal |
| T-35-27 | Tampering | paging desynchronising under concurrent inserts, re-showing or skipping entries | mitigate | Keyset `(created_at, id)` row comparison rather than OFFSET. A new note has `created_at = now()`, strictly newer than any cursor; migrated notes are dated at the record's `createdAt`, strictly older than any unreached cursor; an edit preserves `created_at` |
| T-35-SC | Tampering | npm installs | accept | Zero packages installed |
</threat_model>
