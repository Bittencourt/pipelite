<objective>
Remove the non-shrinkable 256px search input from the header below `md`, replacing it with a 40px
icon that opens the search dialog, and put the last hardcoded nav label into the catalog.

Purpose: `document.scrollWidth` measures 416 against a `clientWidth` of 305 on EVERY main route. The
cause is arithmetic, not styling: the search input carries `min-w-0 w-xs w-64`, `w-64` wins and pins
it to 256px, its wrapper is a bare `div.relative` with no shrink allowance, and
256 + 16 (`gap-4`) + 40 (avatar) = 312px of non-shrinkable content inside a 305px client width.
Shrinking the input in place yields a technically-non-overflowing but unusable control — 256px is
84% of a 320px viewport. Removing it from the flex row is the fix.

Output: a responsive header, a mobile search dialog that actually returns results, and `t("workflows")`.
</objective>

Budget at 320px (client width 305, minus 64px of the global `@utility container` padding = 241
usable): wordmark ~78 + gap-4 16 + search 40 + gap-4 16 + avatar 40 = 190px. 51px of slack. The
`gap-4` stays; the slack does not require reducing it.

The mechanism, so it is not mistaken for a style preference: a flex item defaults to
`min-width: auto` and refuses to shrink below its content. That is what turns a 256px input into
416px of scrollWidth. `min-w-0` is what makes `justify-between` able to shrink.

`showCloseButton={false}` on the dialog: Escape and the overlay already close it, and an X inside a
full-width search field at 320px steals the only spare horizontal room.

`shouldFilter={false}` is MANDATORY and is why 45-07 exists. cmdk defaults it to true and filters
against each item's `value`; every item here is a UUID (`value={org.id}` and siblings), so a user
typing "Acme" matches nothing and the dialog renders `CommandEmpty` for every query while the
network request succeeded.

S-7: `CommandDialog`'s `title` and `description` default to the hardcoded English "Command Palette"
and "Search for a command to run...". `DialogHeader` is a SIBLING of `DialogContent`, so those
strings render into the page whenever the dialog is MOUNTED, open or not. Both props must be passed
or this plan creates a new English leak on a brand-new surface.

The `/` hotkey, both targets, zero state — read the media query AT EVENT TIME inside the handler:
below md open the dialog, at md and up focus the inline input. Never a focus call on an unrendered
node. `768px` must stay in sync with Tailwind's `md`; note it in a comment. No `useMediaQuery` hook:
it returns false on the server and the real value after an effect, which is either a hydration
mismatch or a `react-hooks/set-state-in-effect` lint ERROR (severity 2 in this repo).

Message keys consumed (delivered by 45-01): `nav.workflows`, `nav.searchDescription`.
`common.search` already exists. `t` and `tNav` are already bound in both files.

Out of scope, stated so the checker does not flag it: `data-table.tsx` on organizations and people
carries hardcoded "Search organizations..." and "Add Organization". Same defect class, different
surface, and Phases 39-43 own those files.
