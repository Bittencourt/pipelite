<objective>
Make `CommandDialog` usable as a search surface, and lift the results tree out of
`global-search.tsx` so one tree can serve two surfaces.

Purpose: 45-UI-SPEC lists `ui/command.tsx` as "unchanged, newly used". That is not achievable.
`CommandDialog` renders its own `<Command>` and spreads `...props` onto the Radix `Dialog` root, so
there is no path for `shouldFilter={false}`. cmdk defaults `shouldFilter` to true and filters against
each item's `value` — and every item in this app is `value={org.id}`, a UUID. A user typing "Acme"
matches no UUID, so the dialog would render "No results found" for every query while the network tab
shows a 200 with matches. This plan is a prerequisite for the mobile search surface in 45-10.

Output: two forwarded props on `CommandDialog`, a `SearchResults` component, and a behaviour-neutral
`global-search.tsx` that consumes it.
</objective>
