not.

`present.ts` as defence in depth, a corrected doc comment, and unit + source gates.

<!-- Where the decision belongs, and why it cannot go in the obvious place. -->

`AUDIT_FIELD_LABELS` (src/lib/audit/present.ts:58-79) maps ONE column to ONE message key, and
`describeField` (present.ts:326) emits a single `label` per column with no access to the from/to
pair. "Moved to Trash" vs "Restored from Trash" is two keys for one column, so it CANNOT live there.

Worse, `NATIVE_ORDER` is derived from `Object.keys(AUDIT_FIELD_LABELS)` insertion order
(present.ts:82) and its own doc comment says INSERTION ORDER IS LOAD-BEARING — it is the display
order of native columns. Inserting `deletedAt` anywhere but the END shifts every field after it.

So the direction branch belongs in `src/components/timeline/audit-entry.tsx`, the one place the
from/to pair is in hand (`AuditFieldRow`, lines 222-249).

Key resolution convention already in that file (audit-entry.tsx:106-108, 226-229):
  CUSTOM_CHANGE_PREFIX      = "custom:"
  MESSAGE_NAMESPACE_PREFIX  = "audit."
  FIELD_LABEL_KEY_PREFIX    = "audit.field."
  t                         = useTranslations("audit")
A label stored as "audit.field.movedToTrash" resolves by slicing the "audit." prefix — identical to
every other native label.

Message keys consumed (delivered by 45-01):
  audit.field.movedToTrash, audit.field.restoredFromTrash

Required rendering, by direction (45-UI-SPEC.md § Timeline deletedAt contract):
  null -> timestamp (soft delete)  SUPPRESSED when the entry's own action sentence is
                                   audit.entry.deleted.* — the row is pure redundancy there.
                                   Falls back to audit.field.movedToTrash when the action is
                                   recorded as an update.
  timestamp -> null (restore)      audit.field.restoredFromTrash
One line of text at Label typography. No arrow, no from/to pair, no timestamp — the entry header
already carries WHEN, and the stored deleted_at value is the same instant.
