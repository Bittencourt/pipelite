    Handler body, in this order:
    1. `const actor = getCurrentActor()` — read the store SYNCHRONOUSLY, at handler entry, into a
       local. `EventEmitter.emit` runs handlers inline in the emitter's own stack, so the context is
       still the mutation's. Reading it inside the promise continuation happens to work (probed) but
       depends on ALS continuation semantics staying the same across Node upgrades; capturing first
       is unconditionally correct. Write that reasoning into the comment.
    2. `const changes = buildChanges(payload)`.
    3. If `payload.action === "updated"` and the change map is empty, `return` — a save that changed
       nothing writes no row.
    4. `db.insert(auditLog).values({...}).catch((err) =&gt; console.error("[audit]", err))`.

    `actorKind: actor?.kind ?? "system"`, `actorUserId: actor?.userId ?? null`,
    `workflowRunId: actor?.workflowRunId ?? null`, `importSessionId: actor?.importSessionId ?? null`.
    **`payload.userId` must never appear in this file.** A confidently wrong name in an audit log is
    worse than an honest "unknown", and the grep in the acceptance criteria enforces it.

    The handler must NOT be `async` and must NOT `await` the insert. `crmBus.emit` cannot await; an
    async handler returns a floating promise with no `.catch`, which is an unhandled rejection and a
    silently lost row.

    `_resetForTesting()` loops `AUDITED_EVENTS` calling `crmBus.removeAllListeners(event)`. The
    stage-history caveat gets twelve times worse here — this detaches the webhook and
