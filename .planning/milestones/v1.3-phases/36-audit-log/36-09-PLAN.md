export interface RunChangedRecord {
  entityType: EntityType
  entityId: string
  /** Best-known title at read time; null when the row is gone or has no title column value. */
  title: string | null
  /** The most significant action this run took on this record: deleted &gt; created &gt; updated. */
  action: "created" | "updated" | "deleted"
  /** Distinct fields this run changed on this record, unioned across every row for it. */
  fieldCount: number
  /** The latest audit instant for this record within this run. */
  occurredAt: Date
  /** Currently soft-deleted → not linkable. */
  deleted: boolean
}

export async function readRunChangedRecords(runId: string): Promise&lt;RunChangedRecord[]&gt;

      `organizations.name`; a live person returns the concatenation used elsewhere for a person's

    Step 1: read every `audit_log` row for the run — `where eq(auditLog.workflowRunId, runId)`,
    ordered by `createdAt`. This is the query the partial index serves.

    Step 2: fold in JavaScript into a `Map` keyed by `` `${entityType}:${entityId}` ``, accumulating
    a `Set` of change-map keys for the field-count union, the max `createdAt`, and the most
    significant action by the precedence `deleted > created > updated`. Do the fold in JS rather than
    in SQL: the union of JSONB object keys across rows is awkward and slow in SQL, the row count per
    run is small and bounded by the run's own step count, and a JS fold is the part that is testable
    against a mocked driver.

    Step 3: resolve titles with ONE batched read per entity type present — four queries at most, and
    typically one. Each read selects the id, the title-bearing column and `deletedAt`, and does NOT
    filter on `deletedAt` — a soft-deleted record must still be reported, just not linked. Do not
    issue one query per record.

    Step 4: map to `RunChangedRecord[]` sorted by `occurredAt` descending.

    Do NOT wrap the body in a try/catch. The consumer (36-16) catches and renders a degraded panel;
    a swallow here would return `[]`, which renders "This run didn't change any records" — a lie the
    user cannot distinguish from the truth. The empty array must mean empty.

    There is no cap and no pagination: the list length is the number of records touched, which is the
    number the operator is asking about.

    Run green. Commit: `feat(36-09): add workflow-run linked-records reader`.
