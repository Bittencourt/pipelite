<objective>
Ship the filter toggle: audit entries OFF by default, on when the operator asks, with the count, the
list, the cursor and the empty state all computed from the same flag by the same render.

Purpose: research measured that 15 of the top 21 merged entries would be audit rows. Audit does not
merely add to the feed — it takes it over, burying the human-written notes Phase 35 exists to
surface. The toggle is what keeps the default view readable.

**Contract-conflict resolution, recorded here so it is not re-litigated:** 36-PATTERNS § Flagged item
6 reports a disagreement between 36-CONTEXT (which requires the toggle) and 36-UI-SPEC § Density
(which excluded filtering). That flag is stale. The UI-SPEC was revised after the research and now
contains Surface 4 in full, and its § Density section explicitly retracts the earlier claim: "This
section previously argued that no filter was needed. That was written before the phase research
measured the feed, and it was wrong." There is no live conflict. The toggle ships.

Output: one new client component, the third empty-state variant, the flag threaded through the
server render, the client list and the load-more action, and `searchParams` on four detail pages.
</objective>

    `TimelineList` gains `includeAudit`, `auditTotal` and passes the flag with every
    `loadMoreTimeline` call, so page 2 is drawn from the same source set as page 1.

    **The cursor trap is correctness, not polish.** The keyset predicate is applied per branch, so a
    cursor minted with audit OFF and replayed with audit ON returns audit entries older than the
    cursor and SILENTLY OMITS every audit entry newer than it — the ones inside the window the user
    has already scrolled past. `sources.ts` states the standard for this class of bug in its own
    words: "On an audit surface, omitting history is the worst failure available."

    Already-loaded pages MUST be discarded and the list restarted at page 1 on toggle; merging is not
    an option. The URL design gives this for free: toggling is a `router.replace`, the RSC page
    re-renders, and `TimelineList` receives a fresh `initialEntries`/`initialCursor` for the new
    scope. But `timeline-list.tsx` deliberately does NOT re-seed its state from later props — that
    decision exists so a `revalidatePath` after a note mutation cannot drop appended pages. So the
    component must re-seed **specifically when the scope changes**: key the seeded state on
    `includeAudit`, or lift the reset into a `key` on the component from `record-timeline.tsx`. A
    `key={includeAudit ? "audit" : "default"}` on `<TimelineList>` is the smallest correct change and
    it remounts the subtree, which is exactly the semantics wanted. Whichever you choose, DO NOT
    turn the general no-re-seed rule off — a note mutation must still not drop appended pages.

    Empty-state selection: render `EmptyTimeline variant="hiddenHistory"` with `hiddenCount={auditTotal}` when the entry list is empty AND `!includeAudit` AND `auditTotal > 0`. Otherwise
