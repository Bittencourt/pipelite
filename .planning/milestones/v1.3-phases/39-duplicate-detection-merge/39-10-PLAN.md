<key_facts>
- CI runs `npm ci`, typecheck, lint and `npm test` on GitHub hardware with NO Docker and NO database
  (`.github/workflows/ci.yml`). `npm test` is
  `vitest run && vitest run --config vitest.rsc.config.ts`. A required check that never passes is
  worse than no check: Phase 32 recorded that GitHub treats a required check which never reports as
  permanently pending, making every pull request unmergeable. The CI-exclusion story is not optional
  paperwork; it is why this plan can exist at all.
- The exclusion mechanism already has a precedent in this repo, with its own explanatory comment.
  `vitest.config.ts` excludes `**/*.rsc.test.?(c|m)[jt]s?(x)` because the base `include` glob matches
  those files and they belong to a second project. `*.db.test.ts` is the same shape: the base
  `include` (`src/**/*.{test,spec}.?(c|m)[jt]s?(x)`) matches it, so it must be excluded explicitly.
  Mirror the existing comment's voice.
- The de-risked alternative has a strong analog and ships anyway. `scripts/trash-checks.sql` (667
  lines) exists for exactly this reason one phase earlier, and its header states the argument
  verbatim: a mocked `db.delete` cannot raise SQLSTATE 23503. Task 3 adds the SQL merge probe whether
  or not the vitest path proves cheap, so B4 has a proof either way.
- Fixture rules, inherited from 45-08 (V-4): create the records the test needs and hard-delete them
  and their children afterwards; never borrow and mutate a real user's record; verify zero rows are
  left. Give every fixture a recognizable name prefix so the leftover check is a single query.
- Environment guard, inherited from 45-02: parse the host out of the connection URL and refuse
  anything that is not `localhost` or `127.0.0.1`, with the refusal proven by a RUN negative proof.
  `E2E_DATABASE_URL` in `.env` already points at `localhost:5433` and already carries that posture.
- B4's numbers: 29,037 of 46,054 organizations carry a `source='migration'` note.
  `notes_migration_uniq` is `uniqueIndex ON (entity_type, entity_id) WHERE source='migration'` and is
  a permanent invariant that may not be dropped. The merge's resolution is to demote the loser's note
  to `source='user'` when the survivor already has one.
- The exhaustive child inventory is three foreign keys (`deals.organization_id`,
  `people.organization_id`, `deals.person_id`) plus polymorphic `notes`. Activities are absent by
  design - they attach via `activities.deal_id` and follow their deal. `audit_log` rows are
  deliberately NOT reassigned - the loser keeps its history. Both facts must be ASSERTED here, so a
  future reader sees them as decisions rather than omissions.
- The database this runs against holds 46,054 organizations and 38,348 people of real data. Fixtures
  must be additive and self-cleaning; nothing in this file may update or delete a row it did not
  create.
</key_facts>
