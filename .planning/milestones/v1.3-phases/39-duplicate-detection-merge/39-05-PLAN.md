<key_facts>
- **A1 is RESOLVED and 39-RESEARCH's proposed call signature is WRONG.** In the installed
  `drizzle-orm@0.45.1` the Postgres builder is `generatedAlwaysAs(as)` — **one argument, no options
  object** (`node_modules/drizzle-orm/pg-core/columns/common.d.ts:49`). The `{ mode: "stored" }` form
  exists only on MySQL. Postgres has no VIRTUAL generated columns, so drizzle omits the parameter.
  Writing the two-argument form will not typecheck.
- GIN plus an opclass IS supported: `IndexBuilderOn.using('gin', ...)` (`pg-core/indexes.d.ts:55`)
  and `ExtraConfigColumn.op(opClass)` (`pg-core/columns/common.d.ts:103`), with `PgIndexOpClass`
  widened by `(string & {})` so `'gin_trgm_ops'` is accepted.
- **What is still unverified is `drizzle-kit generate`'s emitted DDL** for a generated column with a
  custom function reference. That is task 2, and it is a real task with a documented fallback — do
  not assume it.
- Measured on the live database: `ALTER TABLE organizations ADD COLUMN norm_name ... STORED` takes
  **2.39 s** (ACCESS EXCLUSIVE, table rewrite, 46,054 rows / 13 MB); the GIN index builds in 0.48 s
  at 3832 kB; the btree in 0.13 s. Total about 3 seconds for organizations. Acceptable for a
  boot-time migration.
- The STORED column beats an expression index by **32x fewer heap blocks** on the bitmap recheck
  (6,472 vs 207,765 on a 500-row self-join), because an expression index re-evaluates the function on
  every recheck row. That is the whole reason for the column.
- Both indexes are partial, `WHERE deleted_at IS NULL`. The btree serves the exact-match (certain)
  tier and the create-time check; the GIN serves the fuzzy (likely) tier.
- **Phase 33 D-06:** indexes are declared in the Drizzle schema and generated, never hand-written
  into migration SQL. A hand-written index was silently dropped by a later `generate` in this repo
  (0009 to 0010). Everything in THIS plan goes through `generate`.
- `notes_migration_uniq` (`src/db/schema/notes.ts:42-44`) is a permanent database invariant and must
  still exist after this migration. Assert it.
- Star pairing vs clique pairing, measured: 24,551 pairs instead of 1,030,436 for the same
  exact-name groups. The pair-count sanity assertion is Pitfall 3's detector: **the pair count must
  never exceed the row count of the entity scanned.**
