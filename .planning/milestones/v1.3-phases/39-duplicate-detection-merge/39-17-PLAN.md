<key_facts>
- **The Docker image has NO volume mount.** Source changes are invisible to Playwright until
  `docker compose up -d --build app`. Every UI edit in this phase landed in waves 5 and 6 precisely so
  this plan pays the rebuild once for all of them.
- **Budget realistically: 2 to 4 rebuilds.** Phase 45 budgeted one and needed four, because each
  rebuild exposed a defect only the previous fix made visible. That was not a planning failure and it
  is not one here. **Never weaken an assertion or edit a spec to make a rebuild unnecessary** — 45-11
  recorded that as the rule, and it held: four rebuilds, zero weakened assertions.
- **V-3, anti-vacuity, non-negotiable:** a blank page, an error page and a redirect all satisfy
  `scrollWidth <= clientWidth`. Every route asserts a visible `h1` **by role** before measuring, and
  the anchor text is READ FROM THE CATALOG rather than hardcoded, so a copy change does not silently
  turn the gate off.
- **The 305 rather than 320** comes from `launchOptions: { ignoreDefaultArgs: ["--hide-scrollbars"] }`
  in `playwright.config.ts`. Without it headless Chromium reports `clientWidth` 320 and the whole file
  green-lights layouts that still scroll sideways on a real phone.
- **The viewport is neither declared nor changed inside a spec.** Resizing mid-run is deliberately
  absent: `@dnd-kit/core` wires the window `Resize` event to its drag-cancel handler, so a programmatic
  resize is a hazard that must not become a habit anywhere under `e2e/`.
- **No login happens in a spec.** The session arrives from the setup project's `storageState`
  (`e2e/.auth/admin.json`, gitignored). Never inline a password. The e2e admin is
  `pipelite-e2e@local.test` — NOT `@local`, because the login form validates with
  `z.string().email()` whose zod-4 regex demands a dotted domain.
- **V-4, fixtures:** follow `e2e/deals-drag.spec.ts` — create the records the spec needs, hard-delete
  them and their children afterwards, verify zero rows left. Never borrow and mutate a real user's
  record. The database holds 46,054 real organizations.
- **V-5:** Playwright stays out of CI. `.github/workflows/ci.yml` must end this plan byte-identical
  and must contain zero occurrences of `playwright`.
- **Imports in `e2e/` use relative paths, not `@/...`** — Playwright does not read vitest's alias
  table.
- **`/duplicates` renders its empty state with no fixture data**, so extending the viewport matrix
  costs no seeding (R-1). `/duplicates/[pairId]` cannot be measured without a pair, which is why it
  gets its own spec with its own fixtures (R-2).
- Browser binaries are a machine-local step: `./node_modules/.bin/playwright install chromium`
  (about 300 MB into `~/.cache/ms-playwright`). That is the property that keeps CI from downloading
  browsers it never uses.
- The `computer`-tool keyboard action delivers ZERO key events to the page in this environment
  (calibrated in Phase 38: a document capture listener saw 0 events for Escape, and Space and Enter on
  a plain focused button produced 0 clicks). Click, JS evaluation, navigation and geometry all work.
  **Never report a keyboard check as FAILED on that instrument's evidence.**
</key_facts>
