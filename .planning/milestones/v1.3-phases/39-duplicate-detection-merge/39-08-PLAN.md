<key_facts>
- **The measured discriminators** in the live organization `custom_fields`: `CNPJ / CPF` populated on
  5,312 rows (11.5%, the strongest — a legally unique Brazilian company registration number, and 15
  organizations already share one), `E-mail de Contato 1` on 25,533 (55.4%), `Telefone de Contato 1`
  on 24,265 (52.7%). These are deployment-specific human labels created by the Pipedrive import, and
  `customFields` is keyed by that label, not by definition id. Hardcoding them would make the feature
  work here and nowhere else.
- **The certain rule** (39-CONTEXT Post-Research, plus 39-01's `classifyOrganizationMatch`):
  identical normalized name AND identical non-empty value of the first configured identity field that
  is non-empty on both records. For people it is unchanged and simpler: an exact, syntactically valid
  email (`people.email` is a real column).
- **The B2 numbers that justify the email predicate:** unfiltered exact-email grouping over people
  yields 28,032 pairs, largest group 212 (email literally `#`). Requiring a valid address yields
  5,338 pairs, largest group 23. A 5.25x precision improvement, and the difference between the
  feature working and being switched off by its first user.
- **Create-time cost, measured:** a single-record trigram lookup on the worst-case high-frequency
  prefix is 60 ms with the index correctly chosen; the certain tier is a btree equality lookup,
  sub-millisecond. UI-SPEC W-9 folds it into the submit — there is no separate "checking" step.
- **`app_settings` doctrine** (`src/lib/trash/settings.ts`, itself a documented copy of
  `src/lib/audit/settings.ts`): an exported `*_KEY` constant, a private zod schema, a fail-closed
  `read*` that returns `null` and logs identifiers and bounds only, a `Write*Result` discriminated
  type, and a `write*` that validates BEFORE touching the database.
- **One deliberate divergence from that doctrine:** audit and trash both seed a default row by
  migration. Phase 39 must NOT seed the identity key — there is no deployment-neutral custom-field
  name to seed — so this is the first `app_settings` key intentionally absent on a fresh install.
  State that in the module comment or a reader will hunt for the missing seed migration.
- **The threshold is asymmetric to the identity key and that asymmetry is the point.** An unset
  identity key means "no certain tier" (fail closed, because the alternative is a million pairs). An
  unset similarity threshold falls back to `DEFAULT_SIMILARITY_THRESHOLD = 0.85` (a safe default,
  measured: 44,522 / 27,156 / 1,474 row-pairs at 0.75 / 0.85 / 0.92, and the 0.85-0.92 band sampled
  as high precision). Making it a setting is what lets the one manual verification in
  39-VALIDATION — "read 20 pairs and judge whether they are duplicates" — be answered without a
  code change.
- **Visibility, decided:** `/organizations` and `/people` are NOT owner-scoped — both list pages
  select every non-deleted row for any authenticated user (source-read this session). So the
  create-time warning reveals nothing the user could not already see, and its only visibility
  predicate is `deleted_at IS NULL`. This must be stated as a comment at the query, bound to the
  list pages, so a future owner-scoping change is applied to both or to neither.
</key_facts>
