<objective>
Implement the merge screen's two decisions as pure functions, before any component exists: how the
compared fields partition into three groups, and which side wins by default in each group.

Purpose: DEDUP-02 and SC-3. 39-VALIDATION V-4 names the default-selection rule "the phase's
highest-consequence silent default" — a wrong default silently writes the wrong value onto a live
record and the audit entry records it as intentional. It belongs in a unit-tested `src/lib/`
function, not in JSX, because this repo has no jsdom.
Output: `buildMergeFieldGroups` and `resolveMergeDefaults`, plus the one export `present.ts` owes
the merge picker.
</objective>

<key_facts>
- **Locked (39-CONTEXT § Merge Semantics):** "The field picker pre-selects the survivor's value,
  except where the survivor's is empty and the loser's is not."
- **UI-SPEC M-3** fixes three groups and their order: (2) conflicts — both populated and different,
  default survivor, never collapsed; (3) filled only on the other record — survivor empty, loser
  populated, default **loser**, never collapsed; (4) identical — equal, or both empty, no control,
  collapsed behind a disclosure.
- **UI-SPEC M-4:** every label resolves through `AUDIT_FIELD_LABELS` / `describeField` in
  `src/lib/audit/present.ts`. No new map, no new `audit.field.*` key. `describeField` is currently

  from `AUDIT_FIELD_LABELS`' insertion order and adding a key there reorders every record timeline
  in the app (recorded by 45-06). Exporting a function changes neither.
- `AuditValue` (`src/lib/timeline/types.ts:107`) already models `{ type: 'empty' }` as a first-class
  case, which is what M-5's "an empty side renders `audit.value.empty`, never a blank" needs.
- **Pre-existing data anomaly, dedupe don't fix:** `custom_field_definitions` holds TWO rows named
  `Segmento Organização` for `entity_type='organization'`. `customFields` is keyed by NAME, so both
  definitions address one blob key. `describeField`'s `customDefinitionId` already resolves by name
  and returns the first match. The field list must dedupe by name at build time.

  <files>src/lib/dedup/field-groups.ts, src/lib/dedup/field-groups.test.ts</files>
  <read_first>

    - `src/lib/timeline/types.ts` lines 100–135 — `AuditValue` and `AuditFieldChange`.

  <behavior>
    `buildMergeFieldGroups(input): MergeFieldGroups` where `input` is
    `{ entityType, survivor: Record<string, unknown>, loser: Record<string, unknown>, resolution }`
    and the returned shape is `{ conflicts: MergeField[]; filledOnly: MergeField[]; identical: MergeField[] }`,
    each `MergeField` being `{ key, label, survivorValue, loserValue }`:
    - Test 1: `name` differs and both are non-empty → lands in `conflicts`.
    - Test 2: `website` is `null` on the survivor and a URL on the loser → lands in `filledOnly`.
    - Test 3: `website` is a URL on the survivor and `null` on the loser → lands in **`identical`**,
      NOT in `conflicts` — the survivor already has the value and there is nothing to choose.
    - Test 4: both sides `null` → `identical` (the M-3 "both empty counts as identical" rule).
    - Test 5: both sides the same non-empty string → `identical`.
    - Test 6: `""`, `"   "`, `null` and `undefined` are all treated as empty and are equal to each
      other, so a `""`-vs-`null` pair is `identical` and never a conflict.
    - Test 7: a custom field key (`customFields.CNPJ / CPF`) differing on the two sides lands in
      `conflicts` with `label` resolved through `describeField`, not through a literal.
    - Test 8: two custom field definitions sharing the name `Segmento Organização` produce exactly
      ONE `MergeField` — deduped by key.
    - Test 9: ordering — within each group, native columns precede custom fields and native columns
      follow `describeField`'s rank, so `name` precedes `website`. Assert the full key order of a
      mixed input, not just membership.
    - Test 10: `id`, `createdAt`, `updatedAt`, `deletedAt`, `ownerId` and `customFields` never appear
      in any group. Assert the exclusion list explicitly and assert at least one included field in
      the same test, so the assertion cannot pass vacuously on an empty result.
  </behavior>
  <action>
    Create `src/lib/dedup/field-groups.ts`. Export a frozen `MERGE_EXCLUDED_COLUMNS` set holding
    `id`, `createdAt`, `updatedAt`, `deletedAt`, `customFields` and `ownerId`, each with a one-line
    reason (`ownerId` is excluded because Phase 38 established narrow `update{Entity}OwnerMutation`
    functions as the only sanctioned owner write path, and a merge is not one).

    `buildMergeFieldGroups` builds the compared key set as the union of the two records' native
    columns minus `MERGE_EXCLUDED_COLUMNS`, plus `customFields.<name>` for every key present in
    either record's `customFields` blob, deduped by the composed key string. Comment the dedupe with
    the `Segmento Organização` row as its reason.

    Emptiness is one exported predicate, `isEmptyMergeValue(value: unknown): boolean` — true for
    `null`, `undefined`, `""` and whitespace-only strings, and for an empty array. It is used by
    both this module and `merge-defaults.ts`, so the two cannot disagree about what "empty" means.

    Partition with exactly these rules, in order: both empty OR equal → `identical`; survivor empty
    and loser populated → `filledOnly`; survivor populated and loser empty → `identical` (with the
    comment stating why: the survivor keeps what it has and there is no decision to surface);
    otherwise → `conflicts`.

    Sort each group with the `describeField` descriptor's `(group, rank, label, key)` ordering — the
    same `compareChanges` shape `present.ts` uses. Do not re-implement label resolution.
  </action>

  </read_first>
  <behavior>
    `resolveMergeDefaults(groups: MergeFieldGroups): Record<string, "survivor" | "loser">`
    - Test 1: every field in `conflicts` defaults to `"survivor"`.
    - Test 2: every field in `filledOnly` defaults to `"loser"`. This is the locked exception and the
      only place a value is adopted from the record being destroyed.
    - Test 3: fields in `identical` appear in the map with `"survivor"` and carry no user control —
      assert the key IS present, so a later writer cannot drop an identical field from the merged
      blob by accident.
    - Test 4: the returned map's key set equals the union of the three groups' keys, exactly.
    `applyMergeChoices(survivor, loser, groups, choices)` returning
    `{ native: Record<string, unknown>; customFields: Record<string, unknown> }`
    - Test 5: a `conflicts` field whose choice is flipped to `"loser"` produces the loser's value in
      `native`.
    - Test 6: a `customFields.` key routes into `customFields`, never into `native`, and the blob
      key is the bare definition name with the prefix stripped.
    - Test 7: a choice key that is not in any group is IGNORED and does not appear in the output.
      This is the V5 control: the choice map arrives from the browser.
    - Test 8: a choice value that is neither `"survivor"` nor `"loser"` falls back to the default
      from `resolveMergeDefaults`, and never throws.
    - Test 9: the survivor's `customFields` keys that were never compared (because the loser had no
      such key and the survivor's value is non-empty) survive into the output blob unchanged — a
      merge must not silently clear a custom field nobody chose about.
    - Test 10: no key from `MERGE_EXCLUDED_COLUMNS` ever appears in `native`, asserted alongside at
      least one key that does, so the assertion cannot pass on an empty object.
  </behavior>
  <action>
    Create `src/lib/dedup/merge-defaults.ts`. `resolveMergeDefaults` is a direct transcription of the
    locked sentence: survivor wins, except `filledOnly`. Put the locked sentence in the doc comment,
    quoted, with its source named, so a future reader can see the rule was copied and not invented.

    `applyMergeChoices` is the write-side companion. It starts from the survivor's own values,
    applies only the keys present in the three groups, resolves each key by `choices[key] ?? default`,
    narrows an unrecognised choice value back to the default, and splits the result into native
    columns and a `customFields` blob by the `customFields.` prefix. It never mutates its inputs and
    it never emits a key outside the compared set — state both as invariants in the comment, because
    they are what stops a crafted choice map writing an arbitrary column (T-39-04).
  </action>
