<objective>
Prove server-side QuickJS actually works inside the Docker standalone build, and bound it, BEFORE any recalculation code is written that depends on it.

Purpose: RESEARCH.md assumption A1 is the single highest-severity unknown in this phase (confidence MEDIUM/LOW). `.next/server/**` and `.next/standalone/**` contain zero `.wasm` files and `quickjs-emscripten` is absent from `serverExternalPackages`. Output: `quickjs-emscripten` declared external, an additive opt-in resource-limit parameter on `evaluateFormula`, and an operator-signed go/no-go on Docker WASM viability.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin-authored formula expression → server QuickJS process | An arbitrary JS-like expression, unvalidated today (`validateFormula` is dead code per RESEARCH Pitfall 9), moves from executing in the user's browser tab to executing in the shared Node server process |
| npm package → runner container filesystem | The `.wasm` binary is loaded from disk at runtime by `readFileSync`, outside Next.js module tracing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01 | Elevation of Privilege | `evaluateFormula` QuickJS context | mitigate | Keep the WASM isolate free of host bindings — inject only `FORMULA_FUNCTIONS` (a closed pure-JS library) and `JSON.stringify`-serialised data. Task 2 explicitly forbids adding `vm.newFunction` host callbacks |
| T-34-02 | Denial of Service | `evaluateFormula` on the server | mitigate | Task 2 adds opt-in `runtime.setMemoryLimit` and `runtime.setInterruptHandler`; plan 34-03 supplies 8 MB / 500 ms on every server-side call, matching `transform.ts` |
| T-34-08 | Denial of Service | Docker image missing the `.wasm` asset | mitigate | Task 1 declares the package external; Task 3 proves resolution in-container before any write path depends on it, converting a production 500-on-every-save into a build-time finding |
| T-34-SC | Tampering | npm installs | accept | This phase installs zero new packages (RESEARCH § Package Legitimacy Audit). `package.json` and `package-lock.json` are not in `files_modified`; any change to them in this plan is a defect |
</threat_model>
