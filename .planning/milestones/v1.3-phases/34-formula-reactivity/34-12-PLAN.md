<objective>
Make workflow conditions able to reference the 90% of custom fields whose names contain spaces or punctuation.

Purpose: Phase 34's SC-3 says "a workflow condition evaluated against a formula field branches on the current value". Plan 34-05 made the formula *value* normalise correctly into the trigger envelope, but the condition still cannot *name* most fields: `resolveFieldPath` splits the path on `.`, so `customFields.Código Mãe` cannot be expressed. Measured against the live database, **152 of 169 custom field definitions (90%)** have names with spaces or punctuation — `Código Mãe`, `Previsão de início operação`, `CNPJ / CPF`, `UUID UC (TYR Core)`, `Tem solução de solar?`. Without this, SC-3 passes mechanically while remaining unusable on the real dataset.

Output: `resolveFieldPath` additionally accepts bracket-quoted segments, with every existing dot path unchanged.
</objective>

**Current implementation** is a 14-line function at `condition-evaluator.ts:16` that does `path.split(".")` and walks the context object.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workflow definition → `resolveFieldPath` | A `fieldPath` is admin-authored configuration, evaluated against a run's execution context |
| execution context → condition outcome | The resolved value decides workflow branching, which can trigger emails, webhooks and CRM writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-34-20 | Denial of Service | path parser | mitigate | A regex with nested quantifiers over an attacker-influenced path is a ReDoS vector. The plan mandates a single forward scan and an acceptance criterion asserts no nested-quantifier regex is introduced. |
| T-34-21 | Tampering | prototype pollution | mitigate | Bracket notation lets a path name any string key, including `__proto__`, `constructor` and `prototype` — a dot path could too, but bracket quoting makes it easier to express deliberately. The walk must not traverse into prototype chains; reject or return `undefined` for these keys rather than resolving them. Add a test. |
| T-34-22 | Information Disclosure | context traversal | accept | `resolveFieldPath` can already read any key on the execution context; this plan changes only how a key is *spelled*, not what the context contains. No new data is reachable. |
| T-34-23 | Elevation of Privilege | condition outcome | accept | Making previously-unreachable fields reachable means conditions that silently evaluated `undefined` (and so took the false branch) may now take the true branch. That is the intended fix, but it is a **behaviour change for any existing workflow that references such a field** — the SUMMARY must record it so an operator is not surprised by a dormant workflow starting to fire. Live risk is minimal: 0 of 169 definitions are type `formula` today. |
| T-34-SC | Tampering | dependencies | accept | Zero packages installed; no dependency change. |
