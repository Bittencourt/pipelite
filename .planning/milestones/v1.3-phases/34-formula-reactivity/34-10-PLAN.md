<objective>
Close the last two uncovered write paths — the CSV importer and the Pipedrive API importer — with a shared, bounded batch recalculation helper.

Purpose: RESEARCH's consolidated D-02 answer names three paths that "mutations plus v1 routes" misses: the UI path (plan 34-08) and these two importers. Both call a local `batchInsert` and both write `customFields` directly (`import/actions.ts:137,226,408,526` from `extractCustomFields` over `custom_*` columns; `pipedrive-api-import-actions.ts:616,693,822,912`). They are also the highest-volume paths in the system and the ones RESEARCH flags as "most likely to trip the D-04 budget" — 100-row batches at 3 formulas each is 300 evaluations ≈ 360 ms per batch, and an import can contain many batches.

Rather than sprinkling recalc calls through two large files (`import/actions.ts` has four entity flows; `pipedrive-api-import-actions.ts` is over 900 lines), this plan introduces one small shared helper with its own focused test file, and the importers each gain a single call per entity flow.

Output: imported rows carry correct formula values, bounded by one evaluation budget per import operation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| uploaded CSV file → `custom_*` columns → stored JSONB | A user-supplied file's column names map directly to custom field names, one of which could be a formula field |
| Pipedrive API response → field mapping → stored JSONB | Data from a third-party service is written into the same JSONB column |
| one import operation → thousands of row writes → thousands of potential evaluations | The highest-volume write surface in the system |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-03 | Denial of Service | import amplification | mitigate | One `FORMULA_EVALUATION_BUDGET` shared across the entire import run and decremented per row, plus `cascade: false`. Without it a 5,000-row import at 3 formulas each would be 15,000 evaluations ≈ 18 s of pure sandbox time; with it, work stops at the budget and the user is warned. Asserted by Tests 4 and 5 |
| T-34-04 | Tampering | `custom_Margin` column in an uploaded CSV | mitigate | `stripFormulaKeys` is applied to the output of `extractCustomFields` and to the Pipedrive field mapping, so neither an uploaded file nor a third-party API response can seed a server-derived formula value |
| T-34-07 | Tampering | Pipedrive-sourced values | mitigate | Same control. Additionally, Pipedrive values enter the sandbox only as `JSON.stringify`-serialised data with no host bindings (T-34-01) |
| T-34-24 | Denial of Service | one bad row aborting an import | mitigate | The helper catches per row, logs, and continues. A single broken formula cannot abort a 5,000-row import (D-05 applied at import scale) |
| T-34-25 | Repudiation | silent partial recalculation | mitigate | Budget exhaustion surfaces both as a `console.warn` and in the import's user-visible `warnings` array, so a partially recalculated import is visible to the operator rather than silent |
| T-34-26 | Denial of Service | workflow fan-out on import | accept | The importers deliberately emit no `crmBus` events, so an import does not trigger a workflow run per row. Pre-existing behaviour, preserved and now documented |
| T-34-SC | Tampering | npm installs | accept | Zero new packages |
</threat_model>
